---
title: Entity Credit Balances
api: "GET https://api.nozle.app/engine/api/v1/customers/{customer_id}/entities/{entity_id}/credit-systems"
description: Read Entity, shared, and effective exact-decimal balances
---

Base URL: `https://api.nozle.app/engine/api/v1`.

**Auth:** secret key only. The key requires `entity:read`. Publishable keys are rejected.

List all relevant Credit Systems:

```http
GET /customers/workspace_123/entities/user_42/credit-systems
Authorization: Bearer sk_nozle_...
```

Read one system:

```http
GET /customers/workspace_123/entities/user_42/credit-systems/ai_credits/balance
Authorization: Bearer sk_nozle_...
```

The list endpoint returns `{ "customer_id", "entity_id", "entity_status", "as_of", "balances": [...] }`, with one object of this shape per item. Source fields have the same meaning as in [Customer Credit Balances](/api/customer-credit-balances). `pool_policy` is `null` when no policy applies.

An unknown customer returns `404 customer_not_found`, an unknown Entity returns `404 entity_not_found`, and an unknown Credit System code returns `404 credit_system_not_found`. A retryable read failure returns `503 credit_read_temporarily_unavailable` with `Retry-After`.

All amounts are strings. `entity_available` and `shared_available` expose separate source pools. `effective_available` applies the current plan policy and becomes zero when the Entity is inactive or no unambiguous policy exists.

From Engine 2.34.0, open [credit holds](/api/create-usage-hold) are left out of every `*_available` amount and reported separately:

| Field | Description |
|-------|-------------|
| `entity_held` | Credits reserved on the Entity's own sources, already subtracted from `entity_available`. |
| `shared_held` | Credits reserved on the shared customer pool, already subtracted from `shared_available`. These holds can belong to other Entities or to customer-level usage. |
| `held` | Held part of the pool the Entity spends from under its pool policy: `entity_held` for `entity_only`, `entity_held` + `shared_held` for `entity_then_customer`, `shared_held` for `customer_only`. `"0"` when the Entity is inactive or no policy applies. |

Each source also has `held`, the part of its `remaining` that open holds reserve.

The source list contains active or scheduled, non-exhausted sources. Expired and exhausted sources remain in immutable history but are not returned by this balance endpoint.
