---
title: "Create Checkout Session"
api: "POST https://api.nozle.app/engine/api/v1/checkout"
---

Base URL: `https://api.nozle.app/engine/api/v1`.

Create a payment-gated plan checkout from a trusted merchant backend.

**Auth:** secret key only. Publishable keys are always rejected.

<Info>
The merchant backend derives `customer_id` from its authenticated user or team. Do not trust a browser-provided customer ID. The response can contain Stripe or Razorpay checkout, a hosted payment URL, a processing state, or a completed/scheduled transition.
</Info>

## Modes

### Plan checkout

Use this when a customer is selecting a plan.

<ParamField body="customer_id" type="string" required>
  External customer ID. The customer must already exist.
</ParamField>

<ParamField body="plan_code" type="string" required>
  The plan code to subscribe the customer to (e.g. `pro`).
</ParamField>

Plan checkout is payment-gated. Free-to-paid checkout uses an incomplete subscription. Paid-to-paid upgrades keep the old subscription active in a durable pending intent and apply the billing change only after the payment provider confirms the required payment and Nozle fulfills the change.

If prepaid credits fully cover a paid plan change, Nozle applies it without an external payment and returns `type: "completed"`. Free plans may also complete immediately. A downgrade or other cycle-end transition may return `type: "scheduled"`. The selected self-service downgrade flow uses a signed quote with the end-of-period transition endpoint described below.

## Selected subscription and signed quote

<ParamField body="subscription_id" type="string">
  External subscription ID. Select it explicitly for self-service. An unselected checkout for a customer with multiple active subscriptions is rejected as ambiguous.
</ParamField>

<ParamField body="quote_id" type="string">
  Opaque signed quote from `POST /subscriptions/preview`. Requires `subscription_id`; forward it unchanged after the customer confirms the amounts and dates.
</ParamField>

Use an `Idempotency-Key` header for the confirmed action and retain it across uncertain retries. Invalidated or expired new quotes require a fresh preview/confirmation; replay of an already accepted action reuses its recorded checkout. See [Subscription self-service](/api/subscription-management) for quote, downgrade and recovery contracts.

## Return URL

<ParamField body="return_url" type="string">
  URL Stripe should return to after embedded checkout completes. It must use an exactly allowlisted HTTPS origin. If omitted, Nozle uses the configured dashboard return URL.
</ParamField>

<ParamField body="success_url" type="string">
  Backward-compatible alias for `return_url`.
</ParamField>

## Request examples

Plan checkout:

```json
{
  "customer_id": "customer_123",
  "plan_code": "growth",
  "return_url": "https://app.example.com/settings/billing"
}
```

## Response

<ResponseField name="type" type="string" required>
  `stripe`, `razorpay`, `hosted`, `processing`, `completed`, or `scheduled`.
</ResponseField>

<ResponseField name="client_secret" type="string">
  Client secret for the returned embedded Stripe payment flow. Use the matching SDK checkout UI; prefer the hosted `url` when supplied.
</ResponseField>

<ResponseField name="url" type="string">
  Hosted checkout URL. Navigate the current page to this URL.
</ResponseField>

<ResponseField name="clientSecret" type="string">
  Camel-case alias for `client_secret`.
</ResponseField>

<ResponseField name="invoice_id" type="string">
  Nozle invoice ID being paid.
</ResponseField>

<ResponseField name="amount_cents" type="integer">
  Amount due for the checkout session, in the invoice currency's smallest unit.
</ResponseField>

<ResponseField name="currency" type="string">
  Invoice currency.
</ResponseField>

### Razorpay and recovery fields

A `razorpay` result supplies `checkout_id`, `order_id`, public `key_id`, `amount_cents`, and `currency`, with optional expiry/customer/recurring metadata. Verify the genuine Razorpay callback on your backend. Activation requires captured payment and completed fulfillment.

A `processing` result supplies a `checkout_id` to recover rather than starting another checkout. A `hosted` result supplies `payment_url`. Both scoped verification and status recovery are described in [Subscription self-service](/api/subscription-management#payment-status-and-recovery).

### Credit-funded response

When no external payment remains due:

```json
{
  "type": "completed",
  "status": "succeeded",
  "payment_source": "credits",
  "subscription_id": "subscription_uuid",
  "plan_code": "pro",
  "invoice_id": "invoice_uuid",
  "amount_cents": 0,
  "currency": "USD"
}
```

### Scheduled response

```json
{
  "type": "scheduled",
  "status": "pending",
  "subscription_id": "subscription_uuid",
  "plan_code": "starter"
}
```

## Webhook requirement

Stripe must be able to reach your Nozle public API URL. When a Stripe provider is connected, Nozle registers the Stripe webhook endpoint for that tenant's Stripe account:

```text
https://api.nozle.app/core/webhooks/stripe/{organization_id}?code={stripe_provider_code}
```

Checkout relies on these Stripe events:

- `payment_intent.succeeded`
- `payment_intent.payment_failed`
- `payment_intent.canceled`
