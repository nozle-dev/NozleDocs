---
title: "Check Entitlement"
api: "GET https://api.nozle.app/engine/api/v1/can"
---

Base URL: `https://api.nozle.app/engine/api/v1`.

Check whether a customer is entitled to use a feature under their current plan. This is the primary gating endpoint -- call it before executing any metered or limited operation.

**Auth:** secret key only. The key requires `customer_usage:read`. Publishable keys are always rejected.

A subscription on an override plan (a plan made from a catalog plan for one customer, for example a negotiated price or a subscription created from a quote) gets the entitlements and usage limits of the catalog plan it was made from. Its usage is still priced with the override plan's own charges.

<ParamField query="customer_id" type="string" required>
  External customer ID derived by the trusted merchant backend.
</ParamField>

<ParamField query="feature" type="string" required>
  Feature key to check (matches a feature code)
</ParamField>

<ParamField query="subscription_id" type="string">
  External ID of one current subscription of the customer. `/can` evaluates that subscription: its plan, entitlements, limits and usage. An unknown or ended subscription answers `no_subscription`.
</ParamField>

<ParamField query="entity_id" type="string">
  External ID of an Entity. `/can` evaluates the Entity's own subscription, else the customer's own subscription (not owned by an Entity). With `subscription_id` too, the subscription must belong to that Entity.
</ParamField>

Without `subscription_id` or `entity_id`, `/can` evaluates the customer's only current subscription. A customer with several current subscriptions is evaluated on its own subscription (not owned by an Entity) when there is exactly one; otherwise the answer is `allowed: false` with the reason `subscription_required`. Before Engine 2.0.0, the most recently started subscription was used. See [which subscription is checked](/guides/entitlements/can-endpoint#which-subscription-is-checked).

<ParamField query="metadata" type="string">
  URL-encoded JSON object of event properties. The economics estimate uses it to evaluate Cost Sheet conditions and quantities, and, for a sum Feature, reads the call's units from the Feature's `field_name`. A value that is not a JSON object returns `400`.
</ParamField>

<ResponseField name="allowed" type="boolean" required>
  Whether the customer can use this feature
</ResponseField>

<ResponseField name="reason" type="string">
  Present only when access is denied; omitted when `allowed` is `true`. One of `feature_not_found`, `no_subscription`, `subscription_required`, `no_entitlement`, `usage_limit_exceeded`, or `economic_policy_denied`.
</ResponseField>

<ResponseField name="feature_type" type="string">
  Type of the feature. Not returned when the feature or the subscription is missing, or when a metered feature has neither an entitlement nor a charge on the plan.
</ResponseField>

<ResponseField name="configuration" type="object">
  Configuration values granted by the plan for a non-metered feature. Omitted when there are none.
</ResponseField>

<ResponseField name="used" type="integer" required>
  Units consumed in the current billing period (the running total for a recurring Feature), as a whole number (a fractional total is truncated). Also the real usage of a metered Feature that is priced by a charge and has no entitlement. `0` for a denial that is decided before usage is read, and for features that are not metered. The period is the one Nozle invoices the usage in, in the customer's time zone. See [usage and billing periods](/guides/entitlements/can-endpoint#usage-and-billing-periods).
</ResponseField>

<ResponseField name="limit" type="number | null" required>
  Maximum units allowed by the plan. `null` when the plan sets no cap, the feature is not metered, or a metered Feature has no entitlement.
</ResponseField>

<ResponseField name="remaining" type="number | null" required>
  Units still available. `null` when `limit` is `null`.
</ResponseField>

<ResponseField name="overage" type="boolean">
  `true` when usage has reached a soft limit. The request is still allowed. Omitted otherwise.
</ResponseField>

<ResponseField name="economics" type="object">
  Optional point-in-time economics estimate from the published Cost Sheet. Monetary values are exact decimal strings in `currency`, not integer cents.
</ResponseField>

The `economics.status` value is `estimated`, `not_configured`, `unavailable`, or `stale`. `includes` identifies what was calculated and `excludes` explains costs that cannot be known before the operation runs. When a margin policy applies, the separate `policy` object reports its version, thresholds, stale-data fallback, decision, and reason. Estimated revenue is the unit price × the units of this call: 1 for a count Feature, the `field_name` value in `metadata` for a sum Feature. Other aggregations, or a sum call without that value, make the estimate `unavailable`, and the policy's `on_unavailable` decides. See [economics](/guides/entitlements/can-endpoint).

## Denial reasons

| `reason` | Meaning |
|----------|---------|
| `feature_not_found` | No feature with this code exists in the organization. |
| `no_subscription` | The customer has no active subscription (none started, ended, or cancelled), or the customer does not exist. Also an unknown or ended `subscription_id` or `entity_id`. |
| `subscription_required` | The customer has several current subscriptions and not exactly one of them is the customer's own (not Entity-owned). Send `subscription_id` or `entity_id`. |
| `no_entitlement` | The customer's plan does not include the feature. |
| `usage_limit_exceeded` | A hard limit is reached. A soft limit never denies; it sets `overage` to `true`. |
| `economic_policy_denied` | A margin policy in `deny` mode rejected the estimated cost or margin. The `policy` object has the detail. |

A denial is an HTTP `200` response with `allowed: false`.

## Errors

| Status | Body | Meaning |
|--------|------|---------|
| `400` | `{"error": "customer_id and feature required"}` | `customer_id` or `feature` is missing. |
| `400` | `{"error": "metadata must be a JSON object"}` | `metadata` is not a JSON object. |
| `401` | `{"error": "..."}` | The `Authorization` header is missing or malformed, or the key is unknown. |
| `403` | `{"error": "..."}` | A publishable key, or a secret key without `customer_usage:read`. |
| `503` | `{"error": "usage lookup failed", "code": "usage_unavailable", "request_id": "..."}` | The usage counter could not be read. The response has `Retry-After: 1`. Retry after that many seconds, and quote `request_id` to support. |
| `503` | `{"error": "subscription access unavailable"}` | The customer's subscription could not be read. Retry later. |
| `503` | `{"error": "API key verification is unavailable"}` | The key could not be verified. Retry later. |

A failed usage read is never treated as zero usage, so a `503` is not an access decision. Branch on `code`, not on the `error` text.

<Info>
When `allowed` is `false`, the `reason` field tells you why -- use it to show contextual upgrade prompts in your UI. The entitlement decision is authoritative for access at that instant. The economics object is an estimate only and does not create usage, alter a pricing period, or write a financial ledger entry.
</Info>
