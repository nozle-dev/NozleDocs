Base URL: `https://api.nozle.app/core/api/v1`.

Use this Core API when another system already bills the customer and Nozle should provide the plan entitlements without charging them again.

**Base URL:** `https://api.nozle.app/core/api/v1`

**Auth:** secret key with `subscription:write`. Publishable keys are rejected. `Idempotency-Key` is required.

## Import the subscription

```http
POST /customers/workspace_123/billing-state-imports
Authorization: Bearer sk_nozle_...
Idempotency-Key: workspace-123-pro-cutover-v1
Content-Type: application/json

{
  "billing_state_import": {
    "dry_run": false,
    "subscription": {
      "plan_code": "pro_monthly",
      "status": "active",
      "billing_authority": "external",
      "external_reference": "merchant_subscription_123",
      "current_period_start": "2026-08-15T00:00:00Z",
      "current_period_end": "2026-09-15T00:00:00Z"
    }
  }
}
```

For an Entity subscription, add `external_entity_id` beside `subscription`:

```json
{
  "billing_state_import": {
    "external_entity_id": "user_42",
    "subscription": {
      "plan_code": "pro_monthly",
      "status": "active",
      "billing_authority": "external",
      "external_reference": "merchant_user_42_pro",
      "current_period_start": "2026-08-15T00:00:00Z",
      "current_period_end": "2026-09-15T00:00:00Z"
    }
  }
}
```

The referenced customer, plan, and optional Entity must already exist in the authenticated organization. The period must contain the current time and span exactly one plan interval. Periods use exact timestamp-based, half-open boundaries: `current_period_start` is inclusive and `current_period_end` is the first instant of the next period. Non-midnight payment-provider boundaries are preserved exactly—for example, a monthly period from `2026-08-15T10:37:42Z` must end at `2026-09-15T10:37:42Z`. Weekly, monthly, quarterly, semiannual, and yearly calendar advancement is supported, including leap-year and month-end clamping. Month-based periods follow the subscription's anchor day: an anchor on the 29th-31st is clamped down in shorter months and comes back in longer ones. For a subscription anchored on the 31st, both `2026-01-31` to `2026-02-28` and `2026-04-30` to `2026-05-31` are accepted. When `current_period_start` is the last day of its month, `current_period_end` may be any anchor day from that day up to the 31st, clamped to the target month. Shorter, longer, or otherwise mismatched periods are rejected. The imported boundaries are authoritative for current usage reporting and opening-balance expiry. Independent credit-grant cadences remain independent—for example, monthly credits on an annual plan still reset monthly—and lifetime grants remain non-expiring.

## How external periods advance

The import record never changes. After `current_period_end`, Nozle derives the next periods from the imported period and the plan interval: each period starts where the previous one ended and lasts one plan interval, on the original anchor day and time. The anchor day is the later of the imported start and end days of the month. For example, on 2026-09-20 a monthly import of `2026-08-15T00:00:00Z` to `2026-09-15T00:00:00Z` reports current usage for `2026-09-15T00:00:00Z` to `2026-10-15T00:00:00Z`, including every event since 2026-09-15. An import from `2026-04-30` to `2026-05-31` continues with 2026-05-31 to 2026-06-30, then 2026-06-30 to 2026-07-31. The subscription's current billing period advances the same way. Periods keep advancing on this cadence. Nozle does not receive renewals, plan changes, or cancellations from the external system.

## Response

A new import returns `201 Created`. A dry run or a replay returns `200`.

```json
{
  "billing_state_import": {
    "id": "import_uuid",
    "status": "completed",
    "dry_run": false,
    "external_customer_id": "workspace_123",
    "subscription": {
      "id": "subscription_uuid",
      "external_subscription_id": "merchant_subscription_123",
      "external_reference": "merchant_subscription_123",
      "plan_code": "pro_monthly",
      "status": "active",
      "billing_authority": "external",
      "credit_import_required": true,
      "current_period_start": "2026-08-15T00:00:00Z",
      "current_period_end": "2026-09-15T00:00:00Z",
      "invoice_created": false
    },
    "replayed": false
  }
}
```

Nozle creates no invoice, checkout, payment-provider customer, or payment request. Externally billed subscriptions are excluded from Nozle invoicing, upgrades, cancellation, dunning, and payment collection.

If `credit_import_required` is `true`, import every opening Credit System balance before switching usage authority to Nozle. Scheduled plan grants remain paused until that import is complete.

For an Entity import, save the `external_subscription_id` returned in this response. Nozle generates that identifier for the Entity subscription; `external_reference` remains your source-system audit reference and is not used as the Entity subscription ID.

## Dry run and retries

Set `dry_run` to `true` to run the same idempotency, Entity ownership, subscription-slot, grant-scope, and period checks as execution without writing subscription state.

A dry run returns `status: "validated"` and `dry_run: true`. It has no top-level `id`, and its `subscription` has no `id` because no subscription is created. A dry run with the key and payload of an import that already completed returns that import as `validated`, with its `id` and `replayed: true`.

Retry an uncertain response with the same idempotency key and identical payload. A replay returns the original result with `replayed: true`. Reusing the key with a different request returns `422` with `idempotency_key: ["idempotency_key_reused"]`.

<Warning>
This endpoint does not transfer billing authority to Nozle. Adopting payment collection later requires a separate explicit migration flow.
</Warning>
