Base URL: `https://api.nozle.app/engine/api/v1`.

The plan catalog is the one part of the API a publishable `pk_` key can call. Use it to build pricing pages and plan selectors.

**Auth:** `pk_` (publishable key) or `sk_` (secret key). A `pk_` key receives a trimmed plan; an `sk_` key receives the whole plan.

<Warning>
A publishable key ships in browsers, so everything it receives is readable by anyone who has the key: prices, usage charges and their rates, taxes, minimum commitments, entitlements, credit grants and `metadata`. Keep negotiated or internal pricing out of the organization whose publishable key you ship. See [Keep sensitive pricing out of the catalog](#keep-sensitive-pricing-out-of-the-catalog).
</Warning>

## What a publishable key can call

| Host | Request | With `pk_` |
|---|---|---|
| Engine `https://api.nozle.app/engine/api/v1` | `GET /plans` | Allowed. List only. |
| Core `https://api.nozle.app/core/api/v1` | `GET /plans` | Allowed. Same body as Engine, with pagination. |
| Core | `GET /plans/{code}` | Allowed. One plan, wrapped as `{ "plan": { ... } }`. Engine does not serve this path. |
| Either host | Any other path or method | `403`. Core returns `{"status": 403, "error": "Publishable keys may only read the public plan catalog", "code": "publishable_key_not_allowed"}`. Engine returns `403` with an `error` message. |

See [Authentication](/api/authentication) for the full credential model.

Engine forwards the request to Core and returns Core's status code and body unchanged, including Core's errors. If Engine cannot reach Core within 10 seconds, it returns `502` with `{"error": "failed to reach billing service"}`.

## Which plans are returned

All top-level plans of the organization, newest first. There is no listed, public or draft flag, so trial plans, pay-in-arrears plans and free plans are all included. Per-customer override plans (plans with a `parent_id`) and deleted plans are not.

- A `pk_` key does not receive plans that are pending deletion. `GET /plans/{code}` returns `404` with `"code": "plan_not_found"` for one.
- An `sk_` key receives them, with `pending_deletion: true`.

### Pagination

Core accepts `page` and `per_page` (default and page size `100`) and returns `meta`. Engine does not forward query parameters: it always returns the first page, so a catalog of more than 100 plans cannot be read completely through Engine. Read larger catalogs through Core.

| `meta` field | Type | Description |
|---|---|---|
| `current_page` | integer | Page returned. |
| `next_page` | integer or `null` | Next page, `null` on the last page. |
| `prev_page` | integer or `null` | Previous page, `null` on the first page. |
| `total_pages` | integer | Number of pages. |
| `total_count` | integer | Number of plans in the catalog. |

## Fields

Identifiers are named `nozle_id`. Amounts named `*_cents` are integers in cents of the plan currency. Amounts inside a charge's `properties` are decimal strings in currency units (for example `"14.99"` is 14.99 USD), not cents.

### Plan

| Field | Type | Description |
|---|---|---|
| `nozle_id` | string (UUID) | Plan identifier. |
| `code` | string | Unique plan code. Use it to start checkout. |
| `name` | string | Plan name. |
| `description` | string or `null` | Plan description. |
| `interval` | string | `weekly`, `monthly`, `quarterly`, `semiannual` or `yearly`. |
| `amount_cents` | integer | Base price per `interval`, before tax, in cents of `amount_currency`. `0` for a free or pure usage-based plan. Usage prices are in `charges`. |
| `amount_currency` | string | ISO 4217 currency code, such as `USD`. |
| `trial_period` | number or `null` | Free trial length in days. |
| `pay_in_advance` | boolean | `true` bills the base price at the start of each period, `false` at the end. |
| `bill_charges_monthly` | boolean or `null` | `true` invoices usage charges monthly on a yearly or semiannual plan. |
| `bill_fixed_charges_monthly` | boolean or `null` | Same, for fixed charges. |
| `charges` | array | Usage charges. Empty when there are none. |
| `fixed_charges` | array | Fixed charges. Only in `GET /plans/{code}`. |
| `minimum_commitment` | object | Present only when the plan has one. |
| `usage_thresholds` | array | Thresholds for progressive billing. |
| `taxes` | array | Taxes applied to the plan. |
| `entitlements` | array | Feature entitlements. |
| `credit_grant_rules` | array | Active credit grant rules. |
| `credit_pool_policies` | array | Active credit pool policies. |
| `metadata` | object | Key-value pairs set on the plan. Absent when there is none. |

**Only a secret key receives:** `invoice_display_name`, `parent_id`, `pending_deletion`, `created_at` and `applicable_usage_thresholds`.

### Charge (`charges[]`)

| Field | Type | Description |
|---|---|---|
| `nozle_id` | string (UUID) | Charge identifier. |
| `code` | string or `null` | Charge code, unique within the plan. |
| `feature_id`, `feature_code` | string | The metered feature the charge prices. |
| `invoice_display_name` | string or `null` | Name shown on invoices. |
| `created_at` | string | Creation time. |
| `charge_model` | string | `standard`, `graduated`, `package`, `percentage`, `volume`, `graduated_percentage`, `custom` or `dynamic`. |
| `properties` | object | The prices. Its keys depend on `charge_model`: `amount` (standard); `graduated_ranges` (graduated); `amount`, `package_size`, `free_units` (package); `volume_ranges` (volume); `rate`, `fixed_amount`, `free_units_per_events`, `free_units_per_total_aggregation` (percentage); `graduated_percentage_ranges` (graduated percentage). |
| `filters` | array | Prices that differ by event property. Each item has `nozle_id`, `charge_code`, `invoice_display_name`, `properties` and `values`, an object that maps each filter key to the array of values it matches, for example `{ "region": ["eu", "us"] }`. |
| `taxes` | array | Taxes applied to the charge. |
| `pay_in_advance` | boolean | `true` invoices the charge immediately, `false` at the end of the period. |
| `invoiceable` | boolean | `false` means no invoice is issued for the charge itself. |
| `regroup_paid_fees` | string or `null` | `invoice` or `null`. |
| `prorated` | boolean | Whether the charge is prorated in the billing period. |
| `min_amount_cents` | integer | Minimum spend for the charge per period, in cents. `0` for none. |
| `accepts_target_wallet` | boolean | Whether the charge accepts a target prepaid wallet. |
| `applied_pricing_unit` | object or `null` | `{ "code", "conversion_rate" }` when the charge is priced in a pricing unit. |
| `parent_id` | string (UUID) or `null` | Parent charge of an override. |

### Fixed charge (`fixed_charges[]`)

Only in `GET /plans/{code}`. Fields: `nozle_id`, `add_on_id`, `add_on_code`, `code`, `invoice_display_name`, `created_at`, `charge_model` (`standard`, `graduated` or `volume`), `pay_in_advance`, `prorated`, `properties`, `units`, `parent_id` and `taxes`.

### Minimum commitment (`minimum_commitment`)

Fields: `nozle_id`, `plan_code`, `commitment_type` (always `minimum_commitment`), `invoice_display_name`, `amount_cents` (per `interval`), `interval`, `created_at`, `updated_at` and `taxes`.

### Usage threshold (`usage_thresholds[]`)

Fields: `nozle_id`, `threshold_display_name`, `amount_cents` (usage amount in cents that triggers a progressive billing invoice), `recurring` (`true` repeats the invoice each time usage grows by `amount_cents`), `created_at` and `updated_at`.

### Tax (`taxes[]`)

Fields: `nozle_id`, `name`, `code`, `description`, `rate` (percentage, for example `20`), `applied_to_organization` (deprecated), `created_at`. The count fields `add_ons_count`, `customers_count`, `plans_count`, `charges_count` and `commitments_count` are always `0`.

### Entitlement (`entitlements[]`)

| Field | Type | Description |
|---|---|---|
| `feature_type` | string | `boolean`, `config` or `metered`. |
| `code`, `name`, `description` | string, string, string or `null` | Feature code and labels. |
| `usage_limit` | integer or `null` | Usage allowed per period. `null` when no limit is set. |
| `privileges` | array | For `config` features, objects with `code`, `name`, `value_type` (`integer`, `string`, `boolean` or `select`), `value` and `config`. Empty for boolean and metered features. |

**Only a secret key receives:** `feature_id`, `hard_limit` (for metered features, `true` blocks usage over the limit), `min_margin_percent`, `margin_enforcement_mode` and `enforce_plan_margin`.

### Credit grant rule (`credit_grant_rules[]`)

| Field | Type | Description |
|---|---|---|
| `nozle_id`, `plan_code` | string | Rule identifier and plan code. |
| `credit_system_code` | string | The credit system that is granted. |
| `amount` | string | Credits granted per run, as an exact decimal such as `"500.0"`. Credits, not cents. |
| `interval` | string | `month`, `year` or `lifetime`. |
| `interval_count` | integer | Periods between grants. |
| `status` | string | `active`. Archived rules are not returned. |

**Only a secret key receives:** `plan_id`, `credit_system_id`, `scope` (`customer` or `entity`), `entity_join_policy`, `entity_leave_policy`, `upgrade_policy`, `downgrade_policy`, `created_at` and `updated_at`.

### Credit pool policy (`credit_pool_policies[]`)

Fields: `nozle_id`, `plan_id`, `plan_code`, `credit_system_id`, `credit_system_code`, `policy` (`entity_only`, `entity_then_customer` or `customer_only`; see [pool policies](/guides/credits/entities#pool-policies)), `status` (`active`), `created_at` and `updated_at`.

## React, Node, Python and Go

The SDKs declare only five fields for each plan (`code`, `name`, `amount_cents`, `amount_currency`, `interval`), but the API sends the fields above.

| Client | At runtime |
|---|---|
| React `usePlans` / `CatalogPlan` | The plan objects from this response. `PricingTable` renders only the fields it knows. |
| Node `plans()` | The plan objects. |
| Python `plans()` | The plan dictionaries. |
| Go `Plans()` | Only the five declared fields; the Go `Plan` struct drops the rest. |

In TypeScript, read an undeclared field by widening the type yourself. See [`usePlans`](/sdks/react/hooks#useplans).

## Filter the catalog on the client

Every plan is returned, so decide in your code which ones to show:

- Decide what to do with plans where `trial_period` is not `null`: show them as trial plans or hide them.
- Decide what to do with pay-in-arrears plans (`pay_in_advance: false`). Their base price is billed at the end of the period.
- Skip the plan codes you never sell on a pricing page, such as internal or legacy plans. Keep that list in your application; the catalog has no flag for it.

## Keep sensitive pricing out of the catalog

Hiding a plan in your UI does not hide it from the API. Anyone can copy the publishable key from your page and call the endpoint directly.

- Do not put negotiated, customer-specific or internal pricing in plans of the organization whose `pk_` key you ship. This covers charges, taxes, minimum commitments, credit grants and `metadata`.
- Do not store secrets, internal notes or account details in a plan `description` or `metadata`.
- If you need internal plans, keep them in a separate organization, so that its publishable key is never shipped.
- If you want a pricing page that shows a smaller set of fields, call the catalog from your backend with an `sk_` key, keep only the fields you want, and pass that list to `PricingTable` through its `plans` prop. The browser then never calls the catalog. The publishable key still works for anyone who has it.
