Base URL: `https://api.nozle.app/engine/api/v1`.

The plan catalog is the one part of the API a publishable `pk_` key can call. Use it to build pricing pages and plan selectors. The response is the **whole plan** as your organization configured it, not a short display object.

**Auth:** `pk_` (publishable key) or `sk_` (secret key). Both receive the same body.

<Warning>
A publishable key ships in browsers, so everything in a plan is readable by anyone who has the key: base price, usage charges and their rates, taxes, minimum commitments, credit grants, entitlements, `metadata`, and plans you do not sell. There is no way to hide a field or a plan from a `pk_` key. Keep sensitive, negotiated or internal pricing out of the organization whose publishable key you ship. See [Keep sensitive pricing out of the catalog](#keep-sensitive-pricing-out-of-the-catalog).
</Warning>

## What a publishable key can call

| Host | Request | With `pk_` |
|---|---|---|
| Engine `https://api.nozle.app/engine/api/v1` | `GET /plans` | Allowed. List only. |
| Core `https://api.nozle.app/core/api/v1` | `GET /plans` | Allowed. Same body as Engine, with pagination. |
| Core | `GET /plans/{code}` | Allowed. One plan, wrapped as `{ "plan": { ... } }`. Engine does not serve this path. |
| Either host | Any other path or method | `403`. Core returns `{"status": 403, "error": "Publishable keys may only read the public plan catalog", "code": "publishable_key_not_allowed"}`. Engine returns `403` with an `error` message. |

See [Authentication](/api/authentication) for the full credential model.

## Which plans are returned

The list contains **all top-level plans of the organization**. There is no listed, public or draft flag to filter on. In particular, the list includes:

- trial plans (`trial_period` is a number of days);
- pay-in-arrears plans (`pay_in_advance` is `false`);
- free plans and plans with no base price;
- plans pending deletion (`pending_deletion` is `true`).

It does not include per-customer override plans (plans with a `parent_id`) or plans that are already deleted. Plans are sorted newest first by `created_at`.

`GET /plans/{code}` returns the same plan, and it also returns a plan that is pending deletion. An unknown code returns `404` with `"code": "plan_not_found"`.

### Pagination

Core accepts `page` and `per_page` (default and page size `100`) and returns `meta`. Engine does not forward query parameters: it always returns the first page, so a catalog of more than 100 plans cannot be read completely through Engine. Read larger catalogs through Core.

| `meta` field | Type | Description |
|---|---|---|
| `current_page` | integer | Page returned. |
| `next_page` | integer or `null` | Next page, `null` on the last page. |
| `prev_page` | integer or `null` | Previous page, `null` on the first page. |
| `total_pages` | integer | Number of pages. |
| `total_count` | integer | Number of plans in the catalog. |

## Fields

Identifiers are named `nozle_id`. Amounts named `*_cents` are integers in cents of the plan currency. Amounts inside a charge's `properties` are decimal strings in currency units (for example `"14.99"` is 14.99 USD), not cents.

### Plan

| Field | Type | Description |
|---|---|---|
| `nozle_id` | string (UUID) | Plan identifier. |
| `code` | string | Unique plan code. Use it to start checkout. |
| `name` | string | Plan name. |
| `invoice_display_name` | string or `null` | Name shown on invoices. `null` when not set. |
| `description` | string or `null` | Plan description. `null` when not set. |
| `created_at` | string (ISO 8601, UTC) | Creation time. |
| `interval` | string | Billing interval: `weekly`, `monthly`, `quarterly`, `semiannual` or `yearly`. |
| `amount_cents` | integer | Base price per `interval`, before tax, in cents of `amount_currency`. `0` for a free or pure usage-based plan. Usage prices are in `charges`. |
| `amount_currency` | string | ISO 4217 currency code, such as `USD`. |
| `trial_period` | number or `null` | Free trial length in days. `null` when the plan has no trial. |
| `pay_in_advance` | boolean | `true` bills the base price at the start of each period. `false` bills it at the end (pay in arrears). |
| `bill_charges_monthly` | boolean or `null` | `true` invoices usage charges monthly on a yearly or semiannual plan. `null` when not set. |
| `bill_fixed_charges_monthly` | boolean or `null` | Same, for fixed charges. |
| `customers_count` | integer | Reserved. Always `0`. Do not rely on it. |
| `active_subscriptions_count` | integer | Reserved. Always `0`. Do not rely on it. |
| `draft_invoices_count` | integer | Reserved. Always `0`. Do not rely on it. |
| `parent_id` | string (UUID) or `null` | Parent plan of a per-customer override. `null` for every plan the catalog returns. |
| `pending_deletion` | boolean | `true` when deletion was requested and is still being processed. Do not offer these plans. |
| `charges` | array | Usage charges. Empty array when there are none. |
| `fixed_charges` | array | Fixed charges. Only in `GET /plans/{code}`, not in the list. |
| `minimum_commitment` | object | Minimum commitment. The key is absent when the plan has none. |
| `usage_thresholds` | array | Usage thresholds for progressive billing. Empty array when there are none. |
| `applicable_usage_thresholds` | array | Thresholds that apply to the plan. Same as `usage_thresholds` for catalog plans, without ids or timestamps. |
| `taxes` | array | Taxes applied to the plan. Empty array when there are none. |
| `entitlements` | array | Feature entitlements. |
| `credit_grant_rules` | array | Active credit grant rules. |
| `credit_pool_policies` | array | Active credit pool policies. |
| `metadata` | object | Key-value pairs set on the plan. The key is absent when the plan has no metadata. |

### Charge (`charges[]`)

| Field | Type | Description |
|---|---|---|
| `nozle_id` | string (UUID) | Charge identifier. |
| `code` | string or `null` | Charge code, unique within the plan. |
| `feature_id`, `feature_code` | string | The metered feature the charge prices. |
| `invoice_display_name` | string or `null` | Name shown on invoices. |
| `created_at` | string | Creation time. |
| `charge_model` | string | `standard`, `graduated`, `package`, `percentage`, `volume`, `graduated_percentage`, `custom` or `dynamic`. |
| `properties` | object | The prices. Its keys depend on `charge_model`: `amount` (standard); `graduated_ranges` (graduated); `amount`, `package_size`, `free_units` (package); `volume_ranges` (volume); `rate`, `fixed_amount`, `free_units_per_events`, `free_units_per_total_aggregation` (percentage); `graduated_percentage_ranges` (graduated percentage). It is returned as it was saved, so the last range of a tier list can have `"to_value": null` or no `to_value`. |
| `filters` | array | Prices that differ by event property. Each item has `nozle_id`, `charge_code`, `invoice_display_name`, `properties` and `values`. |
| `taxes` | array | Taxes applied to the charge. |
| `pay_in_advance` | boolean | `true` invoices the charge immediately. `false` invoices it at the end of the period. |
| `invoiceable` | boolean | `false` means no invoice is issued for the charge itself. |
| `regroup_paid_fees` | string or `null` | `invoice` or `null`. |
| `prorated` | boolean | Whether the charge is prorated in the billing period. |
| `min_amount_cents` | integer | Minimum spend for the charge per period, in cents. `0` for none. |
| `accepts_target_wallet` | boolean | Whether the charge accepts a target prepaid wallet. |
| `applied_pricing_unit` | object or `null` | `{ "code", "conversion_rate" }` when the charge is priced in a pricing unit. |
| `parent_id` | string (UUID) or `null` | Parent charge of an override. |

### Fixed charge (`fixed_charges[]`)

Only in `GET /plans/{code}`. Fields: `nozle_id`, `add_on_id`, `add_on_code`, `code`, `invoice_display_name`, `created_at`, `charge_model` (`standard`, `graduated` or `volume`), `pay_in_advance`, `prorated`, `properties` (same keys as a charge for that model), `units` (number), `parent_id` and `taxes`.

### Minimum commitment (`minimum_commitment`)

Present only when the plan has one. Fields: `nozle_id`, `plan_code`, `invoice_display_name`, `amount_cents` (cents per `interval`), `interval`, `created_at`, `updated_at` and `taxes`.

### Usage threshold (`usage_thresholds[]`)

| Field | Type | Description |
|---|---|---|
| `nozle_id` | string (UUID) | Threshold identifier. |
| `threshold_display_name` | string or `null` | Display name. |
| `amount_cents` | integer | Usage amount, in cents, that triggers a progressive billing invoice. |
| `recurring` | boolean | `true` repeats the invoice each time usage grows by `amount_cents`. |
| `created_at`, `updated_at` | string | Timestamps. |

### Tax (`taxes[]`)

Fields: `nozle_id`, `name`, `code`, `description` (string or `null`), `rate` (percentage, for example `20`), `applied_to_organization` (deprecated), `created_at`. The count fields `add_ons_count`, `customers_count`, `plans_count`, `charges_count` and `commitments_count` are always `0`.

### Entitlement (`entitlements[]`)

| Field | Type | Description |
|---|---|---|
| `feature_id` | string (UUID) | Feature identifier. |
| `feature_type` | string | `boolean`, `config` or `metered`. |
| `code`, `name`, `description` | string, string, string or `null` | Feature code and labels. |
| `usage_limit` | integer or `null` | Usage allowed per period. `null` when no limit is set. |
| `hard_limit` | boolean or `null` | For metered features, `true` blocks usage over the limit. `null` for other types. |
| `min_margin_percent` | number or `null` | Minimum margin the plan must keep on the feature. |
| `margin_enforcement_mode` | string or `null` | `enforce`, `warn` or `off` for metered features. `null` for other types. |
| `enforce_plan_margin` | boolean or `null` | For metered features, whether the plan margin is enforced. `null` for other types. |
| `privileges` | array | For `config` features, objects with `code`, `name`, `value_type` (`integer`, `string`, `boolean` or `select`), `value` and `config`. Empty for boolean and metered features. |

### Credit grant rule (`credit_grant_rules[]`)

| Field | Type | Description |
|---|---|---|
| `nozle_id`, `plan_id`, `plan_code` | string | Rule and plan identifiers. |
| `credit_system_id`, `credit_system_code` | string | The credit system that is granted. |
| `amount` | string | Credits granted per run, as an exact decimal such as `"500.0"`. Credits, not cents. |
| `interval` | string | `month`, `year` or `lifetime`. |
| `interval_count` | integer | Periods between grants. |
| `scope` | string | `customer` or `entity`. |
| `entity_join_policy` | string or `null` | `full_grant`, `prorated` or `next_period`. `null` for `customer` scope. |
| `entity_leave_policy` | string or `null` | `expire_plan_grant`. `null` for `customer` scope. |
| `upgrade_policy` | string | `grant_difference`. |
| `downgrade_policy` | string | `next_period`. |
| `status` | string | `active`. Archived rules are not returned. |
| `created_at`, `updated_at` | string | Timestamps. |

### Credit pool policy (`credit_pool_policies[]`)

Fields: `nozle_id`, `plan_id`, `plan_code`, `credit_system_id`, `credit_system_code`, `policy` (`entity_only`, `entity_then_customer` or `customer_only`; see [pool policies](/guides/credits/entities#pool-policies)), `status` (`active`), `created_at` and `updated_at`.

## React, Node, Python and Go

The browser SDK declares only five fields for each plan, but the API sends the fields above.

| Client | Declared by the SDK | At runtime |
|---|---|---|
| React `usePlans` / `CatalogPlan` | `code`, `name`, `amount_cents`, `amount_currency`, `interval` | The full plan objects from this response. `PricingTable` renders only what it knows. |
| Node `plans()` | Same five fields | The full plan objects. |
| Python `plans()` | Same five fields | The full plan dictionaries. |
| Go `Plans()` | Same five fields | Only these five fields; the Go `Plan` struct drops the rest. |

In TypeScript, read an undeclared field by widening the type yourself. See [`usePlans`](/sdks/react/hooks#useplans).

## Filter the catalog on the client

Because every plan is returned, decide in your code which ones to show. The API does not do it for you.

- Skip `pending_deletion: true`. These plans are being removed.
- Decide what to do with plans where `trial_period` is not `null`. Show them as trial plans, or hide them.
- Decide what to do with pay-in-arrears plans (`pay_in_advance: false`). Their base price is billed at the end of the period.
- Skip the plan codes you never sell on a pricing page, such as internal or legacy plans. Keep that list in your application; the catalog has no flag for it.

```tsx
import { usePlans, type CatalogPlan } from '@nozle-js/react'

// The API returns these fields; the SDK type does not declare them.
type CatalogPlanDetail = CatalogPlan & {
  pending_deletion?: boolean
  trial_period?: number | null
  pay_in_advance?: boolean
}

const HIDDEN_PLAN_CODES = new Set(['internal_staff'])

export function usePricingPlans() {
  const { plans, isLoading, error } = usePlans()
  const visible = (plans as CatalogPlanDetail[]).filter(
    (plan) => plan.pending_deletion !== true && !HIDDEN_PLAN_CODES.has(plan.code),
  )
  return { plans: visible, isLoading, error }
}
```

## Keep sensitive pricing out of the catalog

Hiding a plan in your UI does not hide it from the API. Anyone can copy the publishable key from your page and call the endpoint directly.

- Do not put negotiated, customer-specific or internal pricing in plans of the organization whose `pk_` key you ship. This covers charges, taxes, minimum commitments, credit grants and `metadata`.
- Do not store secrets, internal notes or account details in a plan `description` or `metadata`.
- If you need internal plans, keep them in a separate organization, so that its publishable key is never shipped, and use the public-facing organization only for plans you are happy to publish.
- If you want a pricing page that shows a reduced set of fields, call the catalog from your backend with an `sk_` key, keep only the fields you want, and pass that list to `PricingTable` through its `plans` prop. The browser then never calls the catalog. The publishable key still works for anyone who has it.
