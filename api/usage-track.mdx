---
title: Track and Consume Credits
api: "POST https://api.nozle.app/engine/api/v1/usage/track"
description: Atomically consume credits and queue the matching billing event
---

Base URL: `https://api.nozle.app/engine/api/v1`.

**Auth:** secret key only. The customer, Feature, and optional Credit System must belong to the authenticated organization.

```http
POST /usage/track
Authorization: Bearer sk_nozle_...
Idempotency-Key: execution_0183f
Content-Type: application/json
```

```json
{
  "customer_id": "customer_123",
  "feature_code": "agent_execution",
  "credit_system_code": "ai_credits",
  "properties": {},
  "timestamp": "2026-07-20T12:00:00.750Z"
}
```

A successful response includes the operation ID, exact credits consumed,
remaining total, and source deductions with their balance-source IDs.
Insufficient credits return `allowed=false` without allocations or a
Core event.

`timestamp` is required. A missing or empty value returns `400 invalid_request` with `timestamp is required`; the API does not default it. The Node.js, Python and Go SDKs fill it with the current time when you omit it. It must be Unix seconds (a JSON number such as `1788345001` or `1788345001.5`, or a numeric string such as `"1788345001"`) or an RFC 3339 string with a time zone offset or `Z`. A date without a time, a time without an offset, zero or negative seconds, and any other JSON type return `400 invalid_request` with `timestamp must be Unix seconds (a number or a numeric string) or an RFC 3339 timestamp with an offset or Z` (zero or negative seconds: `timestamp must be greater than zero`). Unix seconds are available from the Engine release that includes this change; before it, only RFC 3339 is accepted. RFC 3339 keeps its nanoseconds, so a replay must send the same value; the same instant sent in another form is a different request body. The time must also fall after the Credit System rate became effective; an earlier time returns `422 no effective credit rate`.

Retry HTTP `503` with the same idempotency key and the same body, including the same `timestamp`. A replay returns the original result without consuming credits again, and that includes an `allowed=false` denial. Reusing a key with a different body returns `409` with `{"code": "idempotency_key_reused"}`. An SDK call without a `timestamp` gets a new time on each attempt, so its retry no longer matches: store the time once per unit of work and send it on every attempt.

For staged validation and canary guidance, see [Credit Rollout and Acceptance](/guides/credits/rollout).
