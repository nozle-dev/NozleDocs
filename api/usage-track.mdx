---
title: Track and Consume Credits
api: "POST https://api.nozle.app/engine/api/v1/usage/track"
description: Atomically consume credits and queue the matching billing event
---

Base URL: `https://api.nozle.app/engine/api/v1`.

**Auth:** secret key only. The customer, Feature, and optional Credit System must belong to the authenticated organization.

```http
POST /usage/track
Authorization: Bearer sk_nozle_...
Idempotency-Key: execution_0183f
Content-Type: application/json
```

```json
{
  "customer_id": "customer_123",
  "feature_code": "agent_execution",
  "credit_system_code": "ai_credits",
  "properties": {},
  "timestamp": "2026-07-20T12:00:00.750Z"
}
```

`customer_id` and `feature_code` are required. Add `entity_id` to attribute the usage to one Entity of the customer and spend under its pool policy. Unknown fields return `400 invalid_request`. An unknown Entity returns `404 entity_not_found`, an inactive Entity returns `422 entity_inactive`, and Entity usage without an explicit pool policy on the plan returns `422 credit_pool_policy_not_configured`.

A successful response includes the operation ID, exact credits consumed,
remaining total, and source deductions with their balance-source IDs:

```json
{
  "allowed": true,
  "operation_id": "8d3c2b1a-0f9e-4d8c-b7a6-5e4d3c2b1a09",
  "metric_amount": "1",
  "credit_system": "ai_credits",
  "credits_consumed": "2",
  "remaining": "623",
  "deductions": [
    {
      "balance_source_id": "bf659149-0d70-4d2a-8a7b-a4569cc742eb",
      "source_type": "subscription_grant",
      "source_scope": "customer",
      "amount": "2",
      "remaining": "623"
    }
  ]
}
```

Insufficient credits return `200` with `allowed=false`, `credits_required`,
`available`, and `reason`, without allocations or a Core event. `entity_id`
and `pool_policy` are included when they apply. Empty fields are omitted.

`timestamp` is required. A missing or empty value returns `400 invalid_request` with `timestamp is required`; the API does not default it. The Node.js, Python and Go SDKs fill it with the current time when you omit it. It must be Unix seconds (a JSON number such as `1788345001` or `1788345001.5`, or a numeric string such as `"1788345001"`) or an RFC 3339 string with a time zone offset or `Z`. A date without a time, a time without an offset, zero or negative seconds, and any other JSON type return `400 invalid_request` with `timestamp must be Unix seconds (a number or a numeric string) or an RFC 3339 timestamp with an offset or Z` (zero or negative seconds: `timestamp must be greater than zero`). Unix seconds are available from the Engine release that includes this change; before it, only RFC 3339 is accepted. RFC 3339 keeps its nanoseconds, so a replay must send the same value; the same instant sent in another form is a different request body. The time must also fall after the Credit System rate became effective; an earlier time returns `422` with code `credit_usage_configuration_invalid` and the message `no effective credit rate`.

`Idempotency-Key` is required and must not exceed 255 bytes; otherwise the request returns `400 invalid_request`. Retry HTTP `503` with the same idempotency key and the same body, including the same `timestamp`. The `503` codes are `credit_usage_contention` (`Retry-After: 1`), `credit_usage_publication_backlog` (`Retry-After: 30`), and `credit_usage_temporarily_unavailable` (`Retry-After: 1`). A replay returns the original result without consuming credits again, and that includes an `allowed=false` denial. Reusing a key with a different body returns `409` with `{"code": "idempotency_key_reused"}`. An SDK call without a `timestamp` gets a new time on each attempt, so its retry no longer matches: store the time once per unit of work and send it on every attempt.
