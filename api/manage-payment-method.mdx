---
title: "Manage Payment Method"
api: "POST https://api.nozle.app/engine/api/v1/customers/{customer_id}/payment-method/manage"
---

Base URL: `https://api.nozle.app/engine/api/v1`.

Return the page where a customer adds or changes their payment method: Nozle's card page or the Stripe Billing Portal for a Stripe customer, or Nozle's auto-pay setup page for a Razorpay customer whose connection has auto-pay on.

**Auth:** secret key (`sk_`) with `payment:write`, or trusted internal auth. Publishable keys are always refused with `403`. A customer-scoped credential reaches only its own customer.

<Info>
Nozle stores no card data and never shows card details. The payment method lives at the payment provider, so this endpoint sends the customer there. Call it from your backend for the logged-in user or team, then redirect the browser to the returned `url`.
</Info>

## Request

<ParamField path="customer_id" type="string" required>
  External customer ID. The customer must already exist and be linked to a payment provider.
</ParamField>

<ParamField body="return_url" type="string">
  Where Stripe sends the customer when they leave the Billing Portal. Razorpay customers are not sent back, so it has no effect for them, but it is still checked. It must be an absolute HTTPS URL on one of your organization's allowed origins, the same list as [checkout](/api/create-checkout#return-url). If omitted, Nozle uses the organization's default return URL. The body can be empty.
</ParamField>

```json
{ "return_url": "https://app.example.com/settings/billing" }
```

## Response

Core's body is returned unchanged:

<ResponseField name="manage_payment_method.provider" type="string" required>
  `stripe` or `razorpay`.
</ResponseField>

<ResponseField name="manage_payment_method.url" type="string" required>
  For a Stripe customer, the URL of Nozle's card page when the connection has a publishable key and the customer pays by card only (the page registers an e-mandate for a card issued in India), otherwise a Stripe Billing Portal URL. For a Razorpay customer, the URL of Nozle's auto-pay setup page. Redirect the customer to it, or show the card page in a frame (see below).
</ResponseField>

<ResponseField name="manage_payment_method.expires_at" type="string | null">
  When the page stops working, as an RFC 3339 UTC timestamp. `null` for Stripe Billing Portal sessions. For the Nozle card page and the Razorpay setup page, 24 hours after the call.
</ResponseField>

```json
{
  "manage_payment_method": {
    "url": "https://billing.stripe.com/p/session/test_...",
    "expires_at": null,
    "provider": "stripe"
  }
}
```

For a Razorpay customer:

```json
{
  "manage_payment_method": {
    "url": "https://api.nozle.app/core/payment_methods/setup?token=...",
    "expires_at": "2026-10-29T10:15:00Z",
    "provider": "razorpay"
  }
}
```

## Stripe customers

- **Nozle card page.** With a publishable key on the connection and a customer who pays by card only, `url` is Nozle's card page. It needs a return URL, from the request or the organization's default; without either, the Billing Portal is returned. The customer comes back to the return URL with `nozle_card=succeeded`, `processing` or `failed`. If Stripe rejects the publishable key, the page sends the customer to Stripe Checkout instead.
- **In your app.** Add `embed=1` to the `url` to show the page in a frame. Nozle allows framing only from the origin of the return URL, and the page posts `{ "source": "nozle", "type": "card_setup", "status": "ready" | "succeeded" | "processing" | "failed" | "error", "mode": "setup" }` to your page. In React, use [`NozleCardSetup`](/sdks/react/components/nozle-card-setup) (available from `@nozle-js/react` 0.20.0). See [Show the card page in your app](/integrations/stripe#show-the-card-page-in-your-app).
- **Billing Portal.** Otherwise the `url` is a Stripe Billing Portal session, as before.

## Razorpay customers

Razorpay has no portal and its mandates cannot be edited, so a Razorpay customer sets up a new auto-pay mandate instead. What this endpoint does depends on the customer's Razorpay connection:

- **Auto-pay on** (**Enable recurring payments** on the connection). The `url` opens Nozle's auto-pay setup page. It lists the auto-pay methods enabled on the connection (UPI, card and bank debit through Razorpay eMandate; UPI and card by default) with what each one charges, and shows the customer's current method. With a single enabled method the list is skipped. The customer's choice creates a Razorpay registration link for that method and redirects to it. UPI and card authorize ₹1, which is refunded once captured; bank debit authorizes ₹0. Once Razorpay confirms the mandate it becomes the customer's default payment method, replaces the mandates it covers (they are cancelled at Razorpay), and the customer's open INR subscription invoices are collected with it. Nothing is created at Razorpay until the customer picks a method.
- **Auto-pay off.** The endpoint answers `422 razorpay_pays_by_link` with `auto_pay_not_enabled` in the error details, and creates nothing at Razorpay. The customer pays each invoice through a Razorpay payment link: when an invoice is finalized and no mandate charges it, Nozle emails the customer a payment request for that invoice with a **Pay invoice** button (the billing entity and the customer need an email address). The button always opens a current Razorpay payment link, also after an earlier link expired, and paying it marks the invoice paid. Dunning campaigns do not send a second request for such an invoice.

The setup page works for 24 hours (`expires_at`); after that, or with an invalid token, it answers `410`. Call this endpoint again for a new page. Razorpay does not send the customer back to your app after registration: follow the `payment_method.created` and `payment_method.updated` webhooks to learn when the mandate is confirmed.

## Errors

The Engine checks the JSON body, then sends the request to Core, which checks `return_url`.

| Status | Code | Cause |
| --- | --- | --- |
| `400` | `invalid_return_url` | `return_url` is not an absolute HTTPS URL, or its origin is not one of your organization's allowed origins. |
| `403` | — | A publishable key was used. The Engine answers with an `error` message, not a code. |
| `404` | `customer_not_found` | Unknown customer. |
| `422` | `no_linked_payment_provider` | The customer has no payment provider. |
| `422` | `razorpay_pays_by_link` | The customer pays through Razorpay and the connection has auto-pay off (`auto_pay_not_enabled` in `error_details.auto_pay`). The customer pays each invoice by payment link. |
| `422` | `payment_method_not_enabled` | Razorpay: no auto-pay method is enabled on the connection. |
| `422` | `customer_details_required` | Razorpay: the customer needs a name, email and phone number before setting up auto-pay. |
| `422` | `provider_not_supported` | The customer's provider is not Stripe or Razorpay (Adyen, Cashfree, Flutterwave, GoCardless and Moneyhash are not supported). |
| `422` | `missing_payment_provider_customer` | The customer could not be created at Stripe, or is not linked to its Razorpay connection. |

For `422` errors the code is in `error_details`, for example `{"code": "validation_errors", "error_details": {"base": ["razorpay_pays_by_link"], "auto_pay": ["auto_pay_not_enabled"]}}`. Match on the code, never on the message text.

## SDKs

The SDK methods return the inner `manage_payment_method` object.

| SDK | Method |
| --- | --- |
| Node | `client.managePaymentMethod(customerId, returnUrl?, { idempotencyKey? })` |
| Python | `manage_payment_method(customer_id, return_url=None, *, idempotency_key=None)` |
| Go | `ManagePaymentMethod(ctx, customerID, returnURL, key)` |

The idempotency option (`idempotencyKey`, `idempotency_key`, or `key` in Go) is optional. Send the same value when retrying the same request.

See the Billing pages: [Node](/sdks/node/billing#manage-a-payment-method), [Python](/sdks/python/billing#manage-a-payment-method) and [Go](/sdks/go/billing#manage-a-payment-method).
