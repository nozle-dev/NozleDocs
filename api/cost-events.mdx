---
title: Cost Events
api: "POST https://api.nozle.app/engine/api/v1/cost-events"
description: Send detailed internal cost usage from a trusted backend
---

Base URL: `https://api.nozle.app/engine/api/v1`. The Core host does not serve this route and returns `404`.

**Auth:** secret key only. With [API key permissions](/api/authentication#key-permissions), the key needs `event:write`; without it the call returns `403` with `code: permission_denied`.

Use Cost Events for internal usage that needs more detail than the customer-facing Feature Event, such as artificial intelligence tokens, emails, storage operations, or third-party requests.

The Cost Model creation flow includes a provider-neutral **Artificial Intelligence tokens** template. You can enter rates manually or select an effective-dated provider price catalogue version. Nozle creates one `ai_tokens` meter and separate exact rules for each configured token category.

The supported Version One categories are `input`, `cached_input`, `cache_write`, `output`, and `reasoning`. Provider catalogue references are retained on the Cost Rule so negotiated overrides remain traceable to their base prices. Unknown provider, model, or token-category combinations enter the Uncosted queue instead of silently becoming zero-cost usage.

```json
{
  "cost_event_id": "cost_01994d7e",
  "cost_meter_code": "ai_tokens",
  "parent_transaction_id": "feature_01994d7e",
  "external_customer_id": "customer_123",
  "request_id": "provider_request_987",
  "operation_key": "planning",
  "properties": {
    "tokens": 900,
    "provider": "openai",
    "model": "configured-model-a",
    "type": "input"
  },
  "timestamp": 1788345001
}
```

`timestamp` is Unix seconds (a JSON number such as `1788345001` or `1788345001.5`, or a numeric string such as `"1788345001"`) or an RFC 3339 string with a time zone offset or `Z`. Omit it to use the time Nozle receives the event. A date without a time, a time without an offset, or another JSON type returns `400 invalid_request` with `timestamp must be Unix seconds (a number or a numeric string) or an RFC 3339 timestamp with an offset or Z`; zero or negative seconds return `422` with `timestamp must be greater than zero`. Strings are accepted from the Engine release that includes this change; before it, only a number is accepted and any string returns `400 invalid request body`. An RFC 3339 value is stored as Unix seconds.

At least one attribution field is required:

- `parent_transaction_id` links the cost to an existing or future Feature Event in the same organization.
- `external_customer_id` records a customer-direct cost that is not linked to a Feature.
- Both may be provided; asynchronous processing verifies that they resolve to the same customer.

The endpoint returns `202 Accepted` with `{"status": "accepted", "cost_event_id": "..."}` after Kafka durably acknowledges the message; cost calculation and analytics happen asynchronously. Once rated, the cost appears in the [cost intelligence report](/api/cost-intelligence-report) and in the margin views (`/margin/*` and the dashboard margin views), attributed to the customer and to the parent Feature Event's Feature and plan. A Cost Event never adds revenue. See [Margin Intelligence](/guides/margin/overview).

If `cost_event_id` is omitted, Nozle generates and returns a version 7 universally unique identifier. Reuse the same identifier and payload when retrying a Cost Event. Posting the same `cost_event_id` again also returns `202`; the duplicate is removed when the event is processed.

<Warning>
The endpoint does not check `cost_meter_code` when it accepts the event. An unknown meter code still returns `202`. Processing then marks the event `uncosted` with the failure code `unknown_cost_event_meter` ("No active Cost Event Meter matches the event code"), and it appears in the Uncosted queue of the [cost intelligence report](/api/cost-intelligence-report). It adds no cost to the totals until you correct the meter and rate it again. Copy the code exactly from the Cost Model.
</Warning>

## Provider usage capture

The [Node.js](/sdks/node/llm-auto-capture), [Python](/sdks/python/llm-auto-capture), and [Go](/sdks/go/llm-usage) SDKs capture OpenAI and Anthropic usage automatically from completed responses and streams. Each records a parent Feature Event and optional detailed Cost Events. Set `costMeterCode` in Node.js, `cost_meter_code` in Python, or `CostMeterCode` in Go. The parent `transaction_id` is generated before delivery, so child Cost Events may safely arrive before the Feature Event.

Node.js and Python wrap the provider client methods. Go wraps the HTTP client passed to the official provider SDK using `WrapOpenAIHTTPClient` or `WrapAnthropicHTTPClient`. Go's `CaptureOpenAIUsage` and `CaptureAnthropicUsage` methods also support manual or queued delivery.

For providers without a wrapper, or for cost-only tracking, send Cost Events yourself: [`costEvents.track`](/sdks/node/llm-auto-capture#manual-cost-events) in Node.js, [`cost_events.track`](/sdks/python/llm-auto-capture#manual-cost-events) in Python, or [`TrackCostEvent`](/sdks/go/tracking-events) in Go. A Cost Event never bills the customer.

Each non-zero category is emitted separately with canonical properties:

```json
{
  "tokens": 900,
  "provider": "openai",
  "model": "configured-model-a",
  "type": "cached_input"
}
```

The provider response remains authoritative to the application. Tracking failures never replace a successful provider response.
