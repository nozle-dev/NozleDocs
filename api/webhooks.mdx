title: Webhooks

Nozle processes payment webhooks for each connected Stripe account and for each connected Razorpay account. The sections below describe Stripe first, then [Razorpay](#razorpay).

**How it works:**

1. You connect a Stripe account to a Nozle organization.
2. Nozle registers a Stripe webhook endpoint for that Stripe account.
3. Stripe sends payment events to your public Nozle API URL.
4. Nozle verifies the `Stripe-Signature` header using the webhook secret returned by Stripe.
5. Nozle updates invoice payment status and resolves any payment-gated subscription activation.

**Key events processed:**

| Event | What Nozle Does |
|-------|----------------|
| payment_intent.succeeded | Marks the invoice paid; activates payment-gated subscriptions and applies paid upgrades |
| payment_intent.payment_failed | Marks the payment failed. A declined card on a payment-gated checkout keeps the invoice open for a retry; any other failure cancels the incomplete subscription |
| payment_intent.canceled | Treats the payment attempt as failed |
| setup_intent.succeeded | Stores the customer's new default payment method |
| payment_method.detached | Clears a removed payment method |
| customer.updated | Syncs the customer's default payment method |
| charge.refund.updated | Updates the credit-note refund status |
| charge.dispute.closed | Marks the invoice's dispute lost when the dispute is lost |

**Plan features provisioned on subscription:**

Starter plan: base features only
Growth plan: revenue_analytics, remove_branding_watermark, auto_dunning, progressive_billing, lifetime_usage
Scale plan: everything in Growth PLUS netsuite, xero, hubspot, salesforce, okta, avalara, api_permissions, custom_roles, forecasted_usage, security_logs, from_email, issue_receipts, manual_payments, multi_entities_pro

**Setup:**

Nozle registers the Stripe webhook automatically in a background job right after you connect Stripe. The target is:

```text
https://api.nozle.app/core/webhooks/stripe/{organization_id}?code={stripe_provider_code}
```

Your Stripe account must allow webhook endpoint creation, and your public Nozle API URL must be reachable by Stripe. If registration fails, Nozle sends a `payment_provider.error` webhook and does not retry. See the [Stripe integration](/integrations/stripe#webhook-setup) for the events, recovery and limits.

## Razorpay

Nozle does not register the Razorpay webhook. You add it in the Razorpay dashboard, with the webhook secret you entered on the Nozle connection. The target is the Webhook URL shown on the connection:

```text
https://api.nozle.app/core/webhooks/razorpay/{payment_provider_id}
```

Nozle verifies the `X-Razorpay-Signature` header, an HMAC-SHA256 of the raw request body with the webhook secret, and de-duplicates on the `X-Razorpay-Event-Id` header. An invalid request returns `400`; a valid one returns `200`.

| Event | What Nozle Does |
|-------|----------------|
| payment.authorized | Fetches the payment; waits for capture |
| payment.captured, order.paid, payment_link.paid | Fetches the payment and settles the invoice once it is captured |
| payment.failed | Fetches the payment; an interactive order stays open for retry |
| refund.processed, refund.failed | Updates the credit-note refund status |
| payment.dispute.lost, payment.dispute.closed | Applies a lost dispute; a closed or won dispute is not treated as lost |
| token.confirmed, token.rejected, token.cancelled, token.paused, token.resumed | Updates the UPI AutoPay mandate |

See the [Razorpay integration](/integrations/razorpay#webhook-setup) for setup and the checkout flow.
