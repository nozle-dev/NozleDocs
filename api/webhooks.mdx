title: Webhooks
description: Stripe and Razorpay webhook events and signature verification

Nozle processes payment webhooks for each connected Stripe account and for each connected Razorpay account. The sections below describe Stripe first, then [Razorpay](#razorpay).

This page is about the events providers send to Nozle. To receive the webhooks Nozle sends to your application, and to verify their `standard` signature, see [Receive Nozle webhooks](/api/receive-webhooks).

**How it works:**

1. You connect a Stripe account to a Nozle organization.
2. Nozle registers a Stripe webhook endpoint for that Stripe account.
3. Stripe sends payment events to your public Nozle API URL.
4. Nozle verifies the `Stripe-Signature` header using the webhook secret returned by Stripe. It subscribes to the ten events below only, and it does not de-duplicate Stripe events by event ID: replays are safe because handlers act on the current state.
5. Nozle updates invoice payment status and resolves any payment-gated subscription activation.

**Key events processed:**

| Event | What Nozle Does |
|-------|----------------|
| payment_intent.succeeded | Marks the invoice paid; activates payment-gated subscriptions and applies paid upgrades |
| payment_intent.payment_failed | Marks the payment failed. A declined card on a payment-gated checkout keeps the invoice open for a retry; any other failure cancels the incomplete subscription |
| payment_intent.canceled | Treats the payment attempt as failed |
| setup_intent.succeeded | Stores the customer's new default payment method |
| mandate.updated | Records the status of an India card mandate and retries the customer's pending invoices when it becomes active. See [Indian cards](/integrations/stripe#indian-cards-and-automatic-payments) |
| payment_method.detached | Received, but it does not clear the stored payment method today (known bug) |
| customer.updated | Syncs the customer's default payment method |
| refund.updated, refund.failed | Updates the credit-note refund status. The older `charge.refund.updated` is still accepted for one release |
| charge.dispute.closed | Marks the invoice's dispute lost when the dispute is lost |

**Setup:**

Nozle registers the Stripe webhook automatically in a background job right after you connect Stripe. The target is:

```text
https://api.nozle.app/core/webhooks/stripe/{organization_id}?code={stripe_provider_code}
```

Your Stripe account must allow webhook endpoint creation, and your public Nozle API URL must be reachable by Stripe. Registration is retried (up to 6 attempts) when Stripe rate-limits or is briefly unavailable. When Stripe refuses it (a key without permission, the limit of 16 test-mode endpoints, or a URL that is not public), Nozle sends a `payment_provider.error` webhook with Stripe's message. Check your Stripe dashboard for the endpoint to confirm registration. See the [Stripe integration](/integrations/stripe#webhook-setup) for the events, recovery and limits.

## Razorpay

Nozle does not register the Razorpay webhook. You add it in the Razorpay dashboard, with the webhook secret you entered on the Nozle connection. The target is the Webhook URL shown on the connection:

```text
https://api.nozle.app/core/webhooks/razorpay/{payment_provider_id}
```

Nozle verifies the `X-Razorpay-Signature` header, an HMAC-SHA256 of the raw request body with the webhook secret, and de-duplicates on the `X-Razorpay-Event-Id` header. A valid request returns `200`. A request returns `400` when the provider ID is unknown or not a UUID, the signature is not lowercase hexadecimal or does not match, the event ID is missing or longer than 255 bytes, the body is not valid JSON, or an event ID that Nozle already received arrives with a different body (`webhook_event_payload_conflict`).

| Event | What Nozle Does |
|-------|----------------|
| payment.authorized | Fetches the payment; waits for capture |
| payment.captured, order.paid, payment_link.paid | Fetches the payment and settles the invoice once it is captured |
| payment.failed | Fetches the payment; an interactive order stays open for retry |
| refund.processed, refund.failed | Updates the credit-note refund status |
| payment.dispute.lost, payment.dispute.closed | Applies a lost dispute; a closed or won dispute is not treated as lost |
| payment.dispute.created, payment.dispute.under_review, payment.dispute.action_required, payment.dispute.won | Sends you the `invoice.payment_dispute_updated` webhook; the invoice does not change |
| order.notification.delivered, order.notification.failed | Records the status of the pre-debit notice of an automatic debit; a failed notice fails the debit and the customer gets the Pay link |
| token.confirmed, token.rejected, token.cancelled, token.paused, token.resumed | Updates the UPI AutoPay mandate |

See the [Razorpay integration](/integrations/razorpay#webhook-setup) for setup and the checkout flow.
