Every component takes its look from `appearance`. Set it once on `BillingProvider` for all components inside, or on one component. No Tailwind or extra CSS is needed. Requires `@nozle-js/react` `0.11.0`.

You can also pick the look in the dashboard and save it for your organization: every component then uses it without any code. See [Saved appearance](#saved-appearance).

```tsx

>
```

## Saved appearance

Requires `@nozle-js/react` `0.13.0`.

In the dashboard, open **Developers > Customize SDK**, pick a theme, colours and plan card options, and select **Save changes**. Nozle saves the appearance for your organization, next to the plan card content. Every SDK component in your app picks it up automatically, with no code. The components read it from the plan catalog request they already make (`meta.sdk_appearance` in [`GET /api/v1/plans`](/api/list-plans)), with your publishable key.

The page has two tabs:

- **Global settings** are saved at the root of the SDK and apply to every component: theme, "Powered by Nozle", button, surface, text and status colours, and radius. The tab also shows the `BillingProvider` code to paste at the root of your app if you prefer to set the same appearance in code. It has no preview, because it is not tied to one component.
- **Component settings** change one component only. Pick a component in the **Component** dropdown to see it as it would look in your app, with live data from your organization where available and sample data otherwise. The panel lists only the settings that component reads (a usage meter has an accent colour but no buttons), and the plan card layout and the highlighted plan appear on the pricing table and plan card. A field left empty follows the global settings, and the placeholder shows the global value. A field you set is marked **Set here**. **Use global** removes the component's own settings.

**Save changes** saves the content, the global settings and the component settings together.

### What is saved

| Setting | Values |
|---|---|
| Theme | `light`, `dark`, `nozle`, `nozleDark`, `minimal`, `neobrutal` |
| Colours | `colorPrimary`, `colorPrimaryForeground`, `colorBackground`, `colorCard`, `colorForeground`, `colorMuted`, `colorMutedForeground`, `colorAccent`, `colorAccentForeground`, `colorBorder`, `colorDanger`, `colorWarning`, `colorSuccess`, `colorSecondary`, `colorInput`, `colorHighlight`, `colorHighlightForeground`, `buttonBorderColor`. Hex only: `#rgb` or `#rrggbb`. |
| Shape | `borderRadius`, `buttonRadius`, `borderWidth`, `buttonBorderWidth`. Lengths such as `12px` or `1rem`. |
| Plan cards | `planCardLayout` (`card` or `panel`), set per component |
| Pricing table | `highlightStyle` (`outline` or `filled`; the dashboard shows Outlined and Contained), `annualDiscountLabel` (up to 40 characters), `showToggle`, set per component |
| Branding | `hideBranding`, only for plans that remove the "Powered by Nozle" line |
| Components | `components.<Name>` with its own `theme`, `variables`, `planCardLayout` and `pricingTable`. Names: `PricingTable`, `PlanCard`, `PlanComparison`, `PlanBadge`, `CurrentPlan`, `PlanChangeControl`, `CancellationControl`, `UsageMeter`, `UsageDashboard`, `UsageAlert`, `UsageBreakdown`, `UsageTrend`, `CreditBalance`, `CreditHistory`, `PaymentMethodDisplay`, `CheckoutButton`, `UpgradeButton`, `UpgradeModal`, `UpgradePrompt`, `LockedOverlay` |

Fonts, shadows, `elements`, `enterpriseEmail` and any CSS are not saved. Set them in code. The saved object is at most 8 KB. Anything outside this list, or a value in the wrong format, is rejected with `422`.

### Precedence

From lowest to highest: the saved global appearance, the appearance saved for that component, `appearance` on `BillingProvider`, `appearance` on the component in code. A component rendered inside another, such as a `UsageMeter` in a `UsageDashboard`, uses its own saved settings. A theme set in code replaces the values that theme defines; saved values the code theme does not define stay.

For example, you saved the `nozle` theme and a `colorHighlight` of `#16a34a`. In code you set the `minimal` theme:

```tsx
<BillingProvider publishableKey="pk_..." appearance={{ theme: minimal }}>
```

The primary colour becomes `minimal`'s, and the highlight colour stays `#16a34a`, because `minimal` does not define it.

### Turn it off

```tsx
<BillingProvider publishableKey="pk_..." savedAppearance={false}>
```

With `savedAppearance={false}`, the components ignore the saved appearance and use only your code.

Without a saved appearance, nothing is applied, and `--nozle-*` CSS variables you set on `:root` keep working.

Components that only show data, such as `UsageMeter`, make one cached request for the plan catalog through the provider. A page with several components makes one request per `BillingProvider`.

```tsx
  highlightStyle="filled"

  appearance={{ variables: { colorHighlight: '#16a34a', colorHighlightForeground: '#ffffff' } }}
/>
```

## Plan card layout

A theme's `planCardLayout` picks how `PricingTable` and `PlanCard` lay out each plan:

- `card` (default): name, description, price and ticked features. See [Plan buttons](#plan-buttons) for which plan gets which button.
- `panel`: the name in a header band, with `ACTIVE` on the right for the current plan and the highlight label for the highlighted plan, then price, description and plain feature lines. `nozle` and `nozleDark` use it.

```tsx
appearance={{ theme: light, planCardLayout: 'panel' }}
```

The layout can be saved in the dashboard too: see [Saved appearance](#saved-appearance).

### Plan buttons

Requires `@nozle-js/react` `0.13.0`. Which button a plan gets depends on the customer's plan:

- **No current plan known:** every paid plan gets the primary button. In the `nozle`, `nozleDark` and `neobrutal` themes it has the hard shadow of the theme's button shadow; `light`, `dark` and `minimal` have none. The highlighted plan keeps its highlight colours.
- **With `currentPlanCode`:** plans above it get the primary button. The current plan uses the primary colour with no shadow (in the panel layout it also shows the `ACTIVE` label in the header). Plans at or below it get a plain button.
- **Contact-sales plans** stay outlined.

## Combine themes

`minimal` and `neobrutal` set shape; `light` and `dark` set colour. `nozle` and `nozleDark` set both, so use them on their own. Pass several themes in an array. Later ones win where they overlap.

```tsx
appearance={{ theme: [neobrutal, dark] }}
```

## One component

A component's own `appearance` goes on top of the provider's:

```tsx
import { CreditBalance } from '@nozle-js/react'

<BillingProvider publishableKey="pk_..." appearance={{ theme: dark }}>
  <PricingTable appearance={{ variables: { colorPrimary: '#16a34a' } }} />
  <CreditBalance balance={balance} />
</BillingProvider>
```

The order, highest first: the component's `variables`, the component's `theme`, the provider's `variables`, the provider's `theme`, the [saved appearance](#saved-appearance), `--nozle-*` CSS variables set by your app, then the light values.

## Text

All text in the components uses one of eight roles. Each role is a CSS `font` shorthand (weight, size, line height and family) plus a colour. Change a role and every element in it changes, in every component. Every component sets the body role on its root, so no text takes its size, font or colour from your page.

| Role | Variable | Default | Colour | What it styles | `nozle` and `nozleDark` |
|---|---|---|---|---|---|
| Title | `fontTitle` | `700 20px/1.25` | text | The billing portal title, dialog titles | `900 20px/1.15` |
| Heading | `fontHeading` | `600 16px/1.35` | text | Plan names, the `CurrentPlan` header and plan name, the credit balance name, portal section and card headings | `900 14px/1.25` |
| Metric | `fontMetric` | `700 28px/1.1`, numbers font, tabular figures | text | Plan prices, the credit balance, portal prices, balances and usage totals | `800 24px/1` in Nunito |
| Body | `fontBody` | `400 14px/1.5` | text | Features, table cells, meter labels and values, notices, errors and other sentences | `400 13px/1.5` |
| Secondary | `fontBody` | as body | muted | Descriptions, plan prices in `CurrentPlan`, card number, empty messages, the usage period | as body |
| Meta | `fontMeta` | `400 12px/1.4` | muted | Price intervals, "As of" dates, chart labels, card expiry, detail labels, the portal footer | `400 11.5px/1.4` |
| Label | `labelFont` | `600 12px/1.4` | muted | Table headers, plan card badges, status pills, `PlanBadge`, the portal status badge | `800 10.5px/1.4` JetBrains Mono, uppercase |
| Action | `fontAction` | `600 14px/1.4` | the button's colour | Buttons, links, the billing toggle | `800 14px/1.4` |

The defaults are in `fontFamily`; the metric default is in `fontFamilyNumbers` when it is set. `neobrutal` sets title and heading to weight `800`. The other themes keep the defaults. `labelTextTransform` and `labelLetterSpacing` apply with the label role.

```tsx
appearance={{
  variables: {
    fontHeading: '700 18px/1.3 Inter, sans-serif',
    fontMetric: '600 32px/1 Inter, sans-serif',
  },
}}
```

Muted text follows `colorForeground`: when `colorMutedForeground` is not set, it is `colorForeground` mixed 62% into `colorCard`, so a new text colour also recolours descriptions, dates, labels and table headers. Set `colorMutedForeground` to choose it yourself. Error, warning and success text is the status colour mixed with `colorForeground`, so it stays readable on its tinted background.

In code, any CSS value works, including `var(...)` and `oklch(...)`. The [saved appearance](#saved-appearance) takes hex colours and simple lengths only, and none of the font, shadow or `colorScheme` variables. Warning and error tints are mixed from `colorWarning` and `colorDanger`.

You can also set the CSS variables yourself, for example on `:root`. A component without `appearance` reads them. The older `--nozle-portal-*` and `--nozle-pricing-*` names still work after the `--nozle-*` name.

## Elements

`elements` changes one part of a component. A string adds a class name; an object adds inline styles. Every part also has a fixed class, `nozle-<key>`, for your own CSS.

```tsx
<PricingTable
  appearance={{
    elements: {
      planCard: 'rounded-none',
      planCard__cta: { textTransform: 'uppercase', letterSpacing: '0.04em' },
    },
  }}
/>
```

The components style themselves with inline styles, so a class name from `elements` cannot override a property they set. Use an object for those properties, or a variable.

## Stripe checkout

`Checkout` passes the theme's resolved colours, corner radius and font to Stripe's Payment Element, and picks Stripe's `night` theme on a dark card. Stripe's embedded Checkout page (a `cs_` client secret) uses the branding set in your Stripe dashboard instead.

## Upgrading from 0.10

- `@tanstack/react-query` 5 or later is a required peer dependency. Install it with `npm install @tanstack/react-query`.
- `PlanCard` takes a catalog `plan` with `isCurrent`, `returnUrl`, `onSelect` and an optional `features` list, instead of `id`, `name`, `monthlyPrice`, `annualPrice`, `description`, `isAnnual` and `children`. The `Plan` type export is removed.
- `PlanComparison` takes catalog `plans` and optional `features` rows keyed by plan `code`, not `id`.
- Components no longer read shadcn's `--primary` and `--border` on their own. To follow a shadcn/ui theme, pass its variables: `variables: { colorPrimary: 'var(--primary)', colorPrimaryForeground: 'var(--primary-foreground)', colorCard: 'var(--card)', colorForeground: 'var(--foreground)', colorBorder: 'var(--border)', borderRadius: 'var(--radius)' }` (Tailwind v3: wrap each in `hsl()`).
- Without a theme, the default primary is now `#4f46e5` everywhere; the portal's green is gone. Set `colorPrimary` to keep your colour.
- The `nozlePreset` Tailwind export is deprecated and does nothing for current components.
- `PricingTable` no longer treats a plan as "Custom" because its name contains "enterprise" or "custom". List those plan codes in `contactSalesPlans`.
