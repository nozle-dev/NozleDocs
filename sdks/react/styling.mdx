Every component takes its look from `appearance`. Set it once on `BillingProvider` for all components inside, or on one component. No Tailwind or extra CSS is needed. Requires `@nozle-js/react` `0.11.0`.

Every colour, the font, corner radius, border width and shadow can be changed on top of a theme with `variables` (full list below):

```tsx
<BillingProvider
  publishableKey="pk_..."
  appearance={{ theme: dark, variables: { colorPrimary: '#7c3aed', borderRadius: '8px' } }}
>
```

## Highlighted plan

`highlightPlan` on `PricingTable` marks one plan with a "Most Popular" badge. `highlightStyle` picks how the card stands out:

    </Frame>

    ```tsx
    <PricingTable highlightPlan="pro" />
    ```
  </Tab>
  <Tab title="Filled">
    The card takes the highlight colour, and its text and button switch to the highlight text colour.

    <Frame>
      <img src="/images/react/themes/light-filled.png" alt="The highlighted Pro card filled with the highlight colour" />
    </Frame>
    <Frame>
      <img src="/images/react/themes/dark-filled.png" alt="The filled highlight in the dark theme" />
    </Frame>

    ```tsx
    <PricingTable highlightPlan="pro" highlightStyle="filled" />
    ```
  </Tab>
</Tabs>

Set the colours with `colorHighlight` and `colorHighlightForeground`; they default to the primary colours. Change the badge text with `highlightLabel`, or pass `highlightLabel={null}` for no badge.

```tsx
<PricingTable
  highlightPlan="pro"
  highlightStyle="filled"
  highlightLabel="Best value"
  appearance={{ variables: { colorHighlight: '#16a34a', colorHighlightForeground: '#ffffff' } }}
/>
```

## Combine themes

`minimal` and `neobrutal` set shape; `light` and `dark` set colour. `nozle` and `nozleDark` set both, so use them on their own. Pass several themes in an array. Later ones win where they overlap.

```tsx
appearance={{ theme: [neobrutal, dark] }}
```

## One component

A component's own `appearance` goes on top of the provider's:

```tsx
<BillingProvider publishableKey="pk_..." appearance={{ theme: dark }}>
  <PricingTable appearance={{ variables: { colorPrimary: '#16a34a' } }} />
  <CreditBalance balance={balance} />
</BillingProvider>
```

The order, highest first: the component's `variables`, the component's `theme`, the provider's `variables`, the provider's `theme`, `--nozle-*` CSS variables set by your app, then the light values.

## Elements

`elements` changes one part of a component. A string adds a class name; an object adds inline styles. Every part also has a fixed class, `nozle-<key>`, for your own CSS.

```tsx
<PricingTable
  appearance={{
    elements: {
      planCard: 'rounded-none',
      planCard__cta: { textTransform: 'uppercase', letterSpacing: '0.04em' },
    },
  }}
/>
```

The components style themselves with inline styles, so a class name from `elements` cannot override a property they set. Use an object for those properties, or a variable.

| `PricingTable` | `pricingTable`, `pricingTable__toggle`, `pricingTable__toggleButton`, `pricingTable__grid`, and the `planCard` keys |

## Stripe checkout

`Checkout` passes the theme's resolved colours, corner radius and font to Stripe's Payment Element, and picks Stripe's `night` theme on a dark card. Stripe's embedded Checkout page (a `cs_` client secret) uses the branding set in your Stripe dashboard instead.

## Upgrading from 0.10

- Components no longer read shadcn's `--primary` and `--border` on their own. To follow a shadcn/ui theme, pass its variables: `variables: { colorPrimary: 'var(--primary)', colorPrimaryForeground: 'var(--primary-foreground)', colorCard: 'var(--card)', colorForeground: 'var(--foreground)', colorBorder: 'var(--border)', borderRadius: 'var(--radius)' }` (Tailwind v3: wrap each in `hsl()`).
- Without a theme, the default primary is now `#4f46e5` everywhere; the portal's green is gone. Set `colorPrimary` to keep your colour.
- The `nozlePreset` Tailwind export is deprecated and does nothing for current components.
- `PricingTable` no longer treats a plan as "Custom" because its name contains "enterprise" or "custom". List those plan codes in `contactSalesPlans`.
