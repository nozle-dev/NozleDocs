`Checkout` renders the payment step of a checkout your backend created: Stripe's form for a client secret, or a pay button for a checkout result.

**When to use**

- The step after [`CheckoutButton`](/sdks/react/components/checkout-button) or [`PricingTable`](/sdks/react/components/pricing-table) returns a Stripe client secret.
- A payment page that resumes a checkout your backend already created.
- A pay button for a Razorpay, hosted or processing checkout, with or without `BillingProvider`.

`Checkout` does not need `BillingProvider`.

## Usage

```tsx
import { Checkout, useCheckout, type CheckoutResult } from '@nozle-js/react'
```

Pass a Stripe client secret and your Stripe publishable key:

```tsx components/pay-step.tsx
import { Checkout } from '@nozle-js/react'

export function PayStep({ clientSecret }: { clientSecret: string }) {
  return (
    <Checkout
      clientSecret={clientSecret}
      publishableKey="pk_live_stripe..."
      returnUrl="https://app.example.com/settings/billing"
      onSuccess={(paymentIntentId) => console.log('paid', paymentIntentId)}
      onError={(error) => console.error(error.message)}
    />
  )
}
```

A `cs_` Checkout Session secret, which Nozle returns for plan and invoice checkout, mounts Stripe Embedded Checkout. Any other Stripe secret mounts Payment Element, themed from your `appearance`, with a loading placeholder and its own submit button.

<Warning>
Stripe webhooks decide whether the subscription is active. `onSuccess`, `onComplete` and the return page are interface signals; reload billing status before you show success.
</Warning>

## Data

`Checkout` takes either a Stripe client secret or a `checkout` result in the `CheckoutResult` shape that `createCheckout` returns:

```tsx
import { Checkout, type CheckoutResult } from '@nozle-js/react'

const result: CheckoutResult = {
  type: 'razorpay',
  checkout_id: 'chk_123',
  key_id: 'rzp_live_...',
  order_id: 'order_123',
  amount_cents: 2900,
  currency: 'INR',
}

export function ResumePayment() {
  return <Checkout checkout={result} submitLabel="Pay ₹29.00" />
}
```

See [checkout result types](/sdks/react/hooks#checkout-result-types).

### Live data

The client secret comes from `onStripeClientSecret` of [`CheckoutButton`](/sdks/react/components/checkout-button), [`PricingTable`](/sdks/react/components/pricing-table) or [`UpgradeButton`](/sdks/react/components/upgrade-button), or from `fetchClientSecret` of [`useCheckoutSession`](/sdks/react/hooks#usecheckoutsession). Your Stripe publishable key is your own; Nozle does not return it.

```tsx
import { useState } from 'react'
import { Checkout, CheckoutButton } from '@nozle-js/react'

export function BuyPro() {
  const [clientSecret, setClientSecret] = useState<string | null>(null)
  if (clientSecret) return <Checkout clientSecret={clientSecret} publishableKey="pk_live_stripe..." />
  return <CheckoutButton planCode="pro" onStripeClientSecret={setClientSecret} />
}
```

A `stripe` result passed as `checkout` is mounted with Stripe only when it carries a client secret and `publishable_key`. Nozle does not return `publishable_key`, so pass a Stripe client secret with `clientSecret` and `publishableKey` instead; a `stripe` result without them shows "Payment setup is incomplete. Contact support to continue."

## Examples

### Pay button for a checkout result

With `checkout`, the component renders a pay button that handles Razorpay, hosted, processing, completed and scheduled results. It reads `verifyCheckout` and `getCheckoutStatus` from its props first (React `0.10.0` and later), then from `BillingProvider`.

<Frame>
  <img src="/images/react/components/checkout/light.png" alt="Checkout pay button for a checkout result, labelled Pay $29.00, light theme" width="154" />
</Frame>

```tsx
import { Checkout, type CheckoutResult, type CheckoutStatus, type RazorpayVerification } from '@nozle-js/react'

const post = async (path: string, body: object): Promise<CheckoutStatus> => {
  const response = await fetch(path, { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify(body) })
  if (!response.ok) throw new Error(`Request failed: ${response.status}`)
  return response.json()
}

export function ResumePayment({ result }: { result: CheckoutResult }) {
  return (
    <Checkout
      checkout={result}
      submitLabel="Pay ₹29.00"
      verifyCheckout={(checkoutId: string, verification: RazorpayVerification) =>
        post('/api/billing/checkout/verify', { checkoutId, ...verification })
      }
      getCheckoutStatus={(checkoutId: string) => post('/api/billing/checkout/status', { checkoutId })}
      onComplete={() => console.log('done')}
      onDismiss={() => console.log('closed')}
    />
  )
}
```

### Your own pay button

To place your own pay button in the Payment Element form, pass it as `children` and call `useCheckout()` in it. `children` replaces the built-in submit button.

```tsx
import { Checkout, useCheckout } from '@nozle-js/react'

function PayButton() {
  const { confirmPayment, isProcessing, error } = useCheckout()
  return (
    <>
      <button type="button" onClick={() => void confirmPayment()} disabled={isProcessing}>
        {isProcessing ? 'Paying…' : 'Pay now'}
      </button>
      {error && <p role="alert">{error.message}</p>}
    </>
  )
}

export function CustomPay({ clientSecret }: { clientSecret: string }) {
  return (
    <Checkout clientSecret={clientSecret} publishableKey="pk_live_stripe...">
      <PayButton />
    </Checkout>
  )
}
```

## API reference

`Checkout` takes one of two sets of props.

### With a Stripe client secret

<ResponseField name="clientSecret" type="string" required>
  The Stripe client secret. A `cs_` Checkout Session secret mounts Embedded Checkout; any other secret mounts Payment Element.
</ResponseField>

<ResponseField name="publishableKey" type="string" required>
  Your Stripe publishable key.
</ResponseField>

<ResponseField name="stripeAccount" type="string">
  Stripe Connect account ID passed to Stripe.
</ResponseField>

<ResponseField name="returnUrl" type="string">
  Where Stripe returns the customer after a payment that needs a redirect (Payment Element). Defaults to the current URL.
</ResponseField>

<ResponseField name="submitLabel" type="string" default="Pay now">
  Text of the Payment Element submit button. It reads "Processing..." while the payment is confirmed.
</ResponseField>

<ResponseField name="onSuccess" type="(paymentIntentId: string) => void">
  Payment Element only. Fires when the PaymentIntent succeeds without a redirect and receives its ID.
</ResponseField>

<ResponseField name="onComplete" type="() => void">
  Embedded Checkout only. Fires when the session completes without a redirect. It does not fire when the session redirects to its return URL, which is how Nozle creates sessions.
</ResponseField>

<ResponseField name="onError" type="(error: Error) => void">
  Fires when the payment fails and receives Stripe's error, or "Payment could not be confirmed. Check its status before retrying." when confirming throws. The message also shows under the form.
</ResponseField>

<ResponseField name="onReady" type="() => void">
  Payment Element only. Fires when the form can be used; a loading placeholder shows until then.
</ResponseField>

<ResponseField name="children" type="ReactNode">
  Payment Element only. Replaces the submit button. Call `useCheckout()` inside it. Defaults to a submit button.
</ResponseField>

<ResponseField name="className" type="string">
  Class name on the root element.
</ResponseField>

<ResponseField name="style" type="CSSProperties">
  Inline styles on the root element.
</ResponseField>

<ResponseField name="appearance" type="Appearance">
  Theme for the wrapper, also mapped onto Payment Element: primary, background, text and danger colours, corner radius and font. A dark card colour picks Stripe's `night` theme. Embedded Checkout uses the branding of your Stripe account. Defaults to the provider's.
</ResponseField>

### With a checkout result

<ResponseField name="checkout" type="CheckoutResult" required>
  A result from `createCheckout` or from a checkout status call.
</ResponseField>

<ResponseField name="submitLabel" type="string" default="Pay now">
  Text of the pay button. It reads "Processing…" while it runs.
</ResponseField>

<ResponseField name="returnUrl" type="string">
  Passed on to Stripe when the result is mounted with Stripe. Defaults to the current URL.
</ResponseField>

<ResponseField name="verifyCheckout" type="(checkoutId, verification) => Promise<CheckoutStatus>">
  Checks a Razorpay payment on your backend. Required for Razorpay. Defaults to the provider's.
</ResponseField>

<ResponseField name="getCheckoutStatus" type="(checkoutId) => Promise<CheckoutStatus>">
  Reads the checkout status on your backend, polled up to 30 times, one second apart. Required for `processing` results. Defaults to the provider's.
</ResponseField>

<ResponseField name="onSuccess" type="(paymentId: string) => void">
  Fires when a Razorpay payment is captured and fulfilled and receives the payment ID; `onComplete` fires after it.
</ResponseField>

<ResponseField name="onComplete" type="() => void">
  Fires when the checkout completes, including `completed` and `scheduled` results.
</ResponseField>

<ResponseField name="onProcessing" type="(status: CheckoutStatus) => void">
  Fires while payment confirmation is pending and receives the status.
</ResponseField>

<ResponseField name="onDismiss" type="() => void">
  Fires when the customer closes Razorpay without paying.
</ResponseField>

<ResponseField name="onError" type="(error: Error) => void">
  Fires when the payment fails and receives the error. The message also shows under the button.
</ResponseField>

<ResponseField name="className" type="string">
  Class name on the root element.
</ResponseField>

<ResponseField name="appearance" type="Appearance">
  Theme, variables and element overrides. Defaults to the provider's. See [Appearance](/sdks/react/styling).
</ResponseField>

### `useCheckout`

Call `useCheckout()` only inside `children` of the Payment Element form; it throws outside `Checkout`. It is not [`useCheckoutSession`](/sdks/react/hooks#usecheckoutsession), which creates a checkout.

<ResponseField name="confirmPayment" type="() => Promise<void>">
  Confirms the payment.
</ResponseField>

<ResponseField name="isProcessing" type="boolean">
  `true` while the payment is confirmed.
</ResponseField>

<ResponseField name="error" type="Error | null">
  The last payment error.
</ResponseField>

### States

| State | What shows |
|---|---|
| Payment Element loading | A loading placeholder until the form can be used. |
| Confirming the payment | "Processing..." on the submit button, or "Processing…" on the pay button. |
| Waiting for payment confirmation | "Payment is processing. Confirmation may take a little while." |
| Payment failed | The error message under the form or button. |
| `stripe` result without client secret and `publishable_key` | "Payment setup is incomplete. Contact support to continue." |

On the free Nozle plan `Checkout` shows [Powered by Nozle](/sdks/react/components/powered-by-nozle) below the form, unless it is inside another component that already shows it.

### Appearance

<Accordion title="Element keys">
  `checkout` (root), `checkout__submit` (the submit or pay button), `checkout__error`.

  Style them with `appearance.elements`. See [Elements](/sdks/react/styling#elements).
</Accordion>
