`Checkout` renders the payment step of a checkout your backend created. Give it a Stripe client secret to mount Stripe's form, or a checkout result to get a pay button that opens Razorpay, redirects, or waits for confirmation.

## What Checkout supports

- A `cs_` Checkout Session secret, which Nozle returns for plan and invoice checkout, mounted with Stripe Embedded Checkout.
- Any other Stripe secret mounted with Payment Element, themed from your `appearance`, with a loading placeholder and its own submit button.
- A `checkout` result from `createCheckout`, rendered as a pay button that handles Razorpay, hosted, processing, completed and scheduled results.
- Razorpay verification and status recovery through callbacks, with or without `BillingProvider`.

## Where to use Checkout

- The step after [`CheckoutButton`](/sdks/react/components/checkout-button) or [`PricingTable`](/sdks/react/components/pricing-table) returns a Stripe client secret.
- A payment page that resumes a checkout your backend already created.

## Importing Checkout

```tsx
import { Checkout, useCheckout, type CheckoutResult } from '@nozle-js/react'
```

## Rendering Checkout

With a Stripe client secret and your Stripe publishable key:

```tsx
import { Checkout } from '@nozle-js/react'

export function PayStep({ clientSecret }: { clientSecret: string }) {
  return (
    <Checkout
      clientSecret={clientSecret}
      publishableKey="pk_live_stripe..."
      returnUrl="https://app.example.com/settings/billing"
      submitLabel="Pay and subscribe"
      onSuccess={(paymentIntentId) => console.log('paid', paymentIntentId)}
      onError={(error) => console.error(error.message)}
    />
  )
}
```

With a checkout result from your backend:

```tsx
import { Checkout, type CheckoutResult, type CheckoutStatus, type RazorpayVerification } from '@nozle-js/react'

const result: CheckoutResult = {
  type: 'razorpay',
  checkout_id: 'chk_123',
  key_id: 'rzp_live_...',
  order_id: 'order_123',
  amount_cents: 2900,
  currency: 'INR',
}

const post = async (path: string, body: object): Promise<CheckoutStatus> => {
  const response = await fetch(path, { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify(body) })
  if (!response.ok) throw new Error(`Request failed: ${response.status}`)
  return response.json()
}

export function ResumePayment() {
  return (
    <Checkout
      checkout={result}
      submitLabel="Pay ₹29.00"
      verifyCheckout={(checkoutId: string, verification: RazorpayVerification) =>
        post('/api/billing/checkout/verify', { checkoutId, ...verification })
      }
      getCheckoutStatus={(checkoutId: string) => post('/api/billing/checkout/status', { checkoutId })}
      onComplete={() => console.log('done')}
      onDismiss={() => console.log('closed')}
    />
  )
}
```

To place your own pay button in the Payment Element form, pass it as `children` and call `useCheckout()` in it. `children` replaces the built-in submit button.

```tsx
import { Checkout, useCheckout } from '@nozle-js/react'

function PayButton() {
  const { confirmPayment, isProcessing, error } = useCheckout()
  return (
    <>
      <button type="button" onClick={() => void confirmPayment()} disabled={isProcessing}>
        {isProcessing ? 'Paying…' : 'Pay now'}
      </button>
      {error && <p role="alert">{error.message}</p>}
    </>
  )
}

export function CustomPay({ clientSecret }: { clientSecret: string }) {
  return (
    <Checkout clientSecret={clientSecret} publishableKey="pk_live_stripe...">
      <PayButton />
    </Checkout>
  )
}
```

## Using live data

The client secret comes from `onStripeClientSecret` of [`CheckoutButton`](/sdks/react/components/checkout-button), [`PricingTable`](/sdks/react/components/pricing-table) or [`UpgradeButton`](/sdks/react/components/upgrade-button), or from `fetchClientSecret` of [`useCheckoutSession`](/sdks/react/hooks#usecheckoutsession). Your Stripe publishable key is your own; Nozle does not return it.

The `checkout` form reads `verifyCheckout` and `getCheckoutStatus` from its props first (React `0.10.0` and later), then from `BillingProvider`. A `stripe` result is mounted with Stripe only when it carries a client secret and `publishable_key`. Nozle does not return `publishable_key`, so pass a Stripe client secret with `clientSecret` and `publishableKey` instead; a `stripe` result without them shows "Payment setup is incomplete. Contact support to continue."

<Warning>
Stripe webhooks decide whether the subscription is active. `onSuccess`, `onComplete` and the return page are interface signals; reload billing status before you show success.
</Warning>

## Options

`Checkout` takes one of two sets of props.

### With a Stripe client secret

| Prop | Type | Default | What it does |
|---|---|---|---|
| `clientSecret` | `string` | required | The Stripe client secret. A `cs_` Checkout Session secret mounts Embedded Checkout; any other secret mounts Payment Element. |
| `publishableKey` | `string` | required | Your Stripe publishable key. |
| `stripeAccount` | `string` | none | Stripe Connect account ID passed to Stripe. |
| `returnUrl` | `string` | The current URL | Where Stripe returns the customer after a payment that needs a redirect (Payment Element). |
| `submitLabel` | `string` | `'Pay now'` | Text of the Payment Element submit button. It reads "Processing..." while the payment is confirmed. |
| `onSuccess` | `(paymentIntentId: string) => void` | none | Payment Element only. Called when the PaymentIntent succeeds without a redirect. |
| `onComplete` | `() => void` | none | Embedded Checkout only. Called when the session completes without a redirect. It does not fire when the session redirects to its return URL, which is how Nozle creates sessions. |
| `onError` | `(error: Error) => void` | none | Called with Stripe's error, or "Payment could not be confirmed. Check its status before retrying." when confirming throws. The message also shows under the form. |
| `onReady` | `() => void` | none | Payment Element only. Called when the form can be used; a loading placeholder shows until then. |
| `children` | `ReactNode` | A submit button | Payment Element only. Replaces the submit button. Call `useCheckout()` inside it. |
| `className` | `string` | none | Class name on the root element. |
| `style` | `CSSProperties` | none | Inline styles on the root element. |
| `appearance` | `Appearance` | The provider's | Theme for the wrapper, also mapped onto Payment Element: primary, background, text and danger colours, corner radius and font. A dark card colour picks Stripe's `night` theme. Embedded Checkout uses the branding of your Stripe account. |

### With a checkout result

| Prop | Type | Default | What it does |
|---|---|---|---|
| `checkout` | `CheckoutResult` | required | A result from `createCheckout` or from a checkout status call. |
| `submitLabel` | `string` | `'Pay now'` | Text of the pay button. It reads "Processing…" while it runs. |
| `returnUrl` | `string` | The current URL | Passed on to Stripe when the result is mounted with Stripe. |
| `verifyCheckout` | `(checkoutId, verification) => Promise<CheckoutStatus>` | The provider's | Checks a Razorpay payment on your backend. Required for Razorpay. |
| `getCheckoutStatus` | `(checkoutId) => Promise<CheckoutStatus>` | The provider's | Reads the checkout status on your backend, polled up to 30 times, one second apart. Required for `processing` results. |
| `onSuccess` | `(paymentId: string) => void` | none | Called with the payment ID when a Razorpay payment is captured and fulfilled; `onComplete` is called after it. |
| `onComplete` | `() => void` | none | Called when the checkout completes, including `completed` and `scheduled` results. |
| `onProcessing` | `(status: CheckoutStatus) => void` | none | Called while payment confirmation is pending. The form shows "Payment is processing. Confirmation may take a little while." |
| `onDismiss` | `() => void` | none | Called when the customer closes Razorpay without paying. |
| `onError` | `(error: Error) => void` | none | Called when the payment fails. The message also shows under the button. |
| `className` | `string` | none | Class name on the root element. |
| `appearance` | `Appearance` | The provider's | Theme, variables and element overrides. See [Appearance](/sdks/react/styling). |

### `useCheckout`

Call `useCheckout()` only inside `children` of the Payment Element form. It returns `confirmPayment()`, `isProcessing` and `error`, and throws outside `Checkout`. It is not [`useCheckoutSession`](/sdks/react/hooks#usecheckoutsession), which creates a checkout.

`Checkout` does not need `BillingProvider`. On the free Nozle plan it shows [Powered by Nozle](/sdks/react/components/powered-by-nozle) below the form, unless it is inside another component that already shows it.

### Appearance elements

`checkout` (root), `checkout__submit` (the submit or pay button), `checkout__error`.
