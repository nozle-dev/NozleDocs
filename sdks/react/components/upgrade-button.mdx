`UpgradeButton` opens an [`UpgradeModal`](/sdks/react/components/upgrade-modal) for one target plan and, when the customer confirms, starts the change through `createCheckout` on `BillingProvider`.

**When to use**

- Next to the current plan in billing settings ("Upgrade to Scale").
- In an [`UpgradePrompt`](/sdks/react/components/upgrade-prompt) or usage notice that names the next plan.
- A plan change that needs a confirmation step with the price difference.

For a full plan picker with exact quotes, use [`PlanChangeControl`](/sdks/react/components/plan-change-control).

## Usage

```tsx
import { UpgradeButton, type ProrationPreview } from '@nozle-js/react'
```

Render it inside a `BillingProvider` with `createCheckout` (see [Configure BillingProvider](/sdks/react/installation#configure-billingprovider)) and reload billing data when the change is done:

```tsx components/upgrade-to-scale.tsx
import { UpgradeButton, useBillingRefresh } from '@nozle-js/react'

export function UpgradeToScale({ onClientSecret }: { onClientSecret: (secret: string) => void }) {
  const refresh = useBillingRefresh()
  return (
    <UpgradeButton
      planCode="scale"
      label="Upgrade to Scale"
      subscriptionId="sub_123"
      onStripeClientSecret={onClientSecret}
      onUpgraded={() => void refresh()}
      onDowngradeScheduled={() => void refresh()}
      onError={(error) => console.error(error.message)}
    />
  )
}
```

### What a confirm does

The button calls `createCheckout` with the plan code, return URL and the `subscriptionId`, `quoteId` and `idempotencyKey` you pass, then handles every checkout result: Stripe client secret, Razorpay, hosted, processing, completed and scheduled. The dialog closes and:

- calls `onCheckoutStarted` after a Stripe client secret was handed to `onStripeClientSecret`,
- calls `onUpgraded` when the change completed, or a Razorpay payment was captured,
- calls `onDowngradeScheduled` for a `scheduled` result.

When the change fails, the dialog stays open and shows the message. See [checkout result types](/sdks/react/hooks#checkout-result-types).

## Data

`preview` holds the amounts shown in the dialog, in major units (dollars, not cents):

```tsx
import { UpgradeButton, type ProrationPreview } from '@nozle-js/react'

const preview: ProrationPreview = {
  credit: 14.5,
  debit: 49.5,
  net: 35,
  currency: 'USD',
  nextBillingDate: '2026-11-01T00:00:00Z',
}

export function UpgradeToScale() {
  return <UpgradeButton planCode="scale" label="Upgrade to Scale" preview={preview} />
}
```

### Live data

[`useUpgradePreview(planCode)`](/sdks/react/hooks#the-hooks) reads the quote for a plan change from your `billingEndpoint`. Its amounts are minor units and it has no separate credit and debit, so it does not fit `ProrationPreview`. Pass its `quote_id` as `quoteId`, and show its amounts in an [`UpgradeModal`](/sdks/react/components/upgrade-modal#live-data) you control, or use [`PlanChangeControl`](/sdks/react/components/plan-change-control), which shows the exact quote.

```tsx
import { UpgradeButton, useBillingRefresh, useSubscription, useUpgradePreview } from '@nozle-js/react'

export function UpgradeWithQuote() {
  const subscription = useSubscription()
  const quote = useUpgradePreview('scale')
  const refresh = useBillingRefresh()
  return (
    <UpgradeButton
      planCode="scale"
      subscriptionId={subscription.data?.subscription?.external_id}
      quoteId={quote.data?.quote_id}
      onUpgraded={() => void refresh()}
      onDowngradeScheduled={() => void refresh()}
    />
  )
}
```

## API reference

<ResponseField name="planCode" type="string" required>
  The plan to change to, sent to `createCheckout`.
</ResponseField>

<ResponseField name="label" type="string" default="Upgrade">
  Button text.
</ResponseField>

<ResponseField name="preview" type="ProrationPreview">
  Amounts shown in the dialog, in major units: `credit`, `debit`, `net`, `nextBillingDate` and optional `currency` (defaults to `USD`). See [`UpgradeModal`](/sdks/react/components/upgrade-modal#api-reference).
</ResponseField>

<ResponseField name="subscriptionId" type="string">
  The customer's external subscription ID, sent to `createCheckout` to change that subscription. Not sent when left out. `subscriptionId`, `quoteId` and `idempotencyKey` need React `0.10.0` or later.
</ResponseField>

<ResponseField name="quoteId" type="string">
  A server-issued quote the customer saw, sent to `createCheckout`. Not sent when left out.
</ResponseField>

<ResponseField name="idempotencyKey" type="string">
  Sent to `createCheckout`. Reuse the same key when retrying the same change. Not sent when left out.
</ResponseField>

<ResponseField name="returnUrl" type="string">
  Sent to `createCheckout`. Defaults to the current URL.
</ResponseField>

<ResponseField name="onStripeClientSecret" type="(clientSecret: string) => void">
  Fires for an embedded Stripe checkout and receives its client secret; render [`Checkout`](/sdks/react/components/checkout) with it. Without it the dialog closes and the secret is not used.
</ResponseField>

<ResponseField name="onCheckoutStarted" type="() => void">
  Fires after a Stripe client secret was handed over. The dialog closes.
</ResponseField>

<ResponseField name="onUpgraded" type="() => void">
  Fires when the change completed, or a Razorpay payment was captured. The dialog closes.
</ResponseField>

<ResponseField name="onDowngradeScheduled" type="() => void">
  Fires for a `scheduled` result. The dialog closes.
</ResponseField>

<ResponseField name="onError" type="(error: Error) => void">
  Fires when the change fails and receives the error. The dialog stays open and shows the message.
</ResponseField>

<ResponseField name="className" type="string">
  Class name on the button.
</ResponseField>

<ResponseField name="style" type="CSSProperties">
  Inline styles on the button.
</ResponseField>

<ResponseField name="appearance" type="Appearance">
  Used for the button and the dialog. Defaults to the provider's. See [Appearance](/sdks/react/styling).
</ResponseField>

### States

| State | What shows |
|---|---|
| Closed | The button. |
| Open | The confirmation dialog, with the `preview` amounts when set. |
| Confirming | "Checking subscription…" on the dialog's confirm button. |
| Change failed | The message in the dialog, which stays open. |
| No `createCheckout` on the provider | "BillingProvider createCheckout callback is required for checkout" in the dialog after confirm. |
