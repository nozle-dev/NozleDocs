`PaymentMethodDisplay` shows one saved payment method you pass and an "Update Payment Method" button.

**When to use**

- The payment section of your billing settings page.
- Next to a past-due notice, so the customer can fix the card.

## Importing PaymentMethodDisplay

```tsx
import {
  PaymentMethodDisplay,
  type PaymentMethod,
} from '@nozle-js/react'
```

## Rendering PaymentMethodDisplay

Inside a `BillingProvider` configured with `createManagePaymentMethod`, pass the card: the update button opens the hosted card page (React 0.24.0). To run your own flow instead, pass a handler for the update button:

```tsx components/saved-card.tsx
const card: PaymentMethod = { brand: 'visa', last4: '4242', expMonth: 8, expYear: 2029 }

export function SavedCard({ openUpdate }: { openUpdate: () => void }) {
  return <PaymentMethodDisplay paymentMethod={card} onUpdatePaymentMethod={openUpdate} />
}
```

The card shows the brand name, `•••• 4242` and `Expires 08/29`. `visa`, `mastercard`, `amex`, `discover`, `jcb`, `diners` and `unionpay` get readable names; another brand shows as sent.

## Data

The component does not read the card; you pass a `PaymentMethod` with `brand`, `last4`, `expMonth` and `expYear`.

### Live data

No Nozle hook returns the saved payment method. Read it on your backend from your payment provider for the signed-in customer, and pass it in:

```tsx
import { useEffect, useState } from 'react'

export function CardFromBackend() {
  const [card, setCard] = useState<PaymentMethod | undefined>()
  useEffect(() => {
    void fetch('/api/billing/payment-method')
      .then((response) => (response.ok ? response.json() : undefined))
      .then(setCard)
  }, [])
  return <PaymentMethodDisplay paymentMethod={card} updateHref="/settings/billing/card" />
}
```

## API reference

<ResponseField name="paymentMethod" type="PaymentMethod">
  `brand`, `last4`, `expMonth` and `expYear` of the card. Without it the component shows "No payment method on file."
</ResponseField>

<ResponseField name="onUpdatePaymentMethod" type="() => void">
  Fires when "Update Payment Method" is clicked, instead of the default card flow.
</ResponseField>

<ResponseField name="updateHref" type="string" default="/billing/update-payment">
  Without `onUpdatePaymentMethod` and outside a `BillingProvider` with `createManagePaymentMethod`, the button opens this URL in the same window.
</ResponseField>

<Note>
  From React 0.24.0 (_Unreleased_), the button opens the hosted card page by default. What a click does, in order:

  1. `onUpdatePaymentMethod`, when you pass it.
  2. Inside a `BillingProvider` with `createManagePaymentMethod`: `useManagePaymentMethod()` asks your backend for the card page ([Manage payment method](/api/manage-payment-method)) and opens it, returning to the current page. The button shows "Loading..." while the request runs, and the error message below it if the request fails.
  3. Otherwise: `updateHref`. The default `/billing/update-payment` is a path in your own app; if your app has no page there, the click only reloads your app.

  Before 0.24.0 only steps 1 and 3 exist: call `managePaymentMethod(window.location.href)` from `useManagePaymentMethod()` in `onUpdatePaymentMethod` to reach the card page.
</Note>

<ResponseField name="appearance" type="Appearance">
  Theme, variables and element overrides on top of the provider's. See [Appearance](/sdks/react/styling).
</ResponseField>

### States

| State | What shows |
|---|---|
| Card passed | Brand, `•••• <last4>`, `Expires MM/YY` and the update button. |
| No `paymentMethod` | "No payment method on file." and the update button. |
| Card page requested (0.24.0) | The button reads "Loading..." and is disabled. |
| Card page request failed (0.24.0) | The error message below the button. |
