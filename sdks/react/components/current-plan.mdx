`CurrentPlan` shows the customer's subscription in one card. It can read everything itself through your `billingEndpoint`, or render data you pass.

## What CurrentPlan supports

- Plan name, a status label, the price and interval, and "Changes to &lt;plan&gt; on &lt;date&gt;" for a scheduled change.
- "Ends &lt;date&gt;" for a subscription that is cancelled at the end of its period.
- A meter per metered limit of the plan, filled with this period's usage.
- A notice when a meter reaches `warningPercent`, and an alert when an invoice is overdue.
- Your own detail rows and header actions.
- Loading, error and empty states.

## Where to use CurrentPlan

- The top of your billing settings page.
- A dashboard card that links to plan changes or the billing portal.

## Importing CurrentPlan

```tsx
import { CurrentPlan, type BillingSubscription, type CurrentPlanDetail, type UsageDashboardFeature } from '@nozle-js/react'
```

## Rendering CurrentPlan

Pass `subscription` (the shape `useSubscription` returns) and `usage` to render your own data:

```tsx
import { CurrentPlan, type BillingSubscription, type CurrentPlanDetail, type UsageDashboardFeature } from '@nozle-js/react'

const subscription: BillingSubscription = {
  subscription: {
    external_id: 'sub_123',
    plan_code: 'pro',
    status: 'active',
    ending_at: null,
    plan: { code: 'pro', name: 'Pro', amount_cents: 2900, currency: 'USD', interval: 'monthly' },
  },
  pending_change: { plan_code: 'scale', name: 'Scale', effective_at: '2026-11-01T00:00:00Z' },
  past_due: false,
}

const usage: UsageDashboardFeature[] = [
  { key: 'api_calls', label: 'API calls', used: 41200, limit: 50000 },
  { key: 'seats', label: 'Seats', used: 6, limit: 10 },
]

const details: CurrentPlanDetail[] = [
  { label: 'Renews', value: 'Nov 1, 2026' },
  { label: 'AI credits included', value: '500 / month' },
]

export function PlanSummary() {
  return (
    <CurrentPlan
      subscription={subscription}
      usage={usage}
      details={details}
      actions={<a href="/settings/billing/portal">Manage billing</a>}
    />
  )
}
```

## Using live data

Leave `subscription` out and, inside a `BillingProvider` with `billingEndpoint`, `CurrentPlan` reads the data itself:

- the subscription with [`useSubscription`](/sdks/react/hooks#the-hooks),
- the plan's metered limits from the public catalog with `usePlans`,
- this period's units with `useUsage`, joined to the limits by feature code.

Serve `billingEndpoint` with `createBillingHandler` from `@nozle-js/node`; see [Serve the hooks from your backend](/sdks/react/hooks#serve-the-hooks-from-your-backend).

```tsx
import { BillingProvider, CurrentPlan } from '@nozle-js/react'

export function BillingSettings() {
  return (
    <BillingProvider publishableKey="pk_live_..." billingEndpoint="/api/nozle">
      <CurrentPlan actions={<a href="/settings/billing/portal">Manage billing</a>} />
    </BillingProvider>
  )
}
```

To build the meters from your own data, `currentPlanMeters(entitlements, usage)` joins a plan's metered entitlements with a period's `charges_usage` and returns `usage` rows:

```tsx
import { CurrentPlan, currentPlanMeters, usePlans, useSubscription, useUsage, type CustomerUsageData } from '@nozle-js/react'

export function PlanWithMeters() {
  const subscription = useSubscription()
  const { plans } = usePlans()
  const usage = useUsage()
  // `useUsage()` reads the current period; its type also covers the past-periods form.
  const current = (usage.data ?? null) as CustomerUsageData | null
  const plan = plans.find((entry) => entry.code === subscription.data?.subscription?.plan_code)
  return (
    <CurrentPlan
      subscription={subscription.data ?? null}
      usage={currentPlanMeters(plan?.entitlements, current)}
      isLoading={subscription.isPending}
      error={subscription.error}
    />
  )
}
```

<Note>
Without `subscription`, `CurrentPlan` needs `BillingProvider` with `billingEndpoint`, or it throws "Billing hooks need BillingProvider billingEndpoint, a backend route served by createBillingHandler".
</Note>

## Options

| Prop | Type | Default | What it does |
|---|---|---|---|
| `subscription` | `BillingSubscription` or `null` | Read through `billingEndpoint` | The subscription, plan, `ending_at`, scheduled change and `past_due`. `null` shows the empty message. |
| `usage` | `UsageDashboardFeature[]` | The plan's metered limits joined with this period's units | One meter per row: `{ key, label, used, limit }`. `limit: null` shows "Unlimited". Each meter is labelled "&lt;label&gt; used this period". |
| `details` | `CurrentPlanDetail[]` | none | Extra `{ label, value }` rows under the meters, for example a renewal date. `value` can be any React node. |
| `actions` | `ReactNode` | none | Shown on the right of the header, for example a link to the billing portal. |
| `warningPercent` | `number` or `null` | `80` | A meter at or above this percentage shows "You have used N% of the &lt;label&gt; included in &lt;plan&gt;." `null` turns these notices off. |
| `pastDueMessage` | `string` | `'A payment is overdue. Pay the open invoice to keep your plan active.'` | Shown as an alert when `past_due` is true. |
| `title` | `string` | `'Current plan'` | The header text. |
| `emptyMessage` | `string` | `'No active plan.'` | Shown when there is no subscription. |
| `isLoading` | `boolean` | `false` | Shows a loading placeholder. |
| `error` | `Error`, `string` or `null` | `null` | Shows the message as an alert. |
| `locale` | `string` | `'en-US'` | Formats the dates. |
| `appearance` | `Appearance` | The provider's | Theme, variables and element overrides. See [Appearance](/sdks/react/styling). |

### Status label

| Subscription | Label | Colour |
|---|---|---|
| `active`, no `ending_at` | Active | Success |
| `ending_at` set | Ends &lt;date&gt; | Warning |
| `pending` | Pending | Warning |
| `incomplete` | Awaiting payment | Warning |
| `canceled` | Canceled | Muted |
| `terminated` | Ended | Muted |

Another status is shown as sent. On the free Nozle plan the card shows [Powered by Nozle](/sdks/react/components/powered-by-nozle).

### Appearance elements

`currentPlan` (root), `currentPlan__name`, `currentPlan__status`, `currentPlan__price`, `currentPlan__scheduled`, `currentPlan__notice`, `currentPlan__usage`, `currentPlan__details`. The meters take the [`UsageMeter`](/sdks/react/components/usage-meter) elements.
