`UsageDashboard` shows several [`UsageMeter`](/sdks/react/components/usage-meter)s in one card, one per feature.

## What UsageDashboard supports

- One labelled meter per feature, with the meter's colour thresholds.
- Unlimited features.
- A skeleton while loading, an error message, and a message when there is nothing to show.
- `usageItems` to build the rows from your plan's entitlements and your usage results.

## Where to use UsageDashboard

- A "Usage" tab in your billing or account settings.
- A dashboard card that shows the customer's limits.

## Importing UsageDashboard

```tsx
import { UsageDashboard, usageItems, type UsageDashboardFeature, type UsageResult } from '@nozle-js/react'
```

## Rendering UsageDashboard

```tsx
import { UsageDashboard, type UsageDashboardFeature } from '@nozle-js/react'

const features: UsageDashboardFeature[] = [
  { key: 'api_calls', label: 'API calls', used: 31200, limit: 50000 },
  { key: 'seats', label: 'Seats', used: 9, limit: 10 },
  { key: 'storage', label: 'Storage (GB)', used: 98, limit: 100 },
  { key: 'projects', label: 'Projects', used: 12, limit: null },
]

export function Usage() {
  return <UsageDashboard features={features} />
}
```

## Using live data

`usageItems(entitlements, results)` joins a plan's metered entitlements from the catalog (for the names) with usage results keyed by feature code, the `used` and `limit` of a `can()` result. Entitlements that are not metered, or have no result, are left out.

```tsx
import { UsageDashboard, useEntitlement, usePlans, usageItems, useSubscription, type UsageResult } from '@nozle-js/react'

export function LiveUsage() {
  const subscription = useSubscription()
  const { plans } = usePlans()
  const apiCalls = useEntitlement('api_calls')
  const seats = useEntitlement('seats')

  const plan = plans.find((entry) => entry.code === subscription.data?.subscription?.plan_code)
  const results: Record<string, UsageResult | undefined> = {
    api_calls: apiCalls.data && { used: apiCalls.data.used ?? 0, limit: apiCalls.data.limit },
    seats: seats.data && { used: seats.data.used ?? 0, limit: seats.data.limit },
  }
  return (
    <UsageDashboard
      features={usageItems(plan?.entitlements ?? [], results)}
      loading={subscription.isPending || apiCalls.isPending || seats.isPending}
      error={subscription.error ?? apiCalls.error ?? seats.error}
    />
  )
}
```

`currentPlanMeters(entitlements, usage)` builds the same rows from this period's `charges_usage` instead; see [`CurrentPlan`](/sdks/react/components/current-plan#using-live-data).

## Options

| Prop | Type | Default | What it does |
|---|---|---|---|
| `features` | `UsageDashboardFeature[]` | `[]` | The rows: `{ key, label, used, limit? }`. `limit` `null` or missing means unlimited. |
| `loading` | `boolean` | `false` | Shows three skeleton rows. |
| `error` | `Error`, `string` or `null` | `null` | Shows the message in a `role="alert"` card instead of the rows. |
| `emptyMessage` | `string` | `'No usage to show yet.'` | Shown when `features` is empty. |
| `appearance` | `Appearance` | The provider's | Theme, variables and element overrides, also passed to each meter. See [Appearance](/sdks/react/styling). |

### Appearance elements

`usageDashboard` (the card), and the [`UsageMeter`](/sdks/react/components/usage-meter#appearance-elements) elements for each row.
