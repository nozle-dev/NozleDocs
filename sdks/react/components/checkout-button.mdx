`CheckoutButton` starts checkout for one plan through `BillingProvider` and opens Razorpay, redirects, hands you a Stripe client secret, or reports a completed or scheduled change.

**When to use**

- A plan card or marketing section that sells one plan.
- An onboarding step that subscribes the new customer.
- Anywhere you need checkout without the full [`PricingTable`](/sdks/react/components/pricing-table).

## Usage

```tsx
import {
  BillingProvider,
  CheckoutButton,
  type CompletedCheckoutResult,
  type CreateCheckout,
  type ScheduledCheckoutResult,
} from '@nozle-js/react'
```

`CheckoutButton` must be inside a `BillingProvider` with `createCheckout`. Your merchant route creates the checkout with your secret key; see [Implement the merchant endpoint](/sdks/react/installation#implement-the-merchant-endpoint).

```tsx app/pricing/buy-pro.tsx
'use client'
import { BillingProvider, CheckoutButton, type CreateCheckout } from '@nozle-js/react'

const createCheckout: CreateCheckout = async (input) => {
  const response = await fetch('/api/billing/checkout', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(input),
  })
  if (!response.ok) throw new Error('Checkout could not be started')
  return response.json()
}

export function BuyPro() {
  return (
    <BillingProvider publishableKey="pk_live_..." createCheckout={createCheckout}>
      <CheckoutButton planCode="pro" label="Get Pro" returnUrl="https://app.example.com/settings/billing" />
    </BillingProvider>
  )
}
```

The button needs no customer data. It reads `createCheckout`, `verifyCheckout` and `getCheckoutStatus` from `BillingProvider`.

### What a click does

1. The button calls `createCheckout({ idempotencyKey, planCode, returnUrl, registerMandate? })`. It keeps one idempotency key per plan and reuses it when the customer clicks again, so a retry reopens the same pending checkout. A second click while the first is running does nothing.
2. For a `razorpay` result it loads Razorpay and opens it. A captured payment is checked with `verifyCheckout`, then polled with `getCheckoutStatus` up to 30 times, one second apart. A failed payment shows "Payment failed. You can retry checkout."
3. For a `processing` result it polls the same way and continues with the checkout it returns.
4. For a `hosted` result, or a result with a `url`, it redirects the page.
5. For a `stripe` result it passes the client secret to `onStripeClientSecret`.
6. For a `completed` or `scheduled` result it calls `onComplete` or `onScheduled`.

After a completed or scheduled result, reload the customer's billing data, for example with `useBillingRefresh()` from the [hooks](/sdks/react/hooks). See [checkout result types](/sdks/react/hooks#checkout-result-types).

## Examples

### Embedded Stripe checkout and results

Pass `onStripeClientSecret` and render [`Checkout`](/sdks/react/components/checkout) with the secret. `onComplete` and `onScheduled` report changes that need no payment step.

```tsx
import { useState } from 'react'
import {
  Checkout,
  CheckoutButton,
  type CompletedCheckoutResult,
  type ScheduledCheckoutResult,
} from '@nozle-js/react'

export function BuyPro() {
  const [clientSecret, setClientSecret] = useState<string | null>(null)
  const [message, setMessage] = useState('')

  if (clientSecret) return <Checkout clientSecret={clientSecret} publishableKey="pk_live_stripe..." />
  return (
    <>
      <CheckoutButton
        planCode="pro"
        label="Get Pro"
        onStripeClientSecret={setClientSecret}
        onComplete={(result: CompletedCheckoutResult) => setMessage(`Subscribed: ${result.status}`)}
        onScheduled={(result: ScheduledCheckoutResult) => setMessage(`Change scheduled for ${result.effective_at}`)}
        onError={(error) => setMessage(error.message)}
      />
      {message && <p>{message}</p>}
    </>
  )
}
```

### Razorpay

For Razorpay, give the provider `verifyCheckout` and `getCheckoutStatus`. Each calls your backend, which scopes the request to the signed-in customer.

```tsx
import { BillingProvider, CheckoutButton, type CheckoutStatus, type CreateCheckout, type RazorpayVerification } from '@nozle-js/react'

const post = async <T,>(path: string, body: object): Promise<T> => {
  const response = await fetch(path, { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify(body) })
  if (!response.ok) throw new Error(`Request failed: ${response.status}`)
  return response.json()
}

const createCheckout: CreateCheckout = (input) => post('/api/billing/checkout', input)
const verifyCheckout = (checkoutId: string, verification: RazorpayVerification) =>
  post<CheckoutStatus>('/api/billing/checkout/verify', { checkoutId, ...verification })
const getCheckoutStatus = (checkoutId: string) => post<CheckoutStatus>('/api/billing/checkout/status', { checkoutId })

export function RazorpayBuy() {
  return (
    <BillingProvider
      publishableKey="pk_live_..."
      createCheckout={createCheckout}
      verifyCheckout={verifyCheckout}
      getCheckoutStatus={getCheckoutStatus}
    >
      <CheckoutButton planCode="pro" registerMandate onSuccess={(paymentId) => console.log('paid', paymentId)} />
    </BillingProvider>
  )
}
```

## API reference

<ResponseField name="planCode" type="string" required>
  The plan to check out, sent to `createCheckout`.
</ResponseField>

<ResponseField name="label" type="string" default="Get Started">
  Button text. While checkout starts, the button reads "Loading..." and is disabled.
</ResponseField>

<ResponseField name="returnUrl" type="string">
  Sent to `createCheckout`, where the provider returns the customer after payment. Defaults to the current URL.
</ResponseField>

<ResponseField name="registerMandate" type="boolean">
  Sent to `createCheckout` when set, to ask for a recurring payment mandate. Not sent when left out.
</ResponseField>

<ResponseField name="onStripeClientSecret" type="(clientSecret: string) => void">
  Fires for an embedded Stripe checkout and receives its client secret; render [`Checkout`](/sdks/react/components/checkout) with it. Without it, a Stripe result fails with "onStripeClientSecret is required for embedded Stripe checkout".
</ResponseField>

<ResponseField name="onComplete" type="(result: CompletedCheckoutResult) => void">
  Fires for a `completed` result and receives it: the change took effect without a payment step, or a resumed checkout succeeded.
</ResponseField>

<ResponseField name="onScheduled" type="(result: ScheduledCheckoutResult) => void">
  Fires for a `scheduled` result, such as a downgrade at renewal, and receives it.
</ResponseField>

<ResponseField name="onSuccess" type="(paymentId: string) => void">
  Razorpay only. Fires when the payment is captured and the plan is fulfilled, and receives the Razorpay payment ID.
</ResponseField>

<ResponseField name="onProcessing" type="(status: CheckoutStatus) => void">
  Fires with each status while the button waits for a payment to be confirmed, and receives that status.
</ResponseField>

<ResponseField name="onDismiss" type="() => void">
  Razorpay only. Fires when the customer closes the Razorpay window without paying.
</ResponseField>

<ResponseField name="onError" type="(error: Error) => void">
  Fires when checkout fails and receives the error. The message also shows next to the button in a `role="alert"` element.
</ResponseField>

<ResponseField name="razorpayKeyId" type="string">
  Deprecated and not used. The Razorpay key comes from the checkout result.
</ResponseField>

<ResponseField name="className" type="string">
  Class name on the button.
</ResponseField>

<ResponseField name="style" type="CSSProperties">
  Inline styles on the button, on top of the theme's.
</ResponseField>

<ResponseField name="appearance" type="Appearance">
  Theme, variables and element overrides. Defaults to the provider's. See [Appearance](/sdks/react/styling).
</ResponseField>

### States

| State | What shows |
|---|---|
| Starting checkout | "Loading..." on a disabled button. |
| Waiting for payment confirmation | "Payment is processing. Confirmation may take a little while." |
| Checkout failed | The error message next to the button in a `role="alert"` element. |
| No `createCheckout` on the provider | "BillingProvider createCheckout callback is required for checkout". |
| Outside a `BillingProvider` | The button throws. |
