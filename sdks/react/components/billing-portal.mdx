`BillingPortal` renders a full customer billing page inside your app, read from Nozle with a short-lived, customer-scoped session that your backend issues.

**When to use**

- A "Billing" page in your app's settings.
- A link from [`CurrentPlan`](/sdks/react/components/current-plan) ("Manage billing").
- Self-service for subscriptions, wallets, billing information and invoices in one place.

You do not need a `BillingProvider` or Tailwind for it.

## Usage

```tsx
import {
  BillingPortal,
  BillingPortalError,
  type BillingPortalSession,
  type CreateBillingPortalSession,
} from '@nozle-js/react'
```

`createSession` asks your backend for a portal session:

```tsx app/settings/billing/page.tsx
'use client'
import { BillingPortal, type BillingPortalSession, type CreateBillingPortalSession } from '@nozle-js/react'

const createSession: CreateBillingPortalSession = async ({ signal }) => {
  const response = await fetch('/api/billing/session', {
    method: 'POST',
    credentials: 'same-origin',
    signal,
  })
  if (!response.ok) throw new Error(`Billing session failed: ${response.status}`)
  const session: BillingPortalSession = await response.json() // { token, apiUrl }
  return session
}

export default function CustomerBilling() {
  return (
    <BillingPortal
      createSession={createSession}
      locale="en-US"
      onError={(error) => console.warn(error.code)}
    />
  )
}
```

Any rejection of `createSession` shows as a `session` error. Keep `createSession` stable across renders: a new function starts a new session. Change `key` when the signed-in account changes.

### What the portal shows

- Subscriptions with status, price, current period and usage details.
- Wallets with their balance and a top-up form.
- Billing information with an edit form.
- Invoice history with search, pages and PDF downloads.

## Data

`createSession` returns a `BillingPortalSession`: `{ token, apiUrl }`. The portal reads everything else itself.

### Live data

Your backend issues the session. It reads the customer's portal URL from Core (`GET /api/v1/customers/{external_id}/portal_url`) with your secret key, takes the token from it, and returns `{ token, apiUrl }`. The portal then reads subscriptions, usage, wallets and invoices from Core's customer-portal GraphQL with that token. [Billing portal and self-service](/sdks/react/billing-portal#issue-the-portal-session) shows the backend step and the plan-change and cancellation adapters.

## Examples

### Plan changes and cancellation

With `planChangeActions` and `cancellationActions`, each subscription shows [`PlanChangeControl`](/sdks/react/components/plan-change-control) and [`CancellationControl`](/sdks/react/components/cancellation-control).

<Frame>
  <img src="/images/react/components/billing-portal/light.png" alt="BillingPortal with a Pro subscription, a prepaid credits wallet, billing information and two paid invoices, light theme" width="1008" />

```tsx
import { BillingPortal, type CancellationActions, type CreateBillingPortalSession, type PlanChangeActions } from '@nozle-js/react'

export function FullPortal(props: {
  accountId: string
  createSession: CreateBillingPortalSession
  cancellationActions: CancellationActions
  planChangeActions: PlanChangeActions
}) {
  return (
    <BillingPortal
      key={props.accountId}
      createSession={props.createSession}
      cancellationActions={props.cancellationActions}
      planChangeActions={props.planChangeActions}
    />
  )
}
```

## API reference

<ResponseField name="createSession" type="({ signal }: { signal: AbortSignal }) => Promise<BillingPortalSession>" required>
  Fires on mount, on "Reconnect" and on "Refresh portal", and receives an `AbortSignal`. Returns `{ token, apiUrl? }`. `apiUrl` is the Core base URL without `/graphql` and defaults to `https://api.nozle.app/core`. The token stays in memory.
</ResponseField>

<ResponseField name="planChangeActions" type="PlanChangeActions">
  Shows [`PlanChangeControl`](/sdks/react/components/plan-change-control) on each subscription. Without it there are no plan changes.
</ResponseField>

<ResponseField name="cancellationActions" type="CancellationActions">
  Shows [`CancellationControl`](/sdks/react/components/cancellation-control) on each subscription. Without it there is no Cancel or Keep.
</ResponseField>

<ResponseField name="locale" type="string" default="en-US">
  Formats amounts and dates. The text is English.
</ResponseField>

<ResponseField name="onError" type="(error: BillingPortalError) => void">
  Fires when a request fails and receives a `BillingPortalError` whose `code` is `session`, `unauthorized`, `request` or `changed`. The message never contains the token or response details.
</ResponseField>

<ResponseField name="className" type="string" default="">
  Class names on the root, after `nozle-billing-portal`.
</ResponseField>

<ResponseField name="style" type="CSSProperties">
  Inline styles on the root.
</ResponseField>

<ResponseField name="nonce" type="string">
  CSP nonce for the portal's `<style>` elements.
</ResponseField>

<ResponseField name="appearance" type="Appearance">
  Theme, variables and element overrides on top of the provider's, also applied to the controls and dialogs inside. The older `--nozle-portal-*` variables still work. See [Appearance](/sdks/react/styling).
</ResponseField>

### States

| State | What shows |
|---|---|
| Starting | "Starting billing session…", then "Loading billing data…". |
| Session failed or took over 20 seconds | "Could not start your billing session. Please try again." with "Try again". |
| Session expired | "Your billing session has expired. Reconnect to continue." with "Reconnect". |
| A request failed | "Could not complete this billing request. Please try again." with "Try again". |

The portal shows [Powered by Nozle](/sdks/react/components/powered-by-nozle) when the session's organization is on the free Nozle plan.
