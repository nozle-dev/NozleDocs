`UpgradeModal` is the confirmation dialog behind [`UpgradeButton`](/sdks/react/components/upgrade-button), for when your page owns the open state or confirms a billing action with your own `onSubmit`.

**When to use**

- A plan change confirmation opened from your own button or menu.
- A confirm step that shows a quote you read with `useUpgradePreview`.
- Any confirm-then-call flow on a billing page, without `BillingProvider`, through `onSubmit`.

## Importing UpgradeModal

```tsx
import { UpgradeModal, type ProrationPreview } from '@nozle-js/react'
```

## Rendering UpgradeModal

Keep the open state yourself and close the dialog in its callbacks. Without `onSubmit`, confirm calls `createCheckout` on `BillingProvider`:

```tsx components/upgrade-flow.tsx
import { useState } from 'react'

export function UpgradeFlow() {
  const [open, setOpen] = useState(false)
  const close = () => setOpen(false)
  return (
    <>
      <button type="button" onClick={() => setOpen(true)}>Upgrade to Scale</button>
      <UpgradeModal
        isOpen={open}
        planCode="scale"
        onCancel={close}
        onCheckoutStarted={close}
        onCompleted={close}
        onScheduled={close}
      />
    </>
  )
}
```

The dialog moves focus in on open and back on close, traps focus, and closes on Escape. It shows a busy state, an error message, and your own title and labels.

### What a confirm does

With `onSubmit`, confirm runs your action. Without it, confirm calls `createCheckout` with the plan code, return URL and the `subscriptionId`, `quoteId` and `idempotencyKey` you pass, then handles the result:

- a hosted Stripe result fires `onCheckoutStarted` just before it redirects the browser to the Stripe-hosted page,
- a completed change or a captured Razorpay payment fires `onCompleted`,
- a `scheduled` result fires `onScheduled`,
- a `processing` result shows "Payment is processing. Confirmation may take a little while." in the dialog.

`onConfirm` fires after confirm finished without an error, by either path. See [checkout result types](/sdks/react/hooks#checkout-result-types).

## Data

`preview` holds the amounts in major units (dollars, not cents), with separate credit and debit:

```tsx
const preview: ProrationPreview = {
  credit: 14.5,
  debit: 49.5,
  net: 35,
  currency: 'USD',
  nextBillingDate: '2026-11-01T00:00:00Z',
}

export function UpgradeDialog({ open, close }: { open: boolean; close: () => void }) {
  return <UpgradeModal isOpen={open} planCode="scale" preview={preview} onCancel={close} onCompleted={close} />
}
```

### Live data

The quote from [`useUpgradePreview`](/sdks/react/hooks#the-hooks) is in minor units, so show it as `children` and pass its `quote_id`:

```tsx
import { useSubscription, useUpgradePreview } from '@nozle-js/react'

function money(minor: number | string, currency: string) {
  const format = new Intl.NumberFormat('en-US', { style: 'currency', currency })
  const digits = format.resolvedOptions().maximumFractionDigits ?? 2
  return format.format(Number(minor) / 10 ** digits)
}

export function QuotedUpgrade({ open, close }: { open: boolean; close: () => void }) {
  const subscription = useSubscription()
  const quote = useUpgradePreview(open ? 'scale' : undefined)
  return (
    <UpgradeModal
      isOpen={open}
      planCode="scale"
      subscriptionId={subscription.data?.subscription?.external_id}
      quoteId={quote.data?.quote_id}
      confirmDisabled={!quote.data}
      onCancel={close}
      onCompleted={close}
      onScheduled={close}
    >
      {quote.data && (
        <p>
          Due now: {money(quote.data.amount_due_now_cents, quote.data.currency)}. Effective{' '}
          {new Date(quote.data.effective_at).toLocaleDateString('en-US')}.
        </p>
      )}
    </UpgradeModal>
  )
}
```

### Your own submit action

With `onSubmit`, the dialog runs your action instead of `createCheckout` and needs no `BillingProvider`.

```tsx
export function ConfirmSeats({ open, close }: { open: boolean; close: () => void }) {
  return (
    <UpgradeModal
      isOpen={open}
      planCode="team"
      title="Add 5 seats?"
      confirmLabel="Add seats"
      onSubmit={async () => {
        const response = await fetch('/api/billing/seats', { method: 'POST', body: JSON.stringify({ add: 5 }) })
        if (!response.ok) throw new Error('Seats could not be added')
      }}
      onConfirm={close}
      onCancel={close}
    >
      <p>Your next invoice includes 5 more seats.</p>
    </UpgradeModal>
  )
}
```

### Back button

`onBack` shows a Back button on the left of the actions, for a step that has a previous step.

```tsx
export function ConfirmStep({ open, back, close }: { open: boolean; back: () => void; close: () => void }) {
  return <UpgradeModal isOpen={open} planCode="scale" onBack={back} onCancel={close} onCompleted={close} />
}
```

## API reference

<ResponseField name="isOpen" type="boolean" required>
  Shows the dialog. When `false` nothing renders.
</ResponseField>

<ResponseField name="planCode" type="string" required>
  The plan sent to `createCheckout`.
</ResponseField>

<ResponseField name="onCancel" type="() => void">
  Fires when the Close button is clicked or Escape is pressed (not while busy). Close the dialog here.
</ResponseField>

<ResponseField name="title" type="string" default="Confirm plan change">
  The dialog title.
</ResponseField>

<ResponseField name="confirmLabel" type="string" default="Confirm">
  Text of the confirm button. While busy it reads "Checking subscription…".
</ResponseField>

<ResponseField name="confirmDisabled" type="boolean" default={false}>
  Disables the confirm button.
</ResponseField>

<ResponseField name="busy" type="boolean" default={false}>
  Marks the dialog busy from outside: buttons disabled, Escape ignored.
</ResponseField>

<ResponseField name="preview" type="ProrationPreview">
  Amounts in major units: `credit` (shown as "Credits applied" only when above 0), `debit` ("New plan charge"), `net` ("Due today"), `nextBillingDate` (an ISO date) and `currency` (defaults to `USD`).
</ResponseField>

<ResponseField name="children" type="ReactNode">
  Content below the amounts.
</ResponseField>

<ResponseField name="locale" type="string">
  Formats the amounts and the next billing date. Without it the amounts use `en-US` and the date uses the browser's locale.
</ResponseField>

<ResponseField name="onSubmit" type="() => Promise<void>">
  From React `0.10.0`. Your action for the confirm button. When set, `createCheckout` is not called and `BillingProvider` is not needed. A rejection shows its message.
</ResponseField>

<ResponseField name="subscriptionId" type="string">
  Sent to `createCheckout`. Not sent when left out.
</ResponseField>

<ResponseField name="quoteId" type="string">
  Sent to `createCheckout`. Not sent when left out.
</ResponseField>

<ResponseField name="idempotencyKey" type="string">
  Sent to `createCheckout`. Not sent when left out.
</ResponseField>

<ResponseField name="returnUrl" type="string">
  Sent to `createCheckout`. Defaults to the current URL.
</ResponseField>

<ResponseField name="onCheckoutStarted" type="() => void">
  Fires just before the browser is sent to the Stripe-hosted page.
</ResponseField>

<ResponseField name="onCompleted" type="() => void">
  Fires when the change completed, or a Razorpay payment was captured.
</ResponseField>

<ResponseField name="onScheduled" type="() => void">
  Fires for a `scheduled` result.
</ResponseField>

<ResponseField name="onConfirm" type="() => void">
  Fires after confirm finished without an error, by either path.
</ResponseField>

<ResponseField name="onBack" type="() => void">
  Shows a Back button on the left of the actions and fires when it is clicked.
</ResponseField>

<ResponseField name="onError" type="(error: Error) => void">
  Fires when confirm fails and receives the error. The dialog shows the message.
</ResponseField>

<ResponseField name="nonce" type="string">
  CSP nonce for the dialog's `<style>` element.
</ResponseField>

<ResponseField name="appearance" type="Appearance">
  Theme, variables and element overrides. Defaults to the provider's. See [Appearance](/sdks/react/styling).
</ResponseField>

### States

| State | What shows |
|---|---|
| Closed (`isOpen={false}`) | Nothing. |
| Confirming, or `busy` | Buttons disabled, "Checking subscription…" on the confirm button, Escape ignored. |
| Payment processing | "Payment is processing. Confirmation may take a little while." |
| Confirm failed | The error message in the dialog. |
| No `onSubmit` and no `createCheckout` on the provider | "BillingProvider createCheckout callback is required for checkout". |

The dialog shows [Powered by Nozle](/sdks/react/components/powered-by-nozle), unless it is inside another component that already shows it.
