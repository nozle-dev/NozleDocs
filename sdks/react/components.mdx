The React SDK separates public catalog and checkout orchestration from customer state:

- `PricingTable` may load the public catalog with a publishable key.
- Catalog checkout components call your `BillingProvider.createCheckout` callback; the portal uses authenticated management adapters.
- Gates, usage widgets, badges, and payment-method UI consume caller-supplied state.

## Subscription self-service

| Component | Purpose |
| --- | --- |
| `BillingPortal` | Customer-scoped overview with optional Cancel/Keep and plan-change adapters. |
| `CancellationControl` | Standalone end-of-period cancellation and Keep confirmation. |
| `PlanChangeControl` | Standalone plan selection, signed quote review, paid checkout, scheduled downgrade and exact withdrawal. |

These exports are available in React `0.10.2`. See [Billing portal and self-service](/sdks/react/billing-portal) for setup, props, callback contracts, standalone examples and installation instructions. The portal does not require `BillingProvider` or Tailwind.

## Pricing components

![React SDK pricing table](/images/react-sdk/pricing-table.png)

### `PricingTable`

Renders responsive plan cards, an optional monthly/annual toggle, current-plan state, highlighted plans, and checkout actions. Each card lists what the plan gives, built from the catalog: entitlements, credit grants and flat per-unit usage prices.

```tsx
import { PricingTable } from '@nozle-js/react'

<PricingTable
  currentPlanCode="free_monthly"
  highlightPlan="pro_monthly"
  returnUrl="https://app.example.com/settings/billing"
  contactSalesPlans={['enterprise']}
  enterpriseEmail="sales@example.com"
  onStripeClientSecret={setClientSecret}
  onCheckoutError={setError}
/>
```

When `plans` is omitted, `PricingTable` reads `GET /api/v1/plans` through `BillingProvider` itself. Supplying `plans` makes the component fully caller-driven and allows it to render outside a provider when `onSelect` is also supplied. With neither `plans` nor a provider, it shows `BillingProvider with a publishableKey is required to load plans`.

<Warning>
If its own catalog request fails, `PricingTable` renders `Plans could not be loaded: <reason>` (`HTTP <status>` or the thrown message) in a `role="alert"` message, from React `0.10.2`. Earlier versions rendered an empty grid and left an unhandled promise rejection. `onCheckoutError` does not receive catalog failures. To render your own message, load plans with `usePlans`, use its `error`, and pass `plans` to `PricingTable`.
</Warning>

`PricingTable` passes only `planCode` and `returnUrl` to `createCheckout`, with no idempotency key. Only `CheckoutButton` sends an idempotency key.

| Prop | Type | Default | Description |
|---|---|---|---|
| `currentPlanCode` | `string` | — | Plan displayed as current and disabled. |
| `plans` | `PricingPlan[]` | Public catalog | Caller-supplied plan list. |
| `features` | `string[][]` or `Record<string, string[]>` | Read from each plan | Optional. Replaces the generated lines of a plan: an array aligned to the rendered plan order, or an object keyed by plan code. |
| `sort` | `(a, b) => number` | Cheapest first | Optional. Orders the plans. |
| `onSelect` | `(plan) => void` | Provider checkout | Overrides built-in checkout selection. |
| `returnUrl` | `string` | Current URL | Return URL sent to `createCheckout`. |
| `onStripeClientSecret` | `(secret) => void` | — | Receives embedded Stripe checkout secrets. |
| `onCheckoutResult` | `(result) => void` | — | Receives every raw checkout result. |
| `onCheckoutError` | `(error) => void` | — | Receives checkout errors. Catalog load failures are not passed to it. |
| `showToggle` | `boolean` | `true` | Shows monthly/annual filtering when yearly plans exist. |
| `highlightPlan` | `string` | — | Plan code marked “Most Popular.” |
| `highlightStyle` | `'outline'` or `'filled'` | `'outline'` | `filled` paints the highlighted card in `colorHighlight`. See [Appearance](/sdks/react/styling#highlighted-plan). |
| `highlightLabel` | `string` or `null` | `Most Popular` | Badge text; `null` hides the badge. |
| `className` | `string` | — | Class applied to the root container. |
| `contactSalesPlans` | `string[]` | — | Codes of plans sold on request. Their card shows "Custom" and a "Contact Sales" button. From React `0.11.0`; earlier versions guessed these plans from their names. |
| `enterpriseEmail` | `string` | — | Opens a prefilled mail link from the "Contact Sales" button. |
| `appearance` | `Appearance` | Provider's | Theme, variables and elements. See [Appearance](/sdks/react/styling). |

**Plan order.** The catalog returns plans newest first. `PricingTable` sorts them by base price, cheapest first, and puts `contactSalesPlans` last. Plans in different currencies stay grouped in the order each currency first appears, and plans with the same price keep the catalog order. Pass `sort` for another order; `sortPlansByPrice(plans)` returns the default.

`PricingPlan` contains `code`, `name`, `amount_cents`, `amount_currency`, `interval`, and optional `description`, `entitlements`, `credit_grant_rules` and `charges`. The three optional arrays are what the public catalog returns; see the [public plan catalog](/api/list-plans).

The generated feature list has one line per item, in this order:

| Source | Line |
|---|---|
| Metered entitlement with a `usage_limit` | `100,000 API calls` |
| Metered entitlement without a limit, and boolean entitlements | The entitlement name |
| `config` entitlement | `Support: priority` (one line per privilege value) |
| Credit grant rule | `500 ai credits every month`, `10 credits (one time)` |
| `standard` usage charge | `$0.01 per api calls` |
| `graduated`, `volume` and `graduated_percentage` charges | One line per range, for example `0 to 1,000 emails: free` and `1,001+ emails: $0.01 each` |
| `package` charge | `$5.00 per 100 sms, first 50 free` |
| `percentage` charge | `2.9% of each payment + $0.30 per payment` |

Leave `features` out and the table can only show what the plan gives. A `custom` or `dynamic` charge produces no line, so pass `features` for a plan that needs one. Call `planFeatures(plan)` to get the same lines for your own layout.

### `PlanCard`

Use `PlanCard` when you already have a custom pricing layout and want an individual card. It takes a plan from the catalog and reads the price, currency, interval and feature lines from it.

```tsx
<PlanCard
  plan={plans.find((plan) => plan.code === 'growth')!}
  isCurrent={currentPlan === 'growth'}
  returnUrl="https://app.example.com/settings/billing"
  onSelect={({ planCode, returnUrl }) => startCheckout(planCode, returnUrl)}
/>
```

| Prop | Type | Description |
|---|---|---|
| `plan` | `PricingPlan` | A plan from the public catalog. |
| `isCurrent` | `boolean` | Shows the card as the current plan and disables its button. |
| `features` | `string[]` | Optional. Replaces the lines read from the plan. |
| `returnUrl` | `string` | Return URL sent to the checkout callback. Defaults to the current URL. |
| `onSelect` | `(input) => void` | Called with `planCode` and `returnUrl`. The button is not rendered without it. |

### `PlanComparison`

Renders a side-by-side table of the plans you pass, cheapest first (pass `sort` for another order). Each row is an entitlement or a granted credit system, in the order the plans return them, and a plan that does not have it shows a cross.

```tsx
<PlanComparison plans={plans} />
```

Each cell shows `✓` for an included entitlement, the limit for a metered entitlement that has one, the value of a `config` entitlement, or the credit grant. Pass `features` to replace the rows:

```tsx
<PlanComparison
  plans={plans}
  features={[
    {
      key: 'projects',
      label: 'Projects',
      values: { free: '3', growth: 'Unlimited', scale: 'Unlimited' },
    },
  ]}
/>
```

`values` is keyed by plan `code`. Call `comparisonRows(plans)` for the generated rows.

## Checkout components

### `CheckoutButton`

Starts checkout through `BillingProvider.createCheckout` with an idempotency key and handles Stripe client-secret, Razorpay, hosted, processing, completed, and scheduled results. See [checkout result types](/sdks/react/hooks#checkout-result-types).

```tsx
<CheckoutButton
  planCode="pro_monthly"
  returnUrl="https://app.example.com/settings/billing"
  label="Choose Pro"
  onStripeClientSecret={setClientSecret}
  onComplete={() => refreshBillingStatus()}
  onScheduled={() => refreshBillingStatus()}
  onError={setError}
/>
```

| Prop | Type | Default | Description |
|---|---|---|---|
| `planCode` | `string` | required | Plan passed to `createCheckout`. |
| `returnUrl` | `string` | Current URL | Validated merchant return URL. |
| `label` | `string` | `Get Started` | Button label. |
| `className` / `style` | React styling props | — | Button styling overrides. |
| `razorpayKeyId` | `string` | — | Deprecated override; use the public key returned in the scoped checkout result. |
| `onStripeClientSecret` | `(secret) => void` | — | Required for embedded Stripe results. |
| `onSuccess` | `(paymentId) => void` | — | Razorpay success callback. |
| `onComplete` | `(result) => void` | — | Immediate completed-result callback. |
| `onScheduled` | `(result) => void` | — | Scheduled-change callback. |
| `registerMandate` | `boolean` | — | Passed to `createCheckout` when set. |
| `onProcessing` | `(status) => void` | — | Fires while the button polls a `processing` checkout. |
| `onDismiss` | `() => void` | — | Razorpay only. Fires when the Razorpay modal is dismissed. |
| `onError` | `(error) => void` | — | Checkout failure callback. |

Each click calls `createCheckout` again, with the same idempotency key for the same plan. For a new subscription whose first payment is still pending, the second call reopens the same checkout, so the "Payment failed. You can retry checkout." button of the Razorpay flow recovers it. See [Create checkout](/api/create-checkout#retry-a-new-subscription-checkout).

### `Checkout`

Renders Stripe checkout for a client secret returned by your merchant backend. Nozle returns an embedded Checkout Session secret (`cs_`), which `Checkout` mounts with Stripe Embedded Checkout. Any other secret is mounted with Payment Element. The provider-result form also handles Razorpay, hosted checkout and processing/recovery results.

```tsx
<Checkout
  clientSecret={clientSecret}
  publishableKey={import.meta.env.VITE_STRIPE_PUBLISHABLE_KEY}
  returnUrl="https://app.example.com/settings/billing"
  submitLabel="Pay and subscribe"
  onSuccess={(paymentIntentId) => console.log(paymentIntentId)}
  onComplete={() => refreshBillingStatus()}
  onError={setError}
/>
```

| Prop | Type | Default | Description |
|---|---|---|---|
| `clientSecret` | `string` | required | Stripe client secret. A `cs_` Checkout Session secret uses Embedded Checkout; any other secret uses Payment Element. |
| `publishableKey` | `string` | required | Stripe publishable key. |
| `stripeAccount` | `string` | — | Connected account ID. |
| `returnUrl` | `string` | Current URL fallback | Stripe redirect URL. |
| `submitLabel` | `string` | `Pay now` | Submit button label. |
| `onSuccess` | `(paymentIntentId) => void` | — | Successful PaymentIntent callback (Payment Element only). |
| `onComplete` | `() => void` | — | Embedded Checkout Session completion callback. It does not fire when the session redirects to `returnUrl`, which is how Nozle creates sessions: show success from your return page or by reading billing status. |
| `onError` | `(error) => void` | — | Stripe or validation failure. |
| `onReady` | `() => void` | — | Payment Element ready callback (Payment Element only). |
| `className` / `style` | React styling props | — | Root styling. |
| `children` | `ReactNode` | — | Additional content above the submit button (Payment Element only). |

For a provider checkout result, use the alternative `checkout` prop. Supply merchant callbacks for verification and status recovery; your backend scopes both to the authenticated customer and selected subscription:

```tsx
<Checkout
  checkout={checkoutResult}
  verifyCheckout={verifySelectedCheckout}
  getCheckoutStatus={getSelectedCheckoutStatus}
  returnUrl="https://app.example.com/settings/billing"
  onComplete={refreshBillingStatus}
  onError={setError}
/>
```

React `0.10.0` and later support these callbacks directly on `Checkout`, without requiring `BillingProvider`; see [the complete adapter](/sdks/react/billing-portal).

The `useCheckout` export from this component must be called inside the component's Stripe Elements context. It returns `confirmPayment`, `isProcessing`, and `error`. Do not confuse it with `useCheckoutSession`, which creates checkout through your merchant callback.

<Warning>
Stripe webhook processing is authoritative. `onSuccess`, `onComplete`, and return-page navigation are user-interface signals, not proof that a subscription is active.
</Warning>

## Plan-change components

![React SDK billing components](/images/react-sdk/billing-components.png)

### `UpgradeButton`

Opens `UpgradeModal` and starts a plan change through the provider callback.

```tsx
<UpgradeButton
  planCode="scale_monthly"
  label="Upgrade to Scale"
  preview={{
    credit: 12.5,
    debit: 49,
    net: 36.5,
    nextBillingDate: '2026-09-01T00:00:00Z',
  }}
  onStripeClientSecret={setClientSecret}
  onUpgraded={refreshBillingStatus}
  onDowngradeScheduled={refreshBillingStatus}
/>
```

The component also accepts `returnUrl`, `className`, `style`, `onCheckoutStarted`, and `onError`. React `0.10.0` adds `subscriptionId`, `quoteId`, and `idempotencyKey`, forwarded to the merchant checkout callback.

### `UpgradeModal`

Use the modal directly when your application owns its open state.

```tsx
<UpgradeModal
  isOpen={upgradeOpen}
  planCode="scale_monthly"
  preview={preview}
  onCancel={() => setUpgradeOpen(false)}
  onCompleted={refreshBillingStatus}
  onScheduled={refreshBillingStatus}
  onStripeClientSecret={setClientSecret}
/>
```

`preview` is caller-supplied and contains `credit`, `debit`, `net`, and `nextBillingDate`. Those legacy amount fields use **major units**. React `0.10.0` adds `currency` (default `USD`) and locale-aware formatting. Do not pass SDK minor-unit quote fields directly into this legacy shape; `PlanChangeControl` renders the exact minor-unit quote instead.

React `0.10.0` also adds `onSubmit` for an authenticated custom action without `BillingProvider`, plus `title`, `confirmLabel`, `confirmDisabled`, `busy`, `children`, `locale`, and stylesheet `nonce`. For provider-backed submission it accepts `subscriptionId`, `quoteId`, and `idempotencyKey`. The modal itself does not fetch a customer quote.

## Billing display components

### `CurrentPlan`

The customer's plan at a glance: name, status, price, a scheduled change, usage against the plan's limits, a notice when a limit is close, and an alert when a payment is overdue.

<Frame>
  <img src="/images/react/current-plan.png" alt="CurrentPlan showing the Pro plan, a scheduled change, two usage meters and a near-limit notice" />
</Frame>

Inside a `BillingProvider` with `billingEndpoint`, it reads everything itself: the subscription (`useSubscription`), the plan's metered limits from the catalog, and this period's usage (`useUsage`).

```tsx
<CurrentPlan actions={<a href="/billing">Manage billing</a>} />
```

To render it from your own data, pass `subscription` (the `useSubscription` shape) and, optionally, `usage`.

```tsx
<CurrentPlan
  subscription={subscription}
  usage={[{ key: 'events', label: 'Events', used: 41200, limit: 50000 }]}
  details={[{ label: 'Renews', value: 'Nov 1, 2026' }]}
/>
```

| Prop | Type | Default | Description |
|---|---|---|---|
| `subscription` | `BillingSubscription` or `null` | Read through `billingEndpoint` | The plan, status, end date and scheduled change. |
| `usage` | `{ key, label, used, limit }[]` | Plan limits joined with this period's units | Meters. `limit: null` shows "Unlimited". |
| `details` | `{ label, value }[]` | none | Extra rows, for example a renewal date. |
| `actions` | `ReactNode` | none | Shown in the header, for example a link to your billing portal. |
| `warningPercent` | `number` or `null` | `80` | A meter at or above it shows a notice; `null` turns notices off. |
| `pastDueMessage` | `string` | `A payment is overdue. Pay the open invoice to keep your plan active.` | Shown when `subscription.past_due` is true. |
| `title`, `emptyMessage`, `locale` | `string` | `Current plan`, `No active plan.`, `en-US` | Text and date format. |
| `isLoading`, `error` | | | Loading and error states when you pass the data. |

Element keys for `appearance`: `currentPlan`, `currentPlan__name`, `currentPlan__status`, `currentPlan__price`, `currentPlan__scheduled`, `currentPlan__notice`, `currentPlan__usage`, `currentPlan__details`.

### `PlanBadge`

```tsx
<PlanBadge plan="Free" tier="free" />
<PlanBadge plan="Starter" tier="starter" />
<PlanBadge plan="Pro" tier="pro" />
<PlanBadge plan="Enterprise" tier="enterprise" />
```

`tier` controls presentation and accepts `free`, `starter`, `pro`, or `enterprise`.

### `PaymentMethodDisplay`

```tsx
<PaymentMethodDisplay
  paymentMethod={{
    brand: 'visa',
    last4: '4242',
    expMonth: 12,
    expYear: 2028,
  }}
  onUpdatePaymentMethod={() => openPaymentMethodFlow()}
/>
```

Without `onUpdatePaymentMethod`, the update button navigates to `updateHref`, which defaults to `/billing/update-payment`. Omit `paymentMethod` to show the empty state.

## Usage components

![React SDK usage components](/images/react-sdk/usage-components.png)

### `UsageMeter`

```tsx
<UsageMeter used={8_200} limit={10_000} label="API requests" />
```

| Prop | Type | Default | Description |
|---|---|---|---|
| `used` | `number` | required | Current usage. |
| `limit` | `number` or `null` | — | Usage limit. Without one the text reads `Unlimited` and the bar stays empty. |
| `label` | `string` | — | Label above the bar. |
| `showText` | `boolean` | `true` | Shows the numeric used/limit text when a label exists. |

The fill uses the primary color below 80%, warning from 80–94%, and destructive at 95% or above. `getUsageMeterColor(percentage)` exposes the same threshold selection.

### `UsageDashboard`

```tsx
<UsageDashboard
  features={[
    { key: 'requests', label: 'API requests', used: 8_200, limit: 10_000 },
    { key: 'storage', label: 'Storage', used: 42, limit: 100 },
  ]}
/>
```

To take the labels from the plan, join the plan's metered entitlements (from the [public catalog](/api/list-plans)) with the usage results you read on your backend, keyed by feature code. A result needs `used` and optionally `limit`, the fields of a `can()` result.

```tsx
import { UsageDashboard, usageItems } from '@nozle-js/react'

<UsageDashboard features={usageItems(plan.entitlements ?? [], resultsByFeatureCode)} />
```

Entitlements that are not metered, or have no result, are left out. A feature without a `limit` shows as unlimited.

| Prop | Type | Default | Description |
|---|---|---|---|
| `features` | `{ key, label, used, limit? }[]` | `[]` | Rows to show. |
| `loading` | `boolean` | `false` | Renders three skeleton rows. |
| `error` | `Error \| string \| null` | `null` | Shows the message as an alert instead of the rows. |
| `emptyMessage` | `string` | `No usage to show yet.` | Shown when there are no rows. |

### `UsageBreakdown` and `UsageTrend`

Both render the usage your backend reads from Core and pass in. Neither fetches anything and neither holds a key. Read it on your backend with a secret key:

- `GET https://api.nozle.app/core/api/v1/customers/{external_customer_id}/current_usage` returns `customer_usage` for the current period. Pass it to `UsageBreakdown`.
- `GET https://api.nozle.app/core/api/v1/customers/{external_customer_id}/past_usage` returns `usage_periods`, one item per past period. Pass them to `UsageTrend`. The endpoint takes `periods_count` and `feature_code`.

Both endpoints take `external_subscription_id` when the customer has more than one subscription. Both are in the Customers section of the API reference.

```tsx
import { UsageBreakdown, UsageTrend } from '@nozle-js/react'

<UsageBreakdown usage={currentUsage.customer_usage} />
<UsageTrend periods={pastUsage.usage_periods} />
<UsageTrend periods={pastUsage.usage_periods} featureCode="emails" />
```

| Component | Shows | Props |
|---|---|---|
| `UsageBreakdown` | One period: each feature's name, units and amount, largest amount first, and the total. | `usage`, `isLoading`, `error`, `emptyMessage` |
| `UsageTrend` | One bar per period, oldest first: the period amount, or the units of `featureCode` (zero where a period has none). | `periods`, `featureCode`, `isLoading`, `error`, `emptyMessage` |

Each has a loading placeholder, an error message and an empty message. A charge's `invoice_display_name` is used as the row name when it is set; otherwise the feature name.

### `UsageAlert`

```tsx
<UsageAlert
  threshold={80}
  upgradeHref="/settings/billing"
  features={[
    { key: 'requests', label: 'API requests', percentage: 82 },
    { key: 'exports', label: 'Data exports', percentage: 96 },
  ]}
/>
```

The component renders one dismissible warning for each feature at or above `threshold`. The default threshold is `80` and the default upgrade link is `/plans`.

## Credit components

Both components render data you read on your backend with the SDK; neither fetches anything and neither holds a key. Each shows a loading state, an error message and an empty message.

### `CreditBalance`

Renders one credit balance: the available credits with the unit name, the time of the reading, and the sources the credits come from (plan grant, top-up, granted, adjustment, allocated top-up) with what remains and when it expires. Sources with nothing left are hidden.

```tsx
import { CreditBalance } from '@nozle-js/react'

// `balance` is one entry of the SDK's `credits.balance` result
<CreditBalance balance={balance} isLoading={isLoading} error={error} />
```

| Prop | Type | Description |
|---|---|---|
| `balance` | `CreditBalanceData` or `null` | `credit_system_name`, `unit_name`, `available`, `as_of` and optional `sources`. `null` shows the empty message. |
| `isLoading` | `boolean` | Shows a loading placeholder. |
| `error` | `Error` or `string` | Shows the message as an alert. |
| `emptyMessage` | `string` | Defaults to `No credit balance yet.` |

### `CreditHistory`

Renders credit operations as a table: when, type (used, granted, adjustment, expired, revoked, refunded, transfer), feature, credits and status.

```tsx
<CreditHistory
  operations={page.operations}
  hasMore={page.next_cursor !== null}
  onLoadMore={() => loadNextPage(page.next_cursor)}
  isLoading={isLoading}
  error={error}
/>
```

| Prop | Type | Description |
|---|---|---|
| `operations` | `CreditOperationData[]` | `id`, `type`, `status`, `credit_amount`, `feature_code` and `occurred_at` of each operation. |
| `hasMore`, `onLoadMore` | `boolean`, `() => void` | Show a `Load more` button. Fetch the next page with the SDK's `next_cursor`. |
| `isLoading` | `boolean` | Shows a placeholder, or disables the button while a page loads. |
| `error` | `Error` or `string` | Shows the message as an alert. |
| `emptyMessage` | `string` | Defaults to `No credit activity yet.` |
