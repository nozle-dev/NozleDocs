```go
import nozle "github.com/nozle-dev/nozle-go"

client := nozle.New("") // reads NOZLE_SECRET_KEY

result, err := client.Can(ctx, "workspace_123", "agent_execution")
if err == nil && result.Allowed {
  // Run the permitted operation.
}
```

`Can` reads Engine `/api/v1/can`; `CanWithMetadata` also sends JSON metadata for the cost and margin estimate. For credit-backed features, `CheckUsage` provides an advisory projection and `TrackUsage` enforces and records the deduction atomically.

## Metadata

```go
result, err := client.CanWithMetadata(ctx, "workspace_123", "model_access", map[string]any{
  "model": "example-large-model", "region": "us-east",
})
_ = result
_ = err
```

Metadata can include quantities required by a Cost Rule. It is input to the cost and margin estimate only. It does not filter usage: `Used`, `Limit` and `Remaining` always cover all of the feature's usage, whatever `model` or other properties you send.

## Choose the subscription

A customer with several active subscriptions needs a selector, as in `nozle-go` v0.16.0 and later. `CanWithOptions` takes `CanOptions` with `Metadata`, `SubscriptionID` and `EntityID` (external IDs); `CanWithMetadata` calls it with only `Metadata`:

```go
result, err := client.CanWithOptions(ctx, "workspace_123", "seats", nozle.CanOptions{
  SubscriptionID: "sub_team_a",
})
_ = result
_ = err
```

Without a selector, `Can` evaluates the customer's only subscription. When the customer has several and not exactly one is its own, the answer is not an error: `Can` returns `Allowed == false` with `Reason` `subscription_required`. Send `SubscriptionID` or `EntityID` to choose. See [The can() endpoint](/guides/entitlements/can-endpoint#which-subscription-is-checked).

## `CanResult`

| Field | Meaning |
|---|---|
| `Allowed`, `Reason` | Access decision and reason. |
| `Used`, `Overage` | Usage so far, and whether a soft limit is reached. `Overage` never denies by itself: the usage is billed as overage. Deny only on `Allowed == false`. |
| `Limit`, `Remaining` | `*int`. `nil` when the feature is unlimited (the API sends `null`), never `0`: a `0` allowance means none left. Check `Limit != nil` before reading either. |
| `Economics` | Optional point-in-time estimate with exact `nozle.Decimal` values, Cost Rule versions, and exclusions. |
| `Policy` | `*CanPolicy`, v0.29.0. The margin policy version that decided the call, with its `Decision` and `Reason`. `nil` when no policy covers the feature. See [Margin policy](#margin-policy). |
| `Budget` | `*Budget`, v0.27.0 with Engine 2.34.0. The spend limit that refused the call (`Reason` `budget_exceeded`), else the tightest one covering the feature. `nil` when none applies. |

Check immediately before protected server work. React gates are not an authorization boundary. `Can` does not reserve product credits.

## Margin policy

From v0.29.0. When a [margin policy](/guides/margin/overview) covers the feature, `Can` returns `Policy`, a `*nozle.CanPolicy`: the policy version that decided the call. It is `nil` when no policy applies. Fields are `VersionID`, `Mode`, `OnUnavailable`, `MinimumMarginAmount`, `MinimumMarginPercent` and `MaximumEstimatedCost` (`nozle.Decimal`, empty when not set), `MaximumSnapshotAgeSeconds`, `Decision` and `Reason`. Before v0.29.0, `Policy` was raw JSON.

| Field | Meaning |
|---|---|
| `Mode` | What the policy does when the call is below its thresholds: `allow`, `warn` or `deny`. |
| `OnUnavailable` | What it does when the economics cannot be estimated: `allow`, `warn` or `deny`. |
| `MinimumMarginAmount`, `MinimumMarginPercent`, `MaximumEstimatedCost` | The thresholds of the policy; each is present only when set. |
| `MaximumSnapshotAgeSeconds` | An estimate older than this is `stale` and follows `OnUnavailable`. |
| `Decision` | `allow`, `warn` or `deny`: what the policy decided for this call. |
| `Reason` | Why: `within_policy`, `minimum_margin_percentage_not_met`, `minimum_margin_amount_not_met`, `maximum_estimated_cost_exceeded`, `economics_not_configured`, `economics_unavailable`, `economics_stale`, `reporting_currency_mismatch` or `margin_percentage_unavailable_for_zero_revenue`. |

A `deny` is a refusal: `allowed` is `false` and `Reason` is `economic_policy_denied`. A `warn` is **not** a refusal: `allowed` stays `true`, so read the policy `Decision` to see it. The call never reaches the provider on a refusal, so deny before protected work and log or alert on a warning.

A feature with no Cost Rule has `economics.status` `not_configured`, and the policy applies `OnUnavailable` to it. An organization-wide policy with `on_unavailable: deny` therefore also refuses features that have no costs at all; scope such a policy to the features that have Cost Rules, or use `allow` or `warn`.

The estimate behind the decision is in `Economics`: `estimated_incremental_cost`, `estimated_incremental_revenue`, `estimated_incremental_margin` and `estimated_margin_percent`, exact decimal strings. For a feature priced $0.10 per call with a $0.08 cost rule, the margin is `0.02` (20%), so a policy with a 50% minimum refuses it with `minimum_margin_percentage_not_met`.

`res.MarginWarning()` is `true` when the policy decision is `warn`. The decision values are `nozle.PolicyDecisionAllow`, `PolicyDecisionWarn` and `PolicyDecisionDeny`.

```go
res, err := client.Can(ctx, "workspace_123", "llm_tokens")
if err != nil {
    return err
}
switch {
case !res.Allowed && res.Reason == nozle.RefusalReasonEconomicPolicyDenied:
    // res.Policy.Reason, for example "minimum_margin_percentage_not_met";
    // res.Economics.EstimatedMarginPercent is the margin that failed the policy
case res.MarginWarning():
    // allowed, but flagged: log it or alert
}
```

## Spend limits

Available from `nozle-go` v0.27.0 with Engine 2.34.0. When a hard [spend limit](/guides/entitlements/spend-limits) covering the feature is used up, `Can` returns `Allowed == false` with `Reason` `budget_exceeded` and the limit in `Budget`. It is a result, not an error. Compare `Reason` with the `RefusalReason...` constants, never with message text:

```go
result, err := client.Can(ctx, "workspace_123", "llm_tokens")
if err != nil {
  return err
}
if !result.Allowed && result.Reason == nozle.RefusalReasonBudgetExceeded {
  // result.Budget.Limit, .Spent, .Currency, .PeriodEnd
}
```

`RefusalReason` is an alias of `string`, with the constants `RefusalReasonFeatureNotFound`, `RefusalReasonNoSubscription`, `RefusalReasonSubscriptionRequired`, `RefusalReasonNoEntitlement`, `RefusalReasonUsageLimitExceeded`, `RefusalReasonEconomicPolicyDenied`, `RefusalReasonCustomerPaymentOverdue`, `RefusalReasonInsufficientCredits` and `RefusalReasonBudgetExceeded`. `CheckUsage` and `TrackUsage` answer the same way, with `UsageResult.Budget`. A soft limit never refuses.

### Read budgets

```go
list, err := client.ListBudgets(ctx, "workspace_123", "sub_pro_123") // "" for the customer's only subscription
if err != nil {
  return err
}
for _, b := range list.Budgets {
  log.Println(b.FeatureCode, b.Spent, b.Limit, b.Currency, b.Status) // FeatureCode "" is the total limit
}
```

`ListBudgets(ctx, customerID, subscriptionID)` calls [`GET /customers/{customer_id}/budgets`](/api/list-customer-budgets) and returns `BudgetList{CustomerID, SubscriptionID, Budgets}`. `Budget` has `FeatureCode` (empty for the total limit), `Limit`, `Spent`, `Held`, `Remaining` (decimal strings in major units), `Currency`, `Period`, `PeriodStart`, `PeriodEnd` (empty for `lifetime`), `Mode`, `Status`, `AsOf` and `CountedFrom` (v0.28.0, Engine 2.38.0: when counting began).

For an exact cap under concurrent calls, take a [budget hold](/sdks/go/credits#budget-holds) instead of a plain `Can`.
