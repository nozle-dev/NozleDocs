---
title: "Product credits"
description: "Discover credit systems, read exact balances, transfer Entity credits, and atomically consume usage."
---

Product-credit quantities are `nozle.Decimal` strings. Keep their exact decimal representation throughout your application.

## List credit systems and read balances

```go
import nozle "github.com/nozle-dev/nozle-go"

client := nozle.New("") // reads NOZLE_SECRET_KEY

systems, err := client.ListCreditSystems(ctx)
balance, err := client.GetEntityCreditBalance(ctx, "workspace_123", "user_42", "ai_credits")
transfer, err := client.AllocateCredits(ctx, "workspace_123", "user_42", "ai_credits", nozle.Decimal("100.000000000001"), "allocate-user-42-v1")
_ = systems
_ = balance
_ = transfer
_ = err
```

`ListCreditSystems` follows every active Core page. Customer and Entity balance and operation methods expose sources, exact amounts, and cursors. `DeallocateCredits` returns eligible credits to the customer; transfer amounts must be positive strings with at most 12 decimal places.

Use `GetCreditBalance` and `ListCreditBalances` for customer balances. `GetEntityCreditBalance` includes `EntityAvailable`, `SharedAvailable`, `EffectiveAvailable`, and `PoolPolicy`. Pool policy can be `entity_only`, `entity_then_customer`, or `customer_only`.

`Available` already leaves out credits reserved by open [credit holds](#credit-holds). From Engine 2.33.0, `Held` on `CreditBalance` and `CreditSource`, and `EntityHeld`, `SharedHeld` and `Held` on `EntityCreditBalance`, report them.

## Operation history and transfers

`ListCreditOperations` and `ListEntityCreditOperations` take `PageOptions{CreditSystemCode, Limit, Cursor}`. Limits are 1–100. Read `NextCursor` to fetch the next page. Operations include exact amounts, status, reason, rate snapshot, occurrence time, and source allocations. `AllocateCredits` and `DeallocateCredits` require stable idempotency keys of at most 255 UTF-8 bytes.

```go
page, err := client.ListCreditOperations(ctx, "workspace_123", nozle.PageOptions{
  CreditSystemCode: "ai_credits", Limit: 25,
})
_ = page
_ = err
returned, err := client.DeallocateCredits(ctx, "workspace_123", "user_42", "ai_credits", nozle.Decimal("25"), "deallocate-user-42-v1")
_ = returned
_ = err
```

## Advisory check and atomic tracking

```go
check, err := client.CheckUsage(ctx, nozle.UsageParams{CustomerID: "workspace_123", EntityID: "user_42", FeatureCode: "agent_execution", CreditSystemCode: "ai_credits"})
result, err := client.TrackUsage(ctx, nozle.UsageParams{
  CustomerID: "workspace_123", EntityID: "user_42", FeatureCode: "agent_execution", CreditSystemCode: "ai_credits",
  Timestamp: "2026-07-01T12:00:00Z", // fixed per operation; reuse it on retries
}, "agent-run-0183f")
_ = check
_ = result
_ = err
```

`CheckUsage` is advisory. `TrackUsage` atomically evaluates and deducts credits, records the operation, and requires an idempotency key.

Set `UsageParams.Timestamp` (a string) once per operation and store it with the idempotency key. A retry with the same key, the same parameters and the same `Timestamp` replays the original result: the same `OperationID` and no second charge. A retry without a `Timestamp` sends a different body, and the API returns `*APIError` with `StatusCode` 409 (`idempotency_key_reused`).

Set `UsageParams.Properties` for conversion or attribution metadata. `UsageResult` includes `Allowed`, exact `CreditsRequired`, `Available`, `ProjectedRemaining`, and deduction details. A check never reserves credits; inspect `Allowed` on the tracking result before granting the operation.

## Credit holds

Available from `nozle-go` v0.26.0 with Engine 2.33.0. When the cost is known only after the work, hold the credits first and finalize with the actual usage. See [When to hold credits](/guides/credits/usage-tracking#when-to-hold-credits).

```go
hold, err := client.CreateCreditHold(ctx, nozle.CreditHoldParams{
  CustomerID: "workspace_123", EntityID: "user_42", FeatureCode: "agent_execution", CreditSystemCode: "ai_credits",
  Properties: map[string]any{"tokens": 8000}, // the most the work can use
  TTLSeconds: 600,                            // 0 uses the Engine default of 900; at most 86400
}, "hold-run-0183f")
if err != nil {
  return err
}
if !hold.Allowed {
  return fmt.Errorf("usage denied: %s", hold.Reason)
}

tokens, runErr := runAgent(ctx)
if runErr != nil {
  _, _ = client.ReleaseCreditHold(ctx, hold.HoldID)
  return runErr
}
result, err := client.FinalizeCreditHold(ctx, hold.HoldID, nozle.FinalizeCreditHoldParams{
  Properties: map[string]any{"tokens": tokens},
})
if err != nil {
  return err
}
_ = result.CreditsReleased

open, err := client.ListCreditHolds(ctx, "workspace_123", nozle.CreditHoldStatusHeld)
one, err := client.GetCreditHold(ctx, hold.HoldID)
_ = open
_ = one
```

| Method | Endpoint |
|--------|----------|
| `CreateCreditHold(ctx, CreditHoldParams, idempotencyKey) (CreditHoldResult, error)` | [`POST /usage/holds`](/api/create-usage-hold) |
| `FinalizeCreditHold(ctx, holdID, FinalizeCreditHoldParams) (CreditHoldFinalizeResult, error)` | [`POST /usage/holds/{hold_id}/finalize`](/api/finalize-usage-hold) |
| `ReleaseCreditHold(ctx, holdID) (CreditHold, error)` | [`POST /usage/holds/{hold_id}/release`](/api/release-usage-hold) |
| `GetCreditHold(ctx, holdID) (CreditHold, error)` | [`GET /usage/holds/{hold_id}`](/api/get-usage-hold) |
| `ListCreditHolds(ctx, customerID, status) (CreditHoldList, error)` | [`GET /customers/{customer_id}/credit-holds`](/api/list-customer-credit-holds) |

- `CreditHoldParams` has the `TrackUsage` fields plus `TTLSeconds`. A denial is `Allowed=false` with `Reason`, not an error.
- `CreditHoldFinalizeResult` embeds `UsageResult` and adds `HoldID`, `HoldStatus`, `CreditsHeld`, `CreditsReleased` and `HoldExpired`. Usage above the hold passes only when free credit covers the difference; zero usage releases the hold; after expiry the finalize runs as a plain track with `HoldExpired=true`.
- `ListCreditHolds` takes `""` for every status, or one of the `CreditHoldStatusHeld`, `CreditHoldStatusDenied`, `CreditHoldStatusFinalized`, `CreditHoldStatusReleased`, `CreditHoldStatusExpired` constants; another value is refused before any request. It returns the newest 100.
- Errors come back as `*nozle.APIError` with `Code()` `CodeHoldNotFound` (404), `CodeHoldAlreadyResolved` (409: releasing a finalized hold, or finalizing a resolved hold with other usage) or `CodeHoldTTLInvalid` (400).
- A missing `Timestamp` is filled in once per idempotency key (create) or hold ID (finalize) and reused, so a repeat replays the first answer. Create, finalize and release are retried under `WithMaxRetries`.

### Budget holds

Available from v0.27.0 with Engine 2.34.0. On a Feature billed in money under a hard [spend limit](/guides/entitlements/spend-limits), `CreateCreditHold` takes a [budget hold](/api/create-usage-hold#budget-holds): it reserves the call's estimated spend, so concurrent calls cannot overrun the limit.

```go
hold, err := client.CreateCreditHold(ctx, nozle.CreditHoldParams{
  CustomerID: "workspace_123", FeatureCode: "llm_tokens", Properties: map[string]any{"tokens": 4000},
}, "hold-"+runID)
if err != nil {
  return err
}
if hold.Kind == nozle.HoldKindBudget && !hold.Allowed {
  return fmt.Errorf("spend limit reached: %s of %s", hold.Budget.Spent, hold.Budget.Limit)
}
```

- `CreditHold.Kind` is `nozle.HoldKindBudget` for a budget hold (empty for a credit hold), with `AmountHeld` and `Currency` instead of the credit fields. `CreditHoldResult.Budget` is the limit.
- `FinalizeCreditHold` of a budget hold sends the usage and answers the hold: `Kind`, `Status`, `AmountHeld` and `Currency` on `CreditHoldFinalizeResult`.
- `ReleaseCreditHold` and `GetCreditHold` work as for credit holds. `ListCreditHolds` returns credit holds only.

## Legacy wallet adapter

For applications still using the legacy wallet, `CheckAndDeduct` calls Engine's legacy wallet adapter with a customer ID and a numeric credit amount. `CheckAndDeductParams.Feature` is deprecated: it is ignored, not validated and not sent. This endpoint has no idempotency key. Use `CheckUsage` and `TrackUsage` for product credits, which preserve exact decimal values.

Keep reads and mutations behind authenticated backend routes. Derive customer and Entity IDs from trusted identity data.
