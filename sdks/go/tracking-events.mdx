---
title: "Tracking events"
description: "Send idempotent metered events and control subscription attribution with Track."
---

## Send an event

```go
err := client.Track(ctx, nozle.TrackParams{
  CustomerID: "workspace_123", Event: "api_calls",
  SubscriptionID: "workspace_123_subscription",
  TransactionID: "request_0183f",
  Metadata: map[string]any{"tokens": 1500},
})
_ = err
```

`Track` posts `{ "event": { ... } }` to Core `/api/v1/events`. Pass `Timestamp` as RFC3339 or Unix seconds; the SDK sends Unix seconds with millisecond precision, as required by Core. If `SubscriptionID` is omitted, the SDK looks up active subscriptions and requires exactly one. Supply it explicitly when a customer has multiple active subscriptions. Reuse the same transaction ID and timestamp when retrying a logical event. `Meter` posts a batch of 1–100 events to Core `/api/v1/events/batch`; each batch event needs an explicit subscription ID.

`TrackParams` contains `CustomerID`, `Event`, optional JSON `Metadata`, `SubscriptionID`, `TransactionID`, and `Timestamp`. When the transaction ID is omitted, Go generates a UUIDv7. An explicit subscription avoids the lookup and ambiguity for customers with multiple active subscriptions.

## Batch and cost events

```go
err := client.Meter(ctx, []nozle.MeterEvent{{
  CustomerID: "workspace_123", Event: "api_calls", SubscriptionID: "workspace_123_subscription",
  TransactionID: "request_0183f", Metadata: map[string]any{"tokens": 1500},
}})
_ = err
```

`TrackCostEvent` records a Cost Event in Engine. Set `CostMeterCode` and either `ParentTransactionID` or `ExternalCustomerID`. Supply a stable `CostEventID` for retries.

`nozle.CreateTransactionID()` and `nozle.CreateCostEventID()` create UUIDv7 identifiers for those two fields. Create an ID once per logical event and keep it for retries.

For high-volume workloads, enqueue the business event and call `Track` from a durable worker. Use `TrackUsage` when an operation must atomically enforce product credits.
