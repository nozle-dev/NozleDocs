---
title: "LLM auto-capture"
description: "Wrap OpenAI or Anthropic clients to emit a Feature Event and optional detailed Cost Events."
---

The wrappers patch the supplied client instance's create method, preserve its return value, and emit one Feature Event when provider usage metadata is available. When `costMeterCode` is configured, they also emit separate detailed Cost Events linked to that Feature Event.

They capture model, input tokens, output tokens, latency, and an optional feature tag. Prompt and completion content are not inspected or sent.

## OpenAI

```bash
npm install openai
```

```ts
import OpenAI from 'openai'
import { Nozle, wrapOpenAI } from '@nozle-js/node'

const nozle = new Nozle({
  apiKey: process.env.NOZLE_SECRET_KEY!,
  baseUrl: 'https://api.nozle.app',
  eventsUrl: 'https://core.nozle.app',
})

const openai = wrapOpenAI(new OpenAI(), nozle, {
  customerId: 'workspace_123',
  metricCode: 'llm_tokens',
  costMeterCode: 'ai_tokens',
  feature: 'assistant_reply',
})

const response = await openai.chat.completions.create({
  model: 'example-chat-model',
  messages: [{ role: 'user', content: 'Hello' }],
})
```

### OpenAI streaming

The wrapper automatically requests usage metadata for streaming calls and reads the final usage-bearing chunk:

```ts
const stream = await openai.chat.completions.create({
  model: 'example-chat-model',
  messages: [{ role: 'user', content: 'Explain vector search' }],
  stream: true,
})

for await (const chunk of stream) {
  process.stdout.write(chunk.choices[0]?.delta?.content ?? '')
}
```

Tracking is attempted after the stream finishes.

## Anthropic

```bash
npm install @anthropic-ai/sdk
```

```ts
import Anthropic from '@anthropic-ai/sdk'
import { Nozle, wrapAnthropic } from '@nozle-js/node'

const anthropic = wrapAnthropic(new Anthropic(), nozle, {
  customerId: 'workspace_123',
  metricCode: 'llm_tokens',
  costMeterCode: 'ai_tokens',
  feature: 'assistant_reply',
})

const message = await anthropic.messages.create({
  model: 'example-anthropic-model',
  max_tokens: 1_024,
  messages: [{ role: 'user', content: 'Hello' }],
})
```

For Anthropic streams, the wrapper reads input usage from `message_start` and output usage from `message_delta` events.

## `WrapOptions`

| Field | Type | Required | Description |
|---|---|---|---|
| `customerId` | `string` | yes | Customer passed to `nozle.track()`. |
| `metricCode` | `string` | no | Event code; defaults to `llm_tokens`. |
| `costMeterCode` | `string` | no | Cost Event Meter code. When set, emits categorized token Cost Events linked to the Feature Event. |
| `feature` | `string` | no | Included as a `feature` event property. |

## Event properties

```json
{
  "provider": "openai",
  "model": "example-chat-model",
  "input_tokens": 320,
  "output_tokens": 84,
  "latency_ms": 742,
  "feature": "assistant_reply"
}
```

The Feature Event preserves the total input and output counts. Detailed Cost Events use canonical properties `{ tokens, provider, model, type }` and one of these non-zero categories:

- OpenAI: `input`, `cached_input`, `output`, and `reasoning`.
- Anthropic: `input`, `cached_input`, `cache_write`, and `output`.

Cost calculation remains server-side. Configure the `ai_tokens` Cost Event Meter and effective-dated provider/model/category Cost Rules to interpret these events.

## Delivery behavior

The wrapper generates the Feature Event `transaction_id` before delivery and uses it as `parent_transaction_id` on every detailed Cost Event. Parent and child events may therefore arrive out of order. Tracking runs without delaying the provider response, and a tracking failure never replaces a successful provider result.

For workflows requiring durable delivery, explicit transaction IDs, or strict error handling, track manually through your queue instead of relying on the wrapper.

```ts
const response = await providerCall()

await nozle.track(
  'workspace_123',
  'llm_tokens',
  {
    model: response.model,
    input_tokens: response.inputTokens,
    output_tokens: response.outputTokens,
  },
  {
    subscriptionId: 'workspace_123_subscription',
    transactionId: `llm:${response.id}:usage`,
  },
)
```
