---
title: "Entitlements"
description: "Check feature access, usage limits, and margin state with nozle.can()."
---

```ts
const check = await nozle.can('workspace_123', 'api_calls')

if (!check.allowed) {
  throw new Error(check.reason ?? 'Feature unavailable')
}
```

`can()` calls `GET /api/v1/can` with the customer, feature, and optional metadata.

## Signature

```ts
can(
  customerId: string,
  feature: string,
  metadata?: Record<string, string>,
): Promise<CanResult>
```

```ts
const check = await nozle.can('workspace_123', 'model_access', {
  model: 'example-large-model',
  region: 'us-east',
})
```

## `CanResult`

| Field | Type | Description |
|---|---|---|
| `allowed` | `boolean` | Whether the request may proceed. |
| `feature_type` | `string?` | Type of the feature. |
| `reason` | `string?` | Denial or decision reason. Present only when it applies. |
| `used` | `number` | Current measured usage. |
| `limit` | `number \| null` | Configured usage limit. `null` when the feature has no limit. |
| `remaining` | `number \| null` | Remaining allowance. `null` when the feature has no limit. |
| `overage` | `boolean?` | Whether usage is in overage. Present only when it applies. |
| `policy` | `object?` | Configured policy. Present only when configured. |
| `configuration` | `Record<string, string>?` | Feature configuration. Present only when configured. |
| `economics` | `object?` | Point-in-time Cost Sheet estimate with exact decimal strings, Cost Rule version identifiers, and explicit exclusions. |

`economics` contains:

| Field | Description |
|---|---|
| `status` | Estimate status, for example `not_configured`. |
| `estimated_incremental_revenue` | Estimated incremental revenue. |
| `includes` | What the estimate includes. |
| `excludes` | What the estimate excludes. |
| `reason` | Why the estimate has its status, for example `missing_cost_composition`. |
| `calculated_at` | When the estimate was calculated. |

## HTTP handler pattern

```ts
const check = await nozle.can(customerId, 'analytics')

if (!check.allowed) {
  return Response.json(
    {
      error: check.reason ?? 'upgrade_required',
      used: check.used,
      limit: check.limit,
      remaining: check.remaining,
    },
    { status: check.overage ? 429 : 403 },
  )
}

return runAnalyticsQuery()
```

## Authorization guidance

Perform entitlement checks on the trusted backend immediately before protected work. A React `FeatureGate` improves the interface but is not an authorization boundary.

`can()` checks entitlement and usage state; it does not reserve product credits. Use `usage.track()` for atomic credit-backed consumption.
