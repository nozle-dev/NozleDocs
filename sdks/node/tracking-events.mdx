---
title: "Tracking events"
description: "Send idempotent metered events and control subscription attribution with nozle.track()."
---

`nozle.track()` sends one event to `eventsUrl/api/v1/events`.

```ts
await nozle.track(
  'workspace_123',
  'api_calls',
  { model: 'example-model', tokens: 1_500 },
  {
    subscriptionId: 'workspace_123_subscription',
    transactionId: 'request_0183f',
    timestamp: '2026-08-04T10:30:00Z',
  },
)
```

## Signature

```ts
track(
  customerId: string,
  event: string,
  metadata?: Record<string, unknown>,
  options?: {
    subscriptionId?: string
    transactionId?: string
    timestamp?: string
  },
): Promise<string>
```

`track()` returns the `transactionId` that was sent. Keep it: it is the `parentTransactionId` for a Cost Event and the value to reuse on a retry.

| Argument | Description |
|---|---|
| `customerId` | External Nozle customer ID. |
| `event` | Event code matching the Feature code. |
| `metadata` | Properties used by metric aggregation or cost attribution. |
| `subscriptionId` | Explicit external subscription target. |
| `transactionId` | Stable event ID used for idempotency. When omitted, the SDK generates a UUIDv7 and returns it. |
| `timestamp` | Optional event time. Use an RFC 3339 string with `Z` or an offset, or Unix seconds as a numeric string. Omit it and the server uses the time it received the event. |

## Subscription resolution

When `subscriptionId` is omitted, the SDK queries `eventsUrl/api/v1/subscriptions` for active subscriptions belonging to the customer:

- exactly one active subscription: its external ID is cached and used;
- no active subscriptions: `track()` rejects with `No active subscription for customer '<id>'`;
- multiple active subscriptions: `track()` rejects with `Customer '<id>' has <n> active subscriptions — pass subscriptionId explicitly`.

Pass `subscriptionId` explicitly for customers with multiple active subscriptions and for latency-sensitive event paths that should avoid the initial lookup.

<Warning>
The cache lasts for the life of the `Nozle` instance and is never refreshed. After a cancellation, a plan change, or a second `subscribe`, the same instance keeps sending events to the old subscription ID, and the Events API accepts them. Pass `subscriptionId` whenever you change a customer's subscription, or create a new client.
</Warning>

`subscribe` to a second plan adds a subscription; it does not replace the first. To move a customer to another plan, change or cancel the old subscription, then pass the new subscription ID to `track()`.

## Timestamp format

`timestamp` accepts an RFC 3339 string with `Z` or an offset, such as `2026-08-04T10:30:00Z`, or Unix seconds as a numeric string. A date only (`2026-08-04`) or a time without an offset (`2026-08-04T10:30:00`) throws `track timestamp must be RFC3339 or Unix seconds` before any request is sent. The SDK sends the value as Unix seconds with three decimals.

## Request payload

```json
{
  "event": {
    "transaction_id": "request_0183f",
    "external_customer_id": "workspace_123",
    "external_subscription_id": "workspace_123_subscription",
    "code": "api_calls",
    "properties": {
      "model": "example-model",
      "tokens": 1500
    },
    "timestamp": "1785839400.000"
  }
}
```

## Idempotency

Generate a deterministic transaction ID and capture the event timestamp from the business operation whenever possible. Retry the same logical event with both values unchanged. See [errors and retries](/sdks/node/errors).

```ts
const transactionId = `generation:${generationId}:completed`
const timestamp = generationCompletedAt.toISOString()

await nozle.track(customerId, 'text_generation', {
  input_tokens: usage.inputTokens,
  output_tokens: usage.outputTokens,
}, { subscriptionId, transactionId, timestamp })
```

## Operational guidance

- Await `track()` when the request must know whether ingestion succeeded.
- For high-volume workloads, publish through your own durable queue and call `track()` from a worker.
- Do not create a new random transaction ID on each retry.
- Do not regenerate the timestamp when retrying an accepted business event.
- Match property names to the Feature aggregation configuration exactly.
- Use `usage.track()` instead when the operation must atomically enforce and deduct product credits.
