`@nozle-js/node` requires Node.js 18 or later and uses the built-in Fetch API. It ships ESM and CommonJS (`import` and `require` both work).

Entity subscription APIs are introduced in `0.5.0`.

```bash
npm install @nozle-js/node@0.11.0
```

<Info>
Version `0.11.0` sends Feature Events through the Go Engine endpoint. Version `0.10.0` adds `NozleApiError` with `status`, `code` and `hasCode()`, richer checkout result types, and no longer sends `feature` from `checkAndDeduct()`. Version `0.9.1` fixes Feature Event timestamp serialization, including events created by the OpenAI and Anthropic wrappers. Version `0.9.0` introduced subscription options, signed quotes, pending-change withdrawal, and scoped checkout recovery. See [subscription self-service](/sdks/node/billing#subscription-self-service) and the [release notes](/changelog#razorpay-and-stripe-guides-new-sdk-releases-api-fixes).
</Info>

## Create a client

```ts
import { Nozle } from '@nozle-js/node'

export const nozle = new Nozle({
  apiKey: process.env.NOZLE_SECRET_KEY!,
  timeout: 10_000,
})
```

### Configuration

| Field | Type | Default | Description |
|---|---|---|---|
| `apiKey` | `string` | `NOZLE_SECRET_KEY` environment variable | Organization credential. Use a restricted `sk_` for server mutations. When you do not pass it, the client reads `NOZLE_SECRET_KEY`; if that is not set the constructor throws. |
| `host` | `string` | `https://api.nozle.app` | Root API origin. The SDK sends Engine calls to `${host}/engine` and Core calls to `${host}/core`. Set only this for a local or self-hosted deployment behind one reverse proxy. |
| `baseUrl` | `string` | `https://api.nozle.app/engine` | Engine API origin used for `track()`, entitlements, credits, entities, usage, and margin. Overrides the address derived from `host`. |
| `eventsUrl` | `string` | `https://api.nozle.app/core` | Core API origin used for customer writes, billing resources, subscription discovery, credit-system discovery, and Entity subscriptions. Use `https://api.nozle.app/core` in production. Overrides the address derived from `host`. |
| `timeout` | `number` | `10000` | Per-request timeout in milliseconds. |

The client defaults to the public service bases under `https://api.nozle.app`. For a local or self-hosted deployment behind one proxy, set `host`. Set `baseUrl` or `eventsUrl` only when the two services live at unrelated addresses; each one you set wins over `host`. If you set only one of them, the other service still uses `host` (by default production), so set `host` too. Trailing slashes are removed automatically.

```mermaid
flowchart LR
  App[Your backend] --> SDK[@nozle-js/node]
  SDK -->|baseUrl| API[Event ingestion, entitlements, credits, usage, margin]
  SDK -->|eventsUrl| Core[Customers, billing resources, subscription discovery]
```

<Warning>
This package is server-only. Never bundle an `sk_`, master key, or internal credential into browser code. Use `@nozle-js/react` with a publishable key for public catalog reads.
</Warning>

## Verify connectivity

```ts
const health = await nozle.ping()

console.log(health.ok)
console.log(health.engine)
console.log(health.version)
```

## API surface

### API and billing

| Method | Purpose |
|---|---|
| `nozle.ping()` | Check API health. |
| `nozle.plans()` | List plans. |
| `nozle.checkout()` | Create a payment-aware checkout result. |
| `nozle.checkoutStatus()` | Read the status of a checkout. |
| `nozle.verifyCheckout()` | Post Razorpay payment fields to the API for verification. The SDK does not check the signature locally. |
| `nozle.checkoutInvoice()` | Create a checkout for an existing invoice. |
| `nozle.subscribe()` | Create a direct subscription where your workflow permits it. |
| `nozle.cancelSubscription()` | Cancel immediately or at the renewal boundary. |
| `nozle.subscriptionOptions()` | Read a subscription with its plan, pending change, and eligible plans. |
| `nozle.previewSubscriptionChange()` | Preview a plan change. |
| `nozle.withdrawPendingSubscriptionChange()` | Withdraw a pending plan change. |
| `nozle.previewSubscriptionTransition()` | Preview cancellation, downgrade, or uncancel settlement. |
| `nozle.applySubscriptionTransition()` | Apply an idempotent settlement transition. |
| `nozle.track()` | Send a metered event through the Events API. |
| `nozle.can()` | Check feature access, usage, and margin state. |
| `nozle.checkAndDeduct()` | Legacy wallet path, takes `customerId` and `credits`. Throws on `404 wallet_not_found` when the customer has no active wallet. |

### Namespaces

| Namespace | Methods |
|---|---|
| `customers` | `upsert()` |
| `creditSystems` | `list()` |
| `entities` | `get()`, `list()`, `upsert()`, `activate()`, `suspend()`, `bulkUpsert()` |
| `entitySubscriptions` | `ensure()`, `get()`, `list()`, `checkout()`, `checkoutMany()`, `changePlan()`, `cancel()`, `remove()` |
| `credits` | Customer and Entity balance/history reads, `allocate()`, `deallocate()` |
| `usage` | Advisory `check()` and atomic, idempotent `track()` |
| `costEvents` | `track()`, `createCostEventId()` |
| `margin` | `summary()`, `byCustomer()`, `byMetric()`, `byPlan()`, `byModel()`, `trend()` |

The package also exports `wrapOpenAI()` and `wrapAnthropic()` for token metadata capture.

## Key behavior

- Billing mutations and settlement transitions require an API key beginning with `sk_`.
- Entity mutations, credit transfers, and `usage.track()` reject publishable `pk_` keys.
- Mutation idempotency keys are caller-supplied and limited to 255 bytes.
- Product-credit amounts are exact decimal strings, not JavaScript numbers.
- Failed HTTP responses reject with an `Error` containing the operation and HTTP status. See [errors and retries](/sdks/node/errors).
- Every request uses `AbortSignal.timeout(timeout)`. The SDK does not retry.

## Production pattern

Create one client per process and reuse it:

```ts
// billing/nozle.ts
import { Nozle } from '@nozle-js/node'

export const nozle = new Nozle({
  apiKey: process.env.NOZLE_SECRET_KEY!,
  baseUrl: process.env.NOZLE_API_URL!,
  eventsUrl: process.env.NOZLE_EVENTS_URL ?? 'https://api.nozle.app/core',
})
```

Do not accept authoritative `customerId`, Entity IDs, plan codes, return origins, or idempotency keys blindly from a browser. Derive or validate them in your trusted backend.
