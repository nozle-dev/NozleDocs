---
title: "Product credits"
description: "Discover credit systems, read exact balances, transfer Entity credits, and atomically consume usage."
---

Product-credit values are exact decimal strings. Do not convert balances, transfer amounts, or deductions to JavaScript `number` when precision matters.

## List credit systems

```ts
const systems = await nozle.creditSystems.list()

for (const system of systems) {
  console.log(system.code, system.unitName, system.status)
}
```

`list()` fetches every active page and returns normalized camel-case `CreditSystem` objects.

## Customer balances

```ts
const balance = await nozle.credits.getBalance(
  'workspace_123',
  'ai_credits',
)

console.log(balance.available) // exact decimal string
console.log(balance.sources)

const allBalances = await nozle.credits.listBalances('workspace_123')
```

`CreditBalance` includes credit-system metadata, `available`, `held`, an `as_of` timestamp, and ordered balance sources. `available` already leaves out credits reserved by open [credit holds](#credit-holds); `held` (Engine 2.34.0, optional in the type because older Engines omit it) reports them, and each source has its own `held`. Sources identify their type, initial and remaining amounts, validity window, priority, scope, and transfer flags.

## Customer operation history

```ts
const page = await nozle.credits.listOperations('workspace_123', {
  creditSystemCode: 'ai_credits',
  limit: 25,
})

const nextPage = page.next_cursor
  ? await nozle.credits.listOperations('workspace_123', {
      creditSystemCode: 'ai_credits',
      limit: 25,
      cursor: page.next_cursor,
    })
  : null
```

`limit` must be an integer from 1 to 100. Operations expose exact credit amounts, status, reason, rate snapshot, event time, and source allocations.

## Entity balances

```ts
const balance = await nozle.credits.getEntityBalance(
  'workspace_123',
  'user_42',
  'ai_credits',
)

console.log(balance.entity_available)
console.log(balance.shared_available)
console.log(balance.effective_available)
console.log(balance.pool_policy)

const allBalances = await nozle.credits.listEntityBalances(
  'workspace_123',
  'user_42',
)
```

`pool_policy` is `entity_only`, `entity_then_customer`, `customer_only`, or `null` when no policy applies. From Engine 2.34.0, `entity_held`, `shared_held` and `held` report credits reserved by open holds on the Entity's sources, the shared pool and the pool the Entity spends from; the `*_available` amounts already leave them out.

const history = await nozle.credits.listEntityOperations(

## Allocate credits

Transfers require a secret key, a positive decimal string with at most 12 decimal places, and an idempotency key.

```ts
const allocation = await nozle.credits.allocate(
  'workspace_123',
  'user_42',
  {
    creditSystemCode: 'ai_credits',
    amount: '100.000000000001',
  },
  { idempotencyKey: 'allocate-user-42-100-v1' },
)

console.log(allocation.transferred)
console.log(allocation.parent_sources)
console.log(allocation.entity_sources)
console.log(allocation.replayed)
```

## Deallocate credits

```ts
const deallocation = await nozle.credits.deallocate(
  'workspace_123',
  'user_42',
  {
    creditSystemCode: 'ai_credits',
    amount: '25',
  },
  { idempotencyKey: 'deallocate-user-42-25-v1' },
)
```

Transfers are subject to Nozle's exact transfer policy and source eligibility rules. Retry an uncertain transfer with the same key and payload.

## Advisory usage check

```ts
const check = await nozle.usage.check({
  customerId: 'workspace_123',
  entityId: 'user_42',
  featureCode: 'agent_execution',
  creditSystemCode: 'ai_credits',
  properties: { model: 'example-model' },
  occurredAt: new Date().toISOString(),
})

console.log(check.advisory) // true
console.log(check.allowed)
console.log(check.credits_required)
console.log(check.projected_remaining)
console.log(check.projected_deductions)
```

`occurredAt` is the event time as an RFC 3339 string with an offset or `Z`, or Unix seconds as a numeric string (the latter from the Engine release that includes the broader timestamp forms). It defaults to now.

`usage.check()` does not reserve or mutate credits. Another request can spend the projected sources before a later consume request.

## Atomic usage tracking

```ts
// Store one time per unit of work and reuse it on every retry.
const timestamp = execution.startedAt.toISOString()

const result = await nozle.usage.track(
  {
    customerId: 'workspace_123',
    entityId: 'user_42',
    featureCode: 'agent_execution',
    creditSystemCode: 'ai_credits',
    properties: { model: 'example-model' },
    timestamp,
  },
  { idempotencyKey: 'agent-execution-0183f' },
)

if (!result.allowed) {
  console.log(result.reason, result.available)
}
```

`usage.track()` atomically evaluates the metric conversion, selects eligible sources, deducts credits, and records the operation. The optional Entity ID enables Entity attribution and configured pool policy.

<Warning>
**Retrying.** Pass the same `idempotencyKey` and the same `timestamp` on every retry of one unit of work. If you omit `timestamp`, the SDK fills in the current time once per idempotency key and reuses it when the same key is sent again on the same client (it remembers the last 1,000 keys). A retry from another process, or after a restart, gets a new time, no longer matches the first request, and the API returns `409 idempotency_key_reused`; pass a fixed `timestamp` there. With a fixed `timestamp`, a retry replays the original result, including a denial, and does not charge again. A `timestamp` from before the credit rate became effective returns `422 no effective credit rate`. See [errors and retries](/sdks/node/errors).
</Warning>

## Credit holds

Available from `@nozle-js/node` 0.30.0 with Engine 2.34.0. When the amount is known only after the work, reserve credits first, then finalize with the actual usage or release them. See [When to hold credits](/guides/credits/usage-tracking#when-to-hold-credits).

```ts
const hold = await nozle.usage.holds.create(
  {
    customerId: 'workspace_123',
    entityId: 'user_42',
    featureCode: 'agent_execution',
    creditSystemCode: 'ai_credits',
    properties: { tokens: 8000 }, // the most the work can use
    ttlSeconds: 600,
  },
  { idempotencyKey: 'hold-run-0183f' },
)
if (!hold.allowed) throw new Error(hold.reason) // 'insufficient_credits': nothing was reserved

try {
  const answer = await runAgent()
  const result = await nozle.usage.holds.finalize(hold.hold_id, {
    properties: { tokens: answer.tokens },
  })
  console.log(result.credits_consumed, result.credits_released, result.hold_expired)
} catch (error) {
  await nozle.usage.holds.release(hold.hold_id)
  throw error
}

const open = await nozle.usage.holds.list('workspace_123', { status: 'held' })
const one = await nozle.usage.holds.get(hold.hold_id)
```

| Method | Endpoint | Notes |
|--------|----------|-------|
| `create(params, { idempotencyKey })` | [`POST /usage/holds`](/api/create-usage-hold) | The `usage.track()` params plus `ttlSeconds` (an integer from 1 to 86400, Engine default 900; checked before any request). Returns `UsageHoldCreateResult`; a short balance is `allowed: false`, not an error. |
| `finalize(holdId, { properties, timestamp })` | [`POST /usage/holds/{hold_id}/finalize`](/api/finalize-usage-hold) | Returns the `usage.track()` result plus `hold_id`, `hold_status`, `credits_held`, `credits_released` and `hold_expired`. |
| `release(holdId)` | [`POST /usage/holds/{hold_id}/release`](/api/release-usage-hold) | Idempotent. A finalized hold throws `hold_already_resolved` (409). |
| `get(holdId)` | [`GET /usage/holds/{hold_id}`](/api/get-usage-hold) | Returns `UsageHold`. |
| `list(customerId, { status })` | [`GET /customers/{customer_id}/credit-holds`](/api/list-customer-credit-holds) | Newest 100. `status` is `held`, `denied`, `finalized`, `released` or `expired`; another value throws before any request. |

Engine errors arrive as `NozleApiError` with `code` `hold_not_found` (404), `hold_already_resolved` (409) or `hold_ttl_invalid` (400). `create` sends an `Idempotency-Key`, and `create`, `finalize` and `release` follow `maxRetries`: a retried finalize with the same usage replays its first answer. A `timestamp` the SDK fills in is kept per idempotency key (create) and per hold (finalize) on this client; pass `timestamp` when a retry may come from another process.

Types: `UsageHold`, `UsageHoldStatus`, `UsageHoldCreateParams`, `UsageHoldCreateResult`, `UsageHoldFinalizeParams`, `UsageHoldFinalizeResult`, `UsageHoldListOptions`, `UsageHoldList`.

### Budget holds

Available from 0.30.0 with Engine 2.34.0. On a Feature billed in money under a hard [spend limit](/guides/entitlements/spend-limits), `usage.holds.create()` takes a [budget hold](/api/create-usage-hold#budget-holds): it reserves the call's estimated spend, so concurrent calls cannot overrun the limit.

```ts
const hold = await nozle.usage.holds.create(
  { customerId: 'workspace_123', featureCode: 'llm_tokens', properties: { tokens: 4000 } },
  { idempotencyKey: `hold-${runId}` },
)
if (hold.kind === 'budget' && !hold.allowed) {
  // hold.reason === 'budget_exceeded'; hold.budget is the limit
}
```

- `UsageHold` is `CreditUsageHold | BudgetUsageHold`. A budget hold has `kind: 'budget'`, `amount_held` and `currency` instead of the credit fields, and its create result carries `budget`.
- `finalize()` of a budget hold sends the usage and returns the hold. Its spend is counted when the usage event is booked.
- `release()` and `get()` work as for credit holds. `list()` returns credit holds only.
- Types: `CreditUsageHold`, `BudgetUsageHold`, `CreditUsageHoldCreateResult`, `BudgetUsageHoldCreateResult`, `CreditUsageHoldFinalizeResult`.

## Legacy wallet adapter

`nozle.checkAndDeduct({ customerId, credits })` is deprecated and remains available for the legacy wallet path. It is not idempotent: a retry after a timeout can deduct again, so the SDK never retries it. The `feature` field is deprecated: it is still accepted but is not sent and has no effect. Use `usage.check()` and `usage.track()` with a credit system instead.

## Security

Keep credit reads and all mutations behind authenticated backend routes. Derive customer and Entity IDs from server-owned identity data and return only fields the browser needs.
