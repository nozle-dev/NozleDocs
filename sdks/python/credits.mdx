title: "Product credits"
description: "Discover credit systems, read exact balances, transfer Entity credits, and consume usage atomically."

Product-credit amounts are exact decimal strings. Keep them as `str`; do not convert them to `float` when precision matters.

## List credit systems

```python
from nozle import Nozle

nozle = Nozle()  # reads NOZLE_SECRET_KEY

systems = nozle.credit_systems.list()

for system in systems:
    print(system["code"], system["unit_name"], system["status"])
```

The SDK follows all active pages and returns normalized `CreditSystem` typed dictionaries.

## Customer balances

```python
balance = nozle.credits.get_balance("workspace_123", "ai_credits")

print(balance["available"])
print(balance["sources"])

all_balances = nozle.credits.list_balances("workspace_123")
```

`available` already leaves out credits reserved by open [credit holds](#credit-holds). From Engine 2.30.0, `held` reports them on the balance and on each source; Entity balances add `entity_held`, `shared_held` and `held`. An older Engine does not send these keys, so read them with `.get()`.

## Customer operation history

```python
page = nozle.credits.list_operations(
    "workspace_123",
    credit_system_code="ai_credits",
    limit=25,
)

next_page = (
    nozle.credits.list_operations(
        "workspace_123",
        credit_system_code="ai_credits",
        limit=25,
        cursor=page["next_cursor"],
    )
    if page["next_cursor"]
    else None
)
```

Limits must be integers from 1 to 100. Operations include exact amounts, status, reason, rate snapshot, occurrence time, and source allocations.

## Entity balances

```python
balance = nozle.credits.get_entity_balance(
    "workspace_123",
    "user_42",
    "ai_credits",
)

print(balance["entity_available"])
print(balance["shared_available"])
print(balance["effective_available"])
print(balance["pool_policy"])

all_balances = nozle.credits.list_entity_balances(
    "workspace_123",
    "user_42",
)
```

`pool_policy` is `entity_only`, `entity_then_customer`, `customer_only`, or `None`.

## Allocate credits

```python
allocation = nozle.credits.allocate(
    "workspace_123",
    "user_42",
    credit_system_code="ai_credits",
    amount="100.000000000001",
    idempotency_key="allocate-user-42-100-v1",
)

print(allocation["transferred"])
print(allocation["parent_sources"])
print(allocation["entity_sources"])
print(allocation["replayed"])
```

## Deallocate credits

```python
deallocation = nozle.credits.deallocate(
    "workspace_123",
    "user_42",
    credit_system_code="ai_credits",
    amount="25",
    idempotency_key="deallocate-user-42-25-v1",
)
```

Transfer amounts must be positive decimal strings with at most 12 decimal places. Idempotency keys are required and limited to 255 UTF-8 bytes.

## Advisory usage check

```python
check = nozle.usage.check(
    "workspace_123",
    "agent_execution",
    entity_id="user_42",
    credit_system_code="ai_credits",
    properties={"model": "example-model"},
    occurred_at="2026-10-12T16:00:00.000Z",
)

print(check["advisory"])
print(check["credits_required"])
print(check.get("projected_remaining"))
print(check.get("projected_deductions"))
```

`usage.check()` does not reserve or mutate credits. `occurred_at` is optional: pass RFC 3339 with an offset or `Z`, or Unix seconds as a numeric string (the latter from the Engine release that includes the broader timestamp forms). It defaults to the current time. `usage.check()` takes `occurred_at`, not `timestamp`; `timestamp=` raises `TypeError`.

## Atomic usage tracking

```python
result = nozle.usage.track(
    "workspace_123",
    "agent_execution",
    entity_id="user_42",
    credit_system_code="ai_credits",
    properties={"model": "example-model"},
    idempotency_key="agent-execution-0183f",
    timestamp="2026-10-12T16:00:00.000Z",
)

if not result["allowed"]:
    print(result.get("reason"), result.get("available"))
```

`usage.track()` atomically evaluates the metric conversion, selects eligible sources, deducts credits, and records the operation. Entity IDs enable per-Entity attribution and configured pool policy.

`timestamp` is optional in the SDK, which fills in the current time; the API itself requires it. Pass RFC 3339 with an offset or `Z`, or Unix seconds as a numeric string (the latter from the Engine release that includes the broader timestamp forms). A date only, an offset-less value, and zero or negative seconds return `400 invalid_request`.

<Warning>
**Retrying `usage.track`.** Pass the same `idempotency_key` **and the same `timestamp`** on every retry. If you omit `timestamp`, the SDK fills in the current time once per idempotency key and reuses it when the same key is sent again on the same client (it remembers the last 1,000 keys). A retry from another process, or after a restart, gets a new time, no longer matches the first request, and the API returns `409 idempotency_key_reused`; pass a fixed `timestamp` there. Store one time per unit of work (RFC 3339 with an offset, for example `2026-10-12T16:00:00.000Z`) and reuse it. A matching replay returns the original `operation_id`, and the balance changes once. The event time must fall after the credit rate became effective. A `409` means the first call was committed: do not retry.
</Warning>

## Credit holds

Available from `nozle-sdk` 0.27.0 on `Nozle` and `AsyncNozle`, with Engine 2.30.0. When the cost is known only after the work, reserve credits first, then finalize with the actual usage or release them. See [When to hold credits](/guides/credits/usage-tracking#when-to-hold-credits).

```python
hold = nozle.usage.holds.create(
    "workspace_123",
    "agent_execution",
    entity_id="user_42",
    credit_system_code="ai_credits",
    properties={"tokens": 8000},  # the most the work can use
    ttl_seconds=600,  # default 900, at most 86400
    idempotency_key="hold-run-0183f",
)
if not hold["allowed"]:  # status "denied", reason "insufficient_credits"
    raise RuntimeError("not enough credits")

try:
    tokens = run_agent()
except Exception:
    nozle.usage.holds.release(hold["hold_id"])
    raise

result = nozle.usage.holds.finalize(hold["hold_id"], properties={"tokens": tokens})
print(result["credits_consumed"], result["credits_released"], result["hold_expired"])

nozle.usage.holds.get(hold["hold_id"])
nozle.usage.holds.list("workspace_123", status="held")
```

| Method | Endpoint |
|--------|----------|
| `create(customer_id, feature_code, *, idempotency_key, entity_id=None, credit_system_code=None, properties=None, timestamp=None, ttl_seconds=None)` | [`POST /usage/holds`](/api/create-usage-hold) |
| `finalize(hold_id, *, properties=None, timestamp=None)` | [`POST /usage/holds/{hold_id}/finalize`](/api/finalize-usage-hold) |
| `release(hold_id)` | [`POST /usage/holds/{hold_id}/release`](/api/release-usage-hold) |
| `get(hold_id)` | [`GET /usage/holds/{hold_id}`](/api/get-usage-hold) |
| `list(customer_id, *, status=None)` | [`GET /customers/{customer_id}/credit-holds`](/api/list-customer-credit-holds) |

- A denial is a result, not an error: `allowed: False`, `status` `denied`, `reason` `insufficient_credits`.
- `finalize()` returns the `usage.track()` result plus `hold_id`, `hold_status`, `credits_held`, `credits_released` and `hold_expired`. Above the hold it spends free balance too, or answers `allowed: False` and keeps the hold open. Zero usage releases the hold.
- `release()` is idempotent. Engine errors keep their code on `NozleAPIError`: `hold_not_found` (404), `hold_already_resolved` (409), `hold_ttl_invalid` (400). An invalid `ttl_seconds` or `status` raises `NozleValidationError` before any request.
- A `timestamp` the SDK fills in is reused for the same idempotency key (create) and the same hold (finalize) on this client, so retries replay. Pass `timestamp` when a retry may come from another process.
- Types: `CreditHold`, `CreditHoldResult`, `CreditHoldFinalizeResult`, `CreditHoldList`, `CreditHoldStatus`.

## Legacy wallet adapter

`nozle.check_and_deduct(customer_id, credits=5)` remains available for the legacy wallet path. It is not idempotent: a retry after a timeout can deduct again, so the SDK never retries it. The old `check_and_deduct(customer_id, feature, credits)` form still works: `feature` is deprecated, ignored and never sent. A missing `credits` raises `NozleValidationError`. New product-credit integrations should use `usage.check()` and `usage.track()`.

Keep reads and mutations behind authenticated backend routes and derive customer and Entity IDs from trusted identity data.
