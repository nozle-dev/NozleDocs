Customers represent billable accounts or workspaces. Entities represent children such as users, agents, projects, or environments.

## Upsert a customer

`customers.upsert()` sends the merchant's secret key directly to Nozle Core.
Core derives the owning organization from that key; the SDK never provisions a
customer through a global or master organization.

```python
from nozle import Nozle

nozle = Nozle()  # reads NOZLE_SECRET_KEY

customer = nozle.customers.upsert(
    "workspace_123",
    name="Acme Workspace",
    email="billing@example.com",
)
```

`external_id` is required. `name`, `email` and `billing_configuration` are optional.

### Link a customer that already exists in Stripe

Pass `billing_configuration` with the Stripe customer ID to link it in the same call (requires `nozle-sdk` `0.12.0`). Nozle stores the link and does not create a new Stripe customer. Sending the same upsert again is safe.

```python
nozle.customers.upsert(
    "workspace_123",
    name="Acme Workspace",
    billing_configuration={
        "payment_provider": "stripe",
        "payment_provider_code": "stripe_main",
        "provider_customer_id": "cus_ABC123",
    },
)
```

`payment_provider` is required inside `billing_configuration`. `payment_provider_code`, `provider_customer_id`, `sync_with_provider` and `provider_payment_methods` are optional. Nozle keeps the assignment with or without `sync_with_provider`, and checkout charges only through the assigned connection. See [Assign the connection to customers](/integrations/stripe#assign-the-connection-to-customers).

## Tax IDs and VAT checks

Available from `nozle-sdk` `0.33.0`, which ships after Core 11.31.0. `customers.upsert` takes the address and the tax ID. Core checks the format and, for an EU VAT number on a billing entity with EU tax management, starts a VIES check.

```python
customer = nozle.customers.upsert(
    "workspace_123",
    customer_type="company",
    legal_name="Acme GmbH",
    address={"line1": "Main St 1", "city": "Berlin", "postal_code": "10115", "country": "DE"},
    tax_id={"type": "eu_vat", "value": "DE811128135"},
)

print(customer["tax_identification_status"])  # "pending" while VIES runs
print(customer["tax_treatment"])
print(customer.get("tax_identification_warnings"))  # for example ["country_mismatch"]
```

`address` and `shipping_address` take `line1`, `line2`, `city`, `state`, `postal_code` and `country`. The SDK sends Core's flat keys. Core validates the tax ID format. The SDK only refuses a `tax_id` without `type` or `value`.

To remove a stored tax ID, pass `clear_tax_id=True`. Do not pass it together with `tax_id`.

```python
nozle.customers.upsert("workspace_123", clear_tax_id=True)
```

Read the result with `customers.get(external_id)`. Before a checkout, wait until the check ends:

```python
ready = nozle.customers.wait_for_tax_check("workspace_123")  # timeout=10.0 seconds
print(ready["tax_identification_status"])  # "valid", "invalid" or "unverified"
```

`wait_for_tax_check` polls `customers.get` until the status is not `pending`, and raises `NozleValidationError` after the timeout. Both methods work on `Nozle` and `AsyncNozle`. A checkout call fails with `customer_tax_location_required` (422) or `customer_tax_check_pending` (409, see `retry_after_seconds`). From Core 11.54.0 (_Unreleased_) the checkout answers a `hosted` result whose URL is Nozle's [billing details step](/guides/billing/tax-ids#billing-details-step) instead of the 422: redirect the customer to it as for any hosted checkout. The 409 then only holds a paid plan change, an invoice checkout and a number without a type that is not well formed. See [Tax IDs, reverse charge and VAT checks](/guides/billing/tax-ids).

## Erase or delete a customer

Available from `0.41.0`, with Core 11.52.0, on `Nozle` and `AsyncNozle`. Both need a secret key and return the customer.

```python
from nozle import CustomerEraseErrorCode, NozleAPIError

try:
    erased = nozle.customers.erase("workspace_123")
    print(erased["erased_at"])  # set; the erasure finishes in the background
except NozleAPIError as error:
    if error.has_code(CustomerEraseErrorCode.HAS_UNPAID_INVOICES):
        ...  # settle or void the unpaid invoices first
```

- `customers.erase(external_id)` calls `POST /customers/{external_id}/erase`. It erases the customer's personal data, irreversibly. A `422` lists `has_active_subscriptions`, `has_draft_invoices` or `has_unpaid_invoices` in `error_details["customer"]` (`CustomerEraseErrorCode`). Erasing an erased customer changes nothing.
- `customers.delete(external_id)` calls `DELETE /customers/{external_id}`. It deletes the customer and ends its subscriptions, and keeps its personal data.
- Erase is not delete. To remove personal data, for example under GDPR, call `erase`.
- Neither is retried automatically.

See [Erase a customer](/api/create-customer#erase-a-customer) for what is erased and what is kept.

## Read Entities

```python
entity = nozle.entities.get("workspace_123", "user_42")

page = nozle.entities.list(
    "workspace_123",
    status="active",
    limit=50,
)

next_page = (
    nozle.entities.list(
        "workspace_123",
        status="active",
        limit=50,
        cursor=page["next_cursor"],
    )
    if page["next_cursor"]
    else None
)
```

Entity status accepts `active` or `suspended`; Entities cannot be deleted. List limits must be integers from 1 to 100.

## Upsert an Entity

```python
result = nozle.entities.upsert(
    "workspace_123",
    "user_42",
    status="active",
    name="Asha",
    metadata={"role": "agent"},
    idempotency_key="entity-user-42-v1",
)

print(result["action"])
print(result["replayed"])
```

Entity IDs and idempotency keys are limited to 255 UTF-8 bytes. Retry an uncertain mutation with the same key and payload.

## Suspend and activate

```python
nozle.entities.suspend(
    "workspace_123",
    "user_42",
    idempotency_key="suspend-user-42-v1",
)

nozle.entities.activate(
    "workspace_123",
    "user_42",
    idempotency_key="activate-user-42-v2",
)
```

These helpers first fetch the Entity and preserve its current name and metadata.

## Bulk upsert

```python
result = nozle.entities.bulk_upsert(
    "workspace_123",
    [
        {"external_id": "user_42", "name": "Asha", "status": "active"},
        {"external_id": "user_43", "name": "Ravi", "status": "suspended"},
    ],
    idempotency_key="workspace-123-users-import-7",
)

print(result["counts"])
```

Each bulk call accepts 1–500 unique Entity IDs.

## Seat billing is explicit

Entity lifecycle methods do not emit Feature seat events. Track seat additions and removals separately when your catalog bills seats.

```python
nozle.track(
    "workspace_123",
    "billable_seats",
    metadata={"user_id": "user_42", "operation": "add"},
    subscription_id="workspace_123_subscription",
    transaction_id="seat-add-user-42-v1",
)
```

Use the same Entity ID with `nozle.credits` and `nozle.usage` for per-Entity balances and attribution.
