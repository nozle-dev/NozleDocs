## List plans

`plans()` accepts either `pk_` or `sk_` credentials.

```python
plans = nozle.plans()

for plan in plans:
    print(
        plan["code"],
        plan["amount_cents"],
        plan["amount_currency"],
        plan["interval"],
    )
```

The `Plan` typed dictionary declares `code`, `name`, `amount_cents`, `amount_currency`, and `interval`. At runtime each item is the full plan dictionary from the API, including `charges`, `entitlements`, `taxes` and `credit_grant_rules`, and the list includes trial, pay-in-arrears and pending-deletion plans. See the [public plan catalog](/api/list-plans). With a `pk_` key, all of it is readable by anyone who has the key.

## Create checkout

```python
result = nozle.checkout(
    "workspace_123",
    "pro_monthly",
    return_url="https://app.example.com/settings/billing",
)
```

`checkout()` requires an `sk_` key and returns a typed dictionary. Handle each `type` explicitly:

| `type` | Fields | Handling |
| --- | --- | --- |
| `stripe` | `client_secret`/`clientSecret` (`cs_...`), `invoice_id`, `amount_cents`, `currency` | Mount Stripe embedded Checkout with the client secret. Plan and invoice checkout never return a Stripe `url`; only credit top-ups return a Stripe-hosted `payment_url`. See [the Stripe flow](/guides/billing/checkout#stripe). |
| `razorpay` | `checkout_id`, `key_id`, `order_id`, `amount_cents`, `currency`, `expires_at`, `invoice_id`; with a mandate also `customer_id`, `recurring: True`, `mandate_max_amount_cents` | Open Razorpay Checkout, then verify the genuine callback through your backend. See [the Razorpay flow](/guides/billing/checkout#razorpay). |
| `hosted` | `payment_url` | Not returned by `checkout()` or `checkout_invoice()`. The type still exists for a Razorpay payment link: navigate to `payment_url`. Invoice payment URLs and credit top-ups return a `payment_url` without a `type`. |
| `processing` | `checkout_id`, `status` | Razorpay: the order is not ready or has expired. Stripe: a replayed quoted upgrade whose webhook is still pending. Recover with `checkout_status(checkout_id)`. `status` is an internal operation status. |
| `completed` | `status: "succeeded"`, `subscription_id`, `plan_code`, `invoice_id` (may be `None`), `amount_cents`, `currency`, `payment_source` (`credits` or `none`) | Refresh authoritative subscription state. |
| `scheduled` | `status: "pending"`, `subscription_id`, `plan_code`, `transition_direction`, `transition_policy`, `effective_at` | Display the pending change and its effective date. |

A paid upgrade returns `plan_upgrade_intent_id` instead of `invoice_id` on `stripe` and `razorpay` results. On `scheduled`, `subscription_id` is the pending subscription. `pending_subscription_id` was removed from the result type in `0.10.0` because the API never returns it; earlier versions declared it.

Do not handle all non-Stripe responses as scheduled changes. See [the React checkout components](/sdks/react/components#checkout-components) for the browser integration.

Validate the exact HTTPS return origin before passing a browser-provided URL to this method.

### Checkout errors

| Status | `code` | Cause |
| --- | --- | --- |
| 400 | `invalid_return_url` | The `return_url` origin is not allowed. Checked before anything else. |
| 404 | `plan_not_found`, `customer_not_found` | Unknown plan or customer. |
| 409 | `subscription_selection_required` | The customer has several active subscriptions and no `subscription_id` was given. |
| 422 | `checkout_not_required` | The plan needs no up-front payment (free, trial, or pay-in-arrears) and the customer has no subscription. Use `subscribe()` instead. |
| 422 | `payment_provider_required` | No payment provider is connected. |
| 422 | `plan_already_active` | The customer is already on that plan. |
| 409 | `subscription_checkout_in_progress` | A new-subscription checkout for this customer is still open on a different plan. Checking out the same plan again reopens it. |

The SDK raises `NozleValidationError` before any request when `register_mandate` is not a `bool`, or when `quote_id` is given without `subscription_id`. See [Create checkout](/api/create-checkout) for the HTTP contract.

### Deprecated `success_url`

`success_url=` remains a deprecated alias for `return_url=`. The SDK emits `DeprecationWarning`, sends only `return_url`, and rejects conflicting values with `NozleValidationError`.

<Warning>
Nozle payment fulfillment is authoritative. Browser callbacks and redirects do not prove activation; Razorpay upgrades require capture and Stripe requires backend settlement.
</Warning>

## Direct subscription

```python
nozle.customers.upsert("workspace_123", name="Acme Workspace")
subscription = nozle.subscribe("workspace_123", "free")

print(subscription["subscription_id"])
print(subscription["status"])
```

The customer must already exist, so call `customers.upsert()` first. An unknown customer returns `404 customer_not_found` and nothing is created. Calling `subscribe()` again for the same customer and plan returns the same subscription. `subscribe()` accepts a paid plan without collecting payment. Use checkout for payment-gated changes. Use direct subscription only when the configured flow does not require interactive payment.

<Warning>
`subscribe()` to another plan adds a second active subscription. It does not replace the first, and plan credit grants are granted again. To move a customer, call `checkout()` with `subscription_id` (needs a [transition policy](/api/plan-transition-policies)), or cancel and then subscribe. Pass the new subscription ID to `track()`: cached clients keep the old ID.
</Warning>

## Cancellation

```python
result = nozle.cancel_subscription(
    "workspace_123",
    "subscription_123",
    policy="end_of_period",
)
```

The policy defaults to `end_of_period` and also accepts `immediate`.

## Subscription self-service

<Info>
The following subscription-management methods are available in `nozle-sdk==0.10.0`. The matching hosted endpoints are available; see the [Python merchant example](https://github.com/nozle-dev/nozle-python/tree/v0.9.1/examples/billing_portal) for a complete integration.
</Info>

These methods power [the React billing portal](/sdks/react/billing-portal). Derive `customer_id` from the authenticated application user and validate the selected external `subscription_id`. Do not substitute the Core internal UUID for that external identifier.

<Warning>
Changing an existing subscription's plan needs a [transition policy](/api/plan-transition-policies) for that source and target plan pair. Without one, preview, checkout, and transitions return `422 plan_transition_policy_required`. Exception: from a \$0 plan to a paid plan, the organization's free-to-paid default applies without a pair policy.
</Warning>

### Load eligible plans and preview a quote

```python
options = nozle.subscription_options(customer_id, subscription_id)
quote = nozle.preview_subscription_change(customer_id, subscription_id, target_plan_code)
```

`SubscriptionOptions` is a typed dictionary with `subscription`, `pending_change`, `eligible_plans`, and optional `checkout`. Plans contain `code`, `name`, `amount_cents`, `currency`, and `interval`; eligible plans add `direction` and `timing`. A pending change has its own internal `id` and `effective_at`.

`SubscriptionChangePreview` contains `quote_id`, `transition_direction`, `timing`, `currency`, `credit_amount_cents`, `debit_amount_cents`, `net_amount_cents`, `amount_due_now_cents`, `amount_due_at_effective_cents`, `effective_at`, and `renewal_at`. The API also returns `transition_policy`, `billing_anchor`, `proration_behavior`, and `credit_action`, which the type omits. Show these exact amounts and dates before confirmation. Minor-unit amounts may be integers or strings; preserve their precision. Eligibility comes from configured transition policies, not a client-side price comparison.

### Confirm a paid upgrade

After the customer confirms, use the saved quote and a stable action key:

```python
checkout = nozle.checkout(
    customer_id,
    target_plan_code,
    return_url=return_url,
    subscription_id=subscription_id,
    quote_id=quote["quote_id"],
    idempotency_key=confirmed_action_key,
)
```

`quote_id` requires `subscription_id`. Quotes expire after five minutes or become invalid when their bound state changes. On HTTP 409, request a new preview and confirmation. For an uncertain response, retry the same confirmed request and key; an accepted request can replay after quote expiry.

A \$0 to \$0 immediate upgrade returns `completed` with `payment_source: "credits"` and creates a \$0 invoice. An upgrade checkout to a pay-in-arrears plan returns `422 plan_upgrade_invoice_missing`.

### Schedule or withdraw a downgrade

For a confirmed quote with `transition_direction == "downgrade"`:

```python
scheduled = nozle.apply_subscription_transition(
    {
        "customer_id": customer_id,
        "subscription_id": subscription_id,
        "operation": "downgrade",
        "target_plan_code": target_plan_code,
        "timing": "end_of_period",
        "billing_anchor": "keep_anchor",
        "quote_id": quote["quote_id"],
    },
    idempotency_key=confirmed_action_key,
)
```

Reload options to display the pending change separately from the current plan. Retain the exact `pending_change["id"]` shown in the customer's withdrawal confirmation:

```python
withdrawn = nozle.withdraw_pending_subscription_change(
    customer_id,
    subscription_id,
    confirmed_pending_subscription_id,
    idempotency_key=withdrawal_action_key,
)
```

The result is `{"subscription": {"id", "external_id", "plan_code", "status"}, "withdrawn_pending_subscription_id", "replayed"}`. The same key returns the same body with `replayed: True`. Withdrawal preserves the active plan.

A new scheduled change while a change is pending replaces it with a new pending ID. A paid upgrade checkout does not replace or withdraw a pending downgrade: withdraw it first, or the upgrade payment ends in `needs_review` with `plan_upgrade_subscription_changed`. Withdrawing the replaced ID returns `409 pending_subscription_changed`. An unknown ID returns `404 pending_subscription_not_found`.

### Cancel at period end and Keep

Preview through the existing transition method:

```python
cancellation = nozle.preview_subscription_transition({
    "customer_id": customer_id,
    "subscription_id": subscription_id,
    "operation": "cancel",
    "timing": "end_of_period",
})
```

After displaying and confirming the ending date, forward the exact timestamp:

```python
nozle.apply_subscription_transition(
    {
        "customer_id": customer_id,
        "subscription_id": subscription_id,
        "operation": "cancel",
        "timing": "end_of_period",
        "expected_effective_at": cancellation["subscription_transition"]["effective_at"],
    },
    idempotency_key=cancellation_action_key,
)
```

Keep uses `uncancel` with a separate confirmed action key and no settlement overrides:

```python
nozle.apply_subscription_transition(
    {"customer_id": customer_id, "subscription_id": subscription_id, "operation": "uncancel"},
    idempotency_key=keep_action_key,
)
```

Keep is available only before the ending is due. Cancellation clears a pending downgrade; Keep does not recreate it. Preserve the preview's full timestamp, including timezone and fractional seconds.

### Scope payment recovery and verification

```python
payment = nozle.checkout_status(
    checkout_id, customer_id=customer_id, subscription_id=subscription_id,
)
verified = nozle.verify_checkout(
    checkout_id,
    razorpay_verification,
    customer_id=customer_id,
    subscription_id=subscription_id,
)
```

Forward the genuine Razorpay callback's `razorpay_order_id`, `razorpay_payment_id`, and `razorpay_signature`; a missing field raises before any request. The optional scope fields must be supplied together. Existing calls without them remain compatible; include both for customer-specific recovery. An unknown checkout ID returns `404 checkout_session_not_found`.

Status distinguishes `awaiting_payment`, `processing`, `succeeded`, `failed`, `expired`, and `needs_review`, with a separate `fulfillment_status`. Reload the selected subscription before reporting activation. Keep the existing checkout for recoverable retries and use your support route for uncertain payments before another collection.

The [merchant example](https://github.com/nozle-dev/nozle-python/tree/v0.9.1/examples/billing_portal) maps these dictionaries to React's camelCase action types and persists retry context. Replace its demo login/file store with your application's authentication and transactional storage for production workers. See [the HTTP contract](/api/subscription-management).

## Entity subscriptions

```python
nozle.entity_subscriptions.ensure("workspace_123", "user_42")

checkout = nozle.entity_subscriptions.checkout(
    "workspace_123",
    "user_42",
    plan_code="pro_monthly",
    billing_time="anniversary",
    return_url="https://app.example.com/settings/billing",
    idempotency_key="checkout-user-42-pro-v1",
)
```

Change or cancel only that Entity:

```python
nozle.entity_subscriptions.change_plan(
    "workspace_123",
    "user_42",
    plan_code="max_annual",
    return_url="https://app.example.com/settings/billing",
    idempotency_key="change-user-42-max-v1",
)

nozle.entity_subscriptions.cancel(
    "workspace_123",
    "user_42",
    timing="end_of_period",
    credit_action="none",
    idempotency_key="cancel-user-42-v1",
)
```

Every method requires an `sk_` key. See [Entity Subscriptions](/api/entity-subscriptions) for lifecycle and payment behavior.

- `billing_time` accepts only `calendar` or `anniversary`.
- Single Entity checkout also accepts free, trial, and pay-in-arrears plans. It returns `completed` with `payment_source: "none"`.
- `change_plan()` needs a [transition policy](/api/plan-transition-policies) for the plan pair and takes no `billing_time`. It returns `scheduled` or `completed`, plus `external_entity_id` and `external_subscription_id`.
- `cancel()` requires `idempotency_key`. On a pay-in-arrears plan without `credit_action` it returns `422` with `credit_action: not_supported_for_pay_in_arrears`.
- `remove()` on an Entity with billing history returns `403 entity_subscription_has_billing_history`.

### Buy several Entity plans together

`checkout_many()` buys plans for several Entities with one payment. Do not loop over `entity_subscriptions.checkout()`: each call creates an independent checkout instead of one combined invoice.

```python
batch = nozle.entity_subscriptions.checkout_many(
    "workspace_123",
    items=[
        {"external_entity_id": "user_42", "plan_code": "pro_monthly"},
        {"external_entity_id": "user_43", "plan_code": "max_monthly"},
    ],
    billing_time="anniversary",
    return_url="https://app.example.com/settings/billing",
    idempotency_key="seats-workspace-123-v1",
)
```

The result contains `id`, `type` (`stripe`, `razorpay`, `processing`, or `completed`), `status` (`pending`, `open`, `completed`, `failed`, or `expired`), `client_secret`, `invoice_id`, `amount_cents`, `currency`, `replayed`, `expires_at`, and `items` with `external_entity_id`, `external_subscription_id`, `plan_code`, and `subscription_status`. Razorpay results add the Razorpay fields.

- Send 1 to 100 unique `external_entity_id` values. The SDK checks this before any request.
- `idempotency_key` is required, up to 255 bytes, and sent as the `Idempotency-Key` header. The same key and request returns `replayed: True` and reuses the open session. Replaying a `failed` or `expired` batch returns `checkout_not_available`.
- The checkout expires after 23 hours.
- Every plan must require up-front payment: pay in advance with an amount above 0 and no trial, or pay-in-advance fixed charges. Otherwise the whole batch fails with `422 validation_errors` and `error_details["items"] == ["paid_plan_required"]`. Other item errors are `mixed_currencies` and `mixed_intervals`.
- An untrusted `return_url` returns `422` with `return_url: invalid_or_untrusted`.
- With no payment provider connected, the call returns `422 payment_provider_required`, as single checkout does.

See [bulk Entity checkout](/api/entity-subscriptions#purchase-multiple-entity-plans-together).

## Settlement transitions

```python
params = {
    "customer_id": "workspace_123",
    "subscription_id": "subscription_123",
    "operation": "downgrade",
    "timing": "end_of_period",
    "target_plan_code": "growth_monthly",
    "credit_action": "none",
}

preview = nozle.preview_subscription_transition(params)

transition = nozle.apply_subscription_transition(
    params,
    idempotency_key="transition-subscription-123-growth-v1",
)
```

Apply requires an idempotency key up to 255 UTF-8 bytes. These methods use the `timing` you pass even when the pair's transition policy says otherwise; checkout always follows the policy. A `downgrade` on a pair whose policy direction is `upgrade` returns `422 target_plan_is_not_a_downgrade`. See [Subscriptions](/guides/billing/subscriptions) for settlement options and validation rules.
