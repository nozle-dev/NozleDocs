## List plans

`plans()` accepts either `pk_` or `sk_` credentials.

```python
plans = nozle.plans()

for plan in plans:
    print(
        plan["code"],
        plan["amount_cents"],
        plan["amount_currency"],
        plan["interval"],
    )
```

Each `Plan` is a typed dictionary containing `code`, `name`, `amount_cents`, `amount_currency`, and `interval`.

## Create checkout

```python
result = nozle.checkout(
    "workspace_123",
    "pro_monthly",
    return_url="https://app.example.com/settings/billing",
)
```

`checkout()` requires an `sk_` key and returns a typed dictionary. Handle each `type` explicitly:

| `type` | Handling |
| --- | --- |
| `stripe` | Hosted `url` or embedded `client_secret`/`clientSecret`. |
| `razorpay` | Razorpay order, amount, currency and public `key_id`; verify the genuine callback through your backend. |
| `hosted` | Hosted `payment_url`. |
| `processing` | Recover the outcome with `checkout_id`. |
| `completed` | Refresh authoritative subscription state. |
| `scheduled` | Refresh and display the pending change/effective date. |

Do not handle all non-Stripe responses as scheduled changes. See [the React checkout components](/sdks/react/components#checkout-components) for the browser integration.

Validate the exact HTTPS return origin before passing a browser-provided URL to this method.

### Deprecated `success_url`

`success_url=` remains a deprecated alias for `return_url=`. The SDK emits `DeprecationWarning`, sends only `return_url`, and rejects conflicting values with `NozleValidationError`.

<Warning>
Nozle payment fulfillment is authoritative. Browser callbacks and redirects do not prove activation; Razorpay upgrades require capture and Stripe requires backend settlement.
</Warning>

## Direct subscription

```python
subscription = nozle.subscribe("workspace_123", "free")

print(subscription["subscription_id"])
print(subscription["status"])
```

Use checkout for payment-gated changes. Use direct subscription only when the configured flow does not require interactive payment.

## Cancellation

```python
result = nozle.cancel_subscription(
    "workspace_123",
    "subscription_123",
    policy="end_of_period",
)
```

The policy defaults to `end_of_period` and also accepts `immediate`.

## Subscription self-service

<Info>
The following subscription-management additions are merged but await a package release. Published `nozle-sdk==0.8.0` does not include them. The matching hosted endpoints are available; use the [merged Python merchant example](https://github.com/nozle-dev/nozle-python/tree/5a3ac66a4508bfa616e68b7d352d7dec83f93f74/examples/billing_portal) to evaluate the source build.
</Info>

These methods power [the React billing portal](/sdks/react/billing-portal). Derive `customer_id` from the authenticated application user and validate the selected external `subscription_id`. Do not substitute the Core internal UUID for that external identifier.

### Load eligible plans and preview a quote

```python
options = nozle.subscription_options(customer_id, subscription_id)
quote = nozle.preview_subscription_change(customer_id, subscription_id, target_plan_code)
```

`SubscriptionOptions` is a typed dictionary with `subscription`, `pending_change`, `eligible_plans`, and optional `checkout`. Plans contain `code`, `name`, `amount_cents`, `currency`, and `interval`; eligible plans add `direction` and `timing`. A pending change has its own internal `id` and `effective_at`.

`SubscriptionChangePreview` contains `quote_id`, `transition_direction`, `timing`, `currency`, `credit_amount_cents`, `debit_amount_cents`, `net_amount_cents`, `amount_due_now_cents`, `amount_due_at_effective_cents`, `effective_at`, and `renewal_at`. Show these exact amounts and dates before confirmation. Minor-unit amounts may be integers or strings; preserve their precision. Eligibility comes from configured transition policies, not a client-side price comparison.

### Confirm a paid upgrade

After the customer confirms, use the saved quote and a stable action key:

```python
checkout = nozle.checkout(
    customer_id,
    target_plan_code,
    return_url=return_url,
    subscription_id=subscription_id,
    quote_id=quote["quote_id"],
    idempotency_key=confirmed_action_key,
)
```

`quote_id` requires `subscription_id`. Quotes expire after five minutes or become invalid when their bound state changes. On HTTP 409, request a new preview and confirmation. For an uncertain response, retry the same confirmed request and key; an accepted request can replay after quote expiry.

### Schedule or withdraw a downgrade

For a confirmed quote with `transition_direction == "downgrade"`:

```python
scheduled = nozle.apply_subscription_transition(
    {
        "customer_id": customer_id,
        "subscription_id": subscription_id,
        "operation": "downgrade",
        "target_plan_code": target_plan_code,
        "timing": "end_of_period",
        "billing_anchor": "keep_anchor",
        "quote_id": quote["quote_id"],
    },
    idempotency_key=confirmed_action_key,
)
```

Reload options to display the pending change separately from the current plan. Retain the exact `pending_change["id"]` shown in the customer's withdrawal confirmation:

```python
withdrawn = nozle.withdraw_pending_subscription_change(
    customer_id,
    subscription_id,
    confirmed_pending_subscription_id,
    idempotency_key=withdrawal_action_key,
)
```

The result contains `subscription`, `withdrawn_pending_subscription_id`, and `replayed`. Withdrawal preserves the active plan; a stale pending UUID conflicts instead of removing a replacement.

### Cancel at period end and Keep

Preview through the existing transition method:

```python
cancellation = nozle.preview_subscription_transition({
    "customer_id": customer_id,
    "subscription_id": subscription_id,
    "operation": "cancel",
    "timing": "end_of_period",
})
```

After displaying and confirming the ending date, forward the exact timestamp:

```python
nozle.apply_subscription_transition(
    {
        "customer_id": customer_id,
        "subscription_id": subscription_id,
        "operation": "cancel",
        "timing": "end_of_period",
        "expected_effective_at": cancellation["subscription_transition"]["effective_at"],
    },
    idempotency_key=cancellation_action_key,
)
```

Keep uses `uncancel` with a separate confirmed action key and no settlement overrides:

```python
nozle.apply_subscription_transition(
    {"customer_id": customer_id, "subscription_id": subscription_id, "operation": "uncancel"},
    idempotency_key=keep_action_key,
)
```

Keep is available only before the ending is due. Cancellation clears a pending downgrade; Keep does not recreate it. Preserve the preview's full timestamp, including timezone and fractional seconds.

### Scope payment recovery and verification

```python
payment = nozle.checkout_status(
    checkout_id, customer_id=customer_id, subscription_id=subscription_id,
)
verified = nozle.verify_checkout(
    checkout_id,
    razorpay_verification,
    customer_id=customer_id,
    subscription_id=subscription_id,
)
```

Forward the genuine Razorpay callback's `razorpay_order_id`, `razorpay_payment_id`, and `razorpay_signature`. The optional scope fields must be supplied together. Existing calls without them remain compatible; include both for customer-specific recovery.

Status distinguishes `awaiting_payment`, `processing`, `succeeded`, `failed`, `expired`, and `needs_review`, with a separate `fulfillment_status`. Reload the selected subscription before reporting activation. Keep the existing checkout for recoverable retries and use your support route for uncertain payments before another collection.

The [merchant example](https://github.com/nozle-dev/nozle-python/tree/5a3ac66a4508bfa616e68b7d352d7dec83f93f74/examples/billing_portal) maps these dictionaries to React's camelCase action types and persists retry context. Replace its demo login/file store with your application's authentication and transactional storage for production workers. See [the HTTP contract](/api/subscription-management).

## Entity subscriptions

```python
nozle.entity_subscriptions.ensure("workspace_123", "user_42")

checkout = nozle.entity_subscriptions.checkout(
    "workspace_123",
    "user_42",
    plan_code="pro_monthly",
    billing_time="anniversary",
    return_url="https://app.example.com/settings/billing",
    idempotency_key="checkout-user-42-pro-v1",
)
```

Change or cancel only that Entity:

```python
nozle.entity_subscriptions.change_plan(
    "workspace_123",
    "user_42",
    plan_code="max_annual",
    return_url="https://app.example.com/settings/billing",
    idempotency_key="change-user-42-max-v1",
)

nozle.entity_subscriptions.cancel(
    "workspace_123",
    "user_42",
    timing="end_of_period",
    idempotency_key="cancel-user-42-v1",
)
```

Every method requires an `sk_` key. See [Entity Subscriptions](/api/entity-subscriptions) for lifecycle and payment behavior.

The Python SDK currently exposes single-Entity checkout and plan changes. For a mixed seat-pool purchase, call the bulk Entity checkout endpoint from your trusted backend. Do not loop over `entity_subscriptions.checkout()`, because each call creates an independent checkout instead of one combined invoice.

## Settlement transitions

```python
params = {
    "customer_id": "workspace_123",
    "subscription_id": "subscription_123",
    "operation": "downgrade",
    "timing": "end_of_period",
    "target_plan_code": "growth_monthly",
    "credit_action": "none",
}

preview = nozle.preview_subscription_transition(params)

transition = nozle.apply_subscription_transition(
    params,
    idempotency_key="transition-subscription-123-growth-v1",
)
```

Apply requires an idempotency key up to 255 UTF-8 bytes. See [Subscriptions](/guides/billing/subscriptions) for settlement options and validation rules.
