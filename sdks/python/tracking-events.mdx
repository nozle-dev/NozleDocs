title: "Tracking events"
description: "Send idempotent metered events and control subscription attribution with nozle.track()."

`nozle.track()` submits events to `base_url/api/v1/events`, defaulting to `https://api.nozle.app/engine/api/v1/events`. Subscription discovery uses `events_url/api/v1/subscriptions`.

```python
from nozle import Nozle

nozle = Nozle()  # reads NOZLE_SECRET_KEY

nozle.track(
    "workspace_123",
    "api_calls",
    metadata={"model": "example-model", "tokens": 1_500},
    subscription_id="workspace_123_subscription",
    transaction_id="request_0183f",
    timestamp="2026-08-04T10:30:00Z",
)
```

## Signature

```python
nozle.track(
    customer_id,
    event,
    metadata=None,
    subscription_id=None,
    transaction_id=None,
    timestamp=None,
)
```

| Argument | Description |
|---|---|
| `customer_id` | External Nozle customer ID. |
| `event` | Feature event code. |
| `metadata` | JSON-compatible aggregation or attribution properties. |
| `subscription_id` | Explicit external subscription target. |
| `transaction_id` | Stable event ID. A UUID is generated when omitted. |
| `timestamp` | Optional. RFC 3339 with an explicit offset or `Z`, or Unix seconds as a numeric string. Omit it and the server uses the time it received the event. |

<Warning>
A naive `datetime` without a timezone is rejected. `datetime.now().isoformat()` raises `NozleValidationError: track timestamp must be RFC3339 or Unix seconds` before any request. Use an aware value, for example `datetime.now(timezone.utc).isoformat()`.
</Warning>

## Subscription resolution

When `subscription_id` is omitted, the SDK queries the Events API for active subscriptions:

- one active subscription is cached and reused until the client changes that customer's subscriptions (see below);
- no active subscription raises `NozleAPIError` with `status_code` 422 and code `active_subscription_not_found` (`no active subscription for customer '…'`); and
- multiple active subscriptions raise `NozleAPIError` with `status_code` 422 and code `active_subscription_ambiguous` (`has 2 active subscriptions; specify subscription_id`) and require an explicit ID.

These are the codes the Engine uses for the same cases. Before `0.17.0` the `status_code` was 200.

From `0.10.0`, `subscribe()`, `checkout()`, `cancel_subscription()` and `apply_subscription_transition()` clear that customer's cached subscription, even when the call fails, so the next `track()` looks it up again. Earlier versions never refreshed the cache. `checkout_many` and the Entity calls do not clear it, because they act on Entity subscriptions. A change made outside this client instance still needs an explicit `subscription_id`. A second `subscribe` adds a subscription; it does not replace the first, and with two active subscriptions `track()` raises until you pass `subscription_id`.

<Warning>
Before `0.17.0` the lookup errors carried `status_code` 200, which is not an HTTP error status. Upgrade, or do not treat 200 as success when you check `status_code`.
</Warning>

Supply the subscription explicitly for customers with multiple subscriptions and latency-sensitive paths.

## Idempotency

Use a deterministic transaction ID and stable event timestamp for each logical event. Reuse both on retries.

```python
from datetime import datetime, timezone

transaction_id = f"generation:{generation_id}:completed"
timestamp = datetime.now(timezone.utc).isoformat()  # store it with the event and reuse it on retries

nozle.track(
    customer_id,
    "text_generation",
    metadata={
        "input_tokens": usage.input_tokens,
        "output_tokens": usage.output_tokens,
    },
    subscription_id=subscription_id,
    transaction_id=transaction_id,
    timestamp=timestamp,
)
```

A timeout, a network error or a `5xx` can arrive after Nozle recorded the event. Nozle records an event once per `transaction_id`, so a retry with the same ID, the same event and the same `timestamp` does not bill it twice; a new ID is a new event. From `nozle-sdk` 0.13.3, the error `track()` raises carries the ID it sent as `error.transaction_id` (on `NozleAPIError`, and on `NozleTransportError` for a network error or a timeout), also when the SDK generated it. Earlier versions lose a generated ID when the call raises, so pass your own `transaction_id` there. Pass a `timestamp` and keep it whenever you may retry.

```python
from datetime import datetime, timezone

from nozle import NozleError

timestamp = datetime.now(timezone.utc).isoformat()
try:
    nozle.track(customer_id, "api_call", subscription_id=subscription_id, timestamp=timestamp)
except NozleError as error:
    nozle.track(
        customer_id,
        "api_call",
        subscription_id=subscription_id,
        timestamp=timestamp,
        transaction_id=error.transaction_id,
    )
```

## Batching events

From `nozle-sdk` 0.24.0, `track_batch()` sends many events through Engine's `/events/batch`. It splits them into gzipped requests of up to 5000 events, sends several at once and returns one result per event. `AsyncNozle.track_batch()` is the same call, awaited. It needs Engine 2.28.0, which accepts gzip and 5000 events per request.

```python
result = nozle.track_batch(
    [
        {"customer_id": "workspace_123", "event": "api_calls", "metadata": {"tokens": 100}},
        {"customer_id": "workspace_456", "event": "api_calls", "timestamp": "2026-10-29T09:30:00Z"},
    ],
    chunk_size=5000,
    concurrency=4,
)

for r in result.results:
    if r.status == "rejected":
        print(r.index, r.errors)  # {"code": ["value_is_mandatory"]}
    elif r.status == "failed":
        print(r.index, r.transaction_id, r.error)  # resend with this transaction_id
```

- **Events.** Each event is a mapping with `customer_id`, `event` and optionally `subscription_id`, `metadata`, `transaction_id` and `timestamp`, the arguments of `track()`.
- **Size.** `chunk_size` is 1 to 5000 (default 5000) events per request, and `concurrency` is 1 to 64 (default 4) requests in flight (threads for `Nozle`, tasks for `AsyncNozle`). An Engine with a lower limit answers `too_many_events`; the SDK then splits that request in half and resends each half.
- **Result.** `TrackBatchResult(total, accepted, rejected, failed, results)`. `results[i]` belongs to `events[i]`: `accepted` (stored), `rejected` (Engine refused this event; `errors` maps a field to codes, and resending it unchanged fails again) or `failed` (its request failed, so the event may or may not be stored; `error` says why). `track_batch()` raises only for invalid arguments.
- **Partial batches.** Engine stores the valid events of a request and names the refused ones by position. An Engine before 2.28.0 refuses a whole request for one invalid event; the SDK then rejects the named events and resends the rest.
- **Idempotency.** Every event has a `transaction_id`, yours or a generated one returned in `results[i].transaction_id`. A request retried after a network error, a timeout, a `429` or a `5xx` records each event once. IDs must be unique in one call.

`track_batch()` records events like `track()`; it does not deduct credits. To batch events as they happen, use an [event buffer](#event-buffer).

## Event buffer

From `nozle-sdk` 0.28.0, `event_buffer()` returns a buffer that queues events in memory and sends them through `track_batch()` from a background thread. `buffer.track()` makes no request. It is available on `Nozle` (sync) only; `AsyncNozle` has no buffer yet.

```python
def report(error, events):
    # error.code: "buffer_full", "rejected", "failed" or "closed"
    print(error.code, [e["transaction_id"] for e in events], error.errors, error.__cause__)

buffer = nozle.event_buffer(on_error=report)
transaction_id = buffer.track("workspace_123", "api_calls", {"tokens": 100})

buffer.flush(timeout=10)  # send what is waiting now; False if it did not finish in time
buffer.close()            # flush, stop the thread, refuse later events

with nozle.event_buffer() as buffer:  # or close it with a with block
    buffer.track("workspace_123", "api_calls")
```

| Option | Default | Description |
|---|---|---|
| `max_batch_size` | `500` | 1 to 5000. A batch is sent as soon as this many events are waiting. |
| `flush_interval` | `5` | Seconds between timer flushes of whatever is waiting. `0` turns the timer off. |
| `max_queue_size` | `10000` | Most events held at once, waiting or in a request being sent. |
| `max_attempts` | `3` | Flushes an event may fail in before it is dropped and reported as `failed`. |
| `on_error` | warning | `on_error(error, events)` receives every event that leaves the buffer unsent. |

`event_buffer()` needs a secret key (`sk_`) and raises `NozleAuthenticationError` otherwise. An option out of range raises `NozleValidationError`.

- **`track()`** takes the arguments of `track()` (`customer_id`, `event`, `metadata`, `subscription_id`, `transaction_id`, `timestamp`) and returns the event's `transaction_id`: yours, or a generated UUIDv7. Every resend of the event keeps that ID, so Engine records it once. It raises `NozleValidationError` for a missing `customer_id` or `event` or a bad `timestamp`, before the event is queued.
- **When it sends.** A batch is sent when `max_batch_size` events are waiting, every `flush_interval` seconds, on `flush()`, on `close()` and when the process exits. Only one flush runs at a time; a size or timer trigger during a flush waits for it.
- **`flush(timeout=None)`** sends every event waiting now. It returns `True` once that is done and `False` when `timeout` seconds pass first. A failed event stays queued for the next flush.
- **`close(timeout=None)`** stops the timer, sends what is waiting and refuses later `track()` calls. It keeps flushing until the queue is empty, so a failed event is retried up to `max_attempts` and then reported. It returns `True` once the last event is sent or reported, and `False` on timeout; the background thread then keeps sending. Leaving a `with` block calls `close()` without a timeout.
- **`buffer.size`** is the number of events waiting, not counting a request being sent.
- **Bounded memory.** When `max_queue_size` events are held, `track()` drops the new event and reports it as `buffer_full`. It still returns the `transaction_id` and raises nothing.
- **Backoff.** After a flush in which any event failed, the size and timer flushes pause for 1 second. The pause doubles after each further flush with failures, up to 60 seconds. A flush without failures ends it. Events keep queueing meanwhile, up to `max_queue_size`, so an outage longer than a few flush intervals does not use up `max_attempts`. `flush()`, `close()` and the exit hook send at once, without waiting for the pause.

### Errors

No event leaves the buffer silently. `on_error` gets an `EventBufferError` with a `code`:

| `code` | Meaning |
|---|---|
| `buffer_full` | The queue held `max_queue_size` events. The new event was dropped. |
| `rejected` | Engine refused the event. `error.errors` maps a field to codes. It is reported one event at a time and is not resent. |
| `failed` | Its request still failed, after the retries of each `track_batch()` call, in `max_attempts` flushes. Until then a failed event goes back to the front of the queue with the same `transaction_id`. `error.__cause__` is the last request error. One report per flush. Also used for events not sent before the process exited. |
| `closed` | `track()` was called after `close()`. The event was dropped. |

Without `on_error`, each one is emitted as a `NozleTrackingWarning`. If `on_error` raises, the buffer emits the warning instead and keeps running. Calling `flush()` or `close()` from inside `on_error` returns `False` at once.

### Exit and serverless

The worker is a daemon thread. An `atexit` handler closes the buffer with a 5 second timeout and reports what it could not send as `failed`. `close()` removes the handler.

A function host may freeze or end the process as soon as your handler returns, before the timer or the exit hook runs. Call `buffer.flush()` (or `buffer.close()`) before you return.

The queue lives in memory only. Like `track_batch()`, the buffer makes no subscription lookup. The OpenAI and Anthropic wrappers and `capture_http_client()` still send each event on its own.

## FastAPI worker pattern

```python
from datetime import timezone

from fastapi import FastAPI

app = FastAPI()


@app.post("/events/generation-completed")
def generation_completed(event: GenerationCompleted) -> dict[str, bool]:
    nozle.track(
        event.customer_id,
        "text_generation",
        metadata={"tokens": event.tokens},
        subscription_id=event.subscription_id,
        transaction_id=f"generation:{event.id}:completed",
        timestamp=event.completed_at.astimezone(timezone.utc).isoformat(),  # timezone-aware, so the SDK accepts it
    )
    return {"accepted": True}
```

For high-volume workloads, enqueue your business event and call `track()` from a durable worker. An [event buffer](#event-buffer) batches events in the same process, but holds them in memory only. Use `usage.track()` instead when the operation must atomically enforce product credits.
