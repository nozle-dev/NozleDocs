```python
from nozle import Nozle

nozle = Nozle()  # reads NOZLE_SECRET_KEY

check = nozle.can("workspace_123", "api_calls")

if not check["allowed"]:
    raise PermissionError(check.get("reason", "Feature unavailable"))
```

## Metadata

Metadata is encoded as a JSON query parameter and may include numeric quantities required by a Cost Rule. It is input to the cost and margin estimate only. It does not filter usage: `used`, `limit` and `remaining` always cover all of the feature's usage, whatever `model` or other properties you send.

```python
check = nozle.can(
    "workspace_123",
    "model_access",
    {"model": "example-large-model", "region": "us-east"},
)
```

## Choose the subscription

A customer with several active subscriptions needs a selector, as in `nozle-sdk` 0.17.0 and later. `subscription_id` and `entity_id` (external IDs) are keyword-only arguments, on the sync and the async client:

```python
check = nozle.can("workspace_123", "seats", subscription_id="sub_team_a")
check = nozle.can("workspace_123", "seats", entity_id="entity_42")

# async client
check = await async_nozle.can("workspace_123", "seats", subscription_id="sub_team_a")
```

Without a selector, `can()` evaluates the customer's only subscription. When the customer has several and not exactly one is its own, the answer is not an exception: `can()` returns `allowed: False` with `reason: "subscription_required"`. Send `subscription_id` or `entity_id` to choose. See [The can() endpoint](/guides/entitlements/can-endpoint#which-subscription-is-checked).

## `CanResult`

| Field | Type | Description |
|---|---|---|
| `allowed` | `bool` | Whether the request may proceed. |
| `reason` | `str`, optional | Decision reason. |
| `used` | `int` | Current usage. |
| `limit` | `int`, optional | Configured limit. |
| `remaining` | `int`, optional | Remaining allowance. |
| `overage` | `bool`, optional | `True` when usage has reached a soft limit; the usage is billed as overage. Never a denial by itself. |
| `policy` | `CanPolicy`, optional | The margin policy version that decided the call, with its `decision` and `reason`. Present only when a policy covers the feature. See [Margin policy](#margin-policy). |
| `economics` | `dict`, optional | Point-in-time Cost Sheet estimate with exact decimal strings, Cost Rule version identifiers, and explicit exclusions. |
| `budget` | `Budget`, optional | 0.28.0, Engine 2.34.0. The spend limit that refused the call (`reason` `budget_exceeded`), else the tightest one covering the feature. See [Spend limits](#spend-limits). |

## Margin policy

When a [margin policy](/guides/margin/overview) covers the feature, `can()` returns `policy`, the policy version that decided the call. `CanResult["policy"]` is a `CanPolicy` typed dict.

| Field | Meaning |
|---|---|
| `mode` | What the policy does when the call is below its thresholds: `allow`, `warn` or `deny`. |
| `on_unavailable` | What it does when the economics cannot be estimated: `allow`, `warn` or `deny`. |
| `minimum_margin_amount`, `minimum_margin_percent`, `maximum_estimated_cost` | The thresholds of the policy; each is present only when set. |
| `maximum_snapshot_age_seconds` | An estimate older than this is `stale` and follows `on_unavailable`. |
| `decision` | `allow`, `warn` or `deny`: what the policy decided for this call. |
| `reason` | Why: `within_policy`, `minimum_margin_percentage_not_met`, `minimum_margin_amount_not_met`, `maximum_estimated_cost_exceeded`, `economics_not_configured`, `economics_unavailable`, `economics_stale`, `reporting_currency_mismatch` or `margin_percentage_unavailable_for_zero_revenue`. |

A `deny` is a refusal: `allowed` is `false` and `reason` is `economic_policy_denied`. A `warn` is **not** a refusal: `allowed` stays `true`, so read the policy `decision` to see it. The call never reaches the provider on a refusal, so deny before protected work and log or alert on a warning.

A feature with no Cost Rule has `economics.status` `not_configured`. The policy's `on_not_configured` setting (`allow`, `warn` or `deny`, default `allow`; Engine 2.39.0 and Core 11.24.0) decides it, and the `reason` is `economics_not_configured`. `on_unavailable` covers only real faults: a failed lookup, a stale estimate, a currency mismatch or zero revenue for a percentage threshold. Before those versions a feature with no Cost Rule followed `on_unavailable`, so an organization-wide `deny` also refused features that have no costs. The SDK types do not expose `on_not_configured` as a field yet; the `decision` and `reason` are in `policy`.

The estimate behind the decision is in `economics`: `estimated_incremental_cost`, `estimated_incremental_revenue`, `estimated_incremental_margin` and `estimated_margin_percent`, exact decimal strings. For a feature priced $0.10 per call with a $0.08 cost rule, the margin is `0.02` (20%), so a policy with a 50% minimum refuses it with `minimum_margin_percentage_not_met`.

```python
from nozle import RefusalReason

check = nozle.can("workspace_123", "llm_tokens")
if not check["allowed"] and check.get("reason") == RefusalReason.ECONOMIC_POLICY_DENIED:
    # check["policy"]["reason"], for example "minimum_margin_percentage_not_met";
    # check["economics"]["estimated_margin_percent"] is the margin that failed the policy
    ...
elif check.get("policy", {}).get("decision") == "warn":
    # allowed, but flagged: log it or alert
    ...
```

## Spend limits

Available from `nozle-sdk` 0.28.0 on `Nozle` and `AsyncNozle`, with Engine 2.34.0. When a hard [spend limit](/guides/entitlements/spend-limits) covering the feature is used up, `can()` returns `allowed: False` with `reason` `budget_exceeded` and the limit in `budget`. It does not raise. Compare `reason` with `RefusalReason`, never with message text:

```python
from nozle import RefusalReason

check = nozle.can("workspace_123", "llm_tokens")
if not check["allowed"] and check["reason"] == RefusalReason.BUDGET_EXCEEDED:
    budget = check["budget"]  # limit, spent, held, remaining, currency, period_end, status, ...
```

`RefusalReason` is a `str` enum with `FEATURE_NOT_FOUND`, `NO_SUBSCRIPTION`, `SUBSCRIPTION_REQUIRED`, `NO_ENTITLEMENT`, `USAGE_LIMIT_EXCEEDED`, `ECONOMIC_POLICY_DENIED`, `CUSTOMER_PAYMENT_OVERDUE`, `INSUFFICIENT_CREDITS` and `BUDGET_EXCEEDED`. Members equal their string, and results keep the plain string, so a reason a newer Engine adds passes through. `usage.check()` and `usage.track()` answer the same way, with `budget`. A soft limit never refuses.

### Read budgets

```python
result = nozle.budgets.list("workspace_123", subscription_id="sub_pro_123")
for budget in result["budgets"]:
    print(budget["feature_code"] or "total", budget["spent"], budget["limit"], budget["status"])
```

`budgets.list(customer_id, *, subscription_id=None)` calls [`GET /customers/{customer_id}/budgets`](/api/list-customer-budgets) and returns `BudgetList`: `customer_id`, `subscription_id` and `budgets`. Each `Budget` has `feature_code` (`None` for the total limit), `limit`, `spent`, `held`, `remaining` (decimal strings in major units), `currency`, `period`, `period_start`, `period_end`, `mode`, `status`, `as_of` and `counted_from` (0.29.0, Engine 2.38.0: when counting began). On `AsyncNozle`, `await nozle.budgets.list(...)`. Types: `Budget`, `BudgetList`, `BudgetPeriod`, `BudgetMode`, `BudgetStatus`.

For an exact cap under concurrent calls, take a [budget hold](/sdks/python/credits#budget-holds) instead of a plain `can()`.

## FastAPI pattern

```python
from fastapi import HTTPException

check = nozle.can(customer_id, "analytics")

if not check["allowed"]:
    raise HTTPException(
        status_code=403,
        detail={
            "reason": check.get("reason", "upgrade_required"),
            "used": check["used"],
            "limit": check.get("limit"),
            "remaining": check.get("remaining"),
        },
    )

if check.get("overage"):
    # Allowed: a soft limit is reached, so this usage is billed as overage.
    warn_about_overage(customer_id, check)
```

Deny only when `allowed` is `False`. `overage` set to `True` never denies by itself: a soft limit is reached and the usage is billed as overage.

Perform this check immediately before protected server work. React gates are not an authorization boundary. `can()` also does not reserve product credits; use `usage.track()` for atomic consumption.
