---
title: "LLM auto-capture"
description: "Wrap synchronous or asynchronous OpenAI and Anthropic clients to emit a Feature Event and optional detailed Cost Events."
---

The wrappers patch `chat.completions.create` (OpenAI) and `messages.create` (Anthropic) in place and preserve their normal return value. The OpenAI Responses API (`responses.create`) is not wrapped. They support synchronous calls, asynchronous calls, synchronous streams, and asynchronous streams. When `cost_meter_code` is configured, each call emits categorized Cost Events linked to its Feature Event.

Only model, token counts, latency, and an optional feature tag are sent. Prompt and completion content are not captured.

## OpenAI

```bash
pip install "nozle-sdk[openai]"
```

```python
import os
from openai import OpenAI

from nozle import Nozle, wrap_openai

nozle = Nozle(
    api_key=os.environ["NOZLE_SECRET_KEY"],
    base_url="https://api.nozle.app/engine",
    events_url="https://api.nozle.app/core",
)

openai = wrap_openai(
    OpenAI(),
    nozle,
    customer_id="workspace_123",
    metric_code="llm_tokens",
    cost_meter_code="ai_tokens",
    feature="assistant_reply",
)

response = openai.chat.completions.create(
    model="example-chat-model",
    messages=[{"role": "user", "content": "Hello"}],
)
```

### OpenAI streaming

The wrapper sets `stream_options.include_usage` to `true` so the final stream chunk contains token counts. Only `include_usage` is overwritten; other `stream_options` keys you pass are kept.

```python
stream = openai.chat.completions.create(
    model="example-chat-model",
    messages=[{"role": "user", "content": "Explain vector search"}],
    stream=True,
)

for chunk in stream:
    print(chunk.choices[0].delta.content or "", end="")
```

## Anthropic

```bash
pip install "nozle-sdk[anthropic]"
```

```python
from anthropic import Anthropic

from nozle import Nozle, wrap_anthropic

anthropic = wrap_anthropic(
    Anthropic(),
    nozle,
    customer_id="workspace_123",
    metric_code="llm_tokens",
    cost_meter_code="ai_tokens",
    feature="assistant_reply",
)

message = anthropic.messages.create(
    model="example-anthropic-model",
    max_tokens=1_024,
    messages=[{"role": "user", "content": "Hello"}],
)
```

Anthropic streams read input usage from `message_start` and output usage from `message_delta` events.

## Wrapper arguments

| Argument | Required | Default | Description |
|---|---|---|---|
| `client` | yes | — | OpenAI or Anthropic client instance. |
| `nozle` | yes | — | Configured `Nozle` client. |
| `customer_id` | yes | — | Customer passed to `track()`. |
| `metric_code` | no | `llm_tokens` | Event code. |
| `cost_meter_code` | no | `None` | Cost Event Meter code. When set, emits categorized token Cost Events linked to the Feature Event. |
| `feature` | no | `None` | Optional event property. |

## Tracked properties

```json
{
  "provider": "openai",
  "model": "example-chat-model",
  "input_tokens": 320,
  "output_tokens": 84,
  "latency_ms": 742,
  "feature": "assistant_reply"
}
```

The Feature Event preserves total input and output counts. Detailed Cost Events use canonical properties `{ tokens, provider, model, type }` and one of these non-zero categories:

- OpenAI: `input`, `cached_input`, `output`, and `reasoning`.
- Anthropic: `input`, `cached_input`, `cache_write`, and `output`.

Cost calculation remains server-side through the `ai_tokens` Cost Event Meter and effective-dated provider/model/category Cost Rules.

## Failure behavior

The wrappers generate the Feature Event `transaction_id` before delivery and use it as `parent_transaction_id` on every detailed Cost Event. Parent and child events may therefore arrive out of order. Tracking failures do not replace a successful provider result; the SDK emits `NozleTrackingWarning`.

The warning names only the exception type, not the cause, for example `Nozle tracking failed after a successful LLM response (NozleAPIError)`. A customer with several active subscriptions makes every wrapped call emit it. Under `python -W error`, the SDK swallows the warning instead of raising it.

The synchronous wrapper tracks inline: each wrapped call waits for one tracking request (about 255 ms observed). With `cost_meter_code`, it sends several requests per call. For async provider calls, synchronous Nozle tracking runs in a worker thread through `asyncio.to_thread()`.

The wrapper does not expose `subscription_id`, so `track()` resolves the customer's single active subscription. Use manual queued tracking when you need to choose the transaction identifier or coordinate delivery through your own queue.

```python
response = provider_call()

nozle.track(
    "workspace_123",
    "llm_tokens",
    metadata={
        "model": response.model,
        "input_tokens": response.input_tokens,
        "output_tokens": response.output_tokens,
    },
    subscription_id="workspace_123_subscription",
    transaction_id=f"llm:{response.id}:usage",
)
```

## Manual cost events

Use `nozle.cost_events.track()` for providers without a wrapper and for cost-only tracking. A Cost Event never bills the customer.

```python
nozle.cost_events.track(
    cost_meter_code="ai_tokens",
    external_customer_id="workspace_123",        # or parent_transaction_id=<Feature Event id>
    cost_event_id=f"turn:{turn.id}:input",       # stable per unit, reused on retry
    properties={"tokens": 900, "provider": "openai", "model": "configured-model-a", "type": "input"},
    timestamp=turn.created_at.timestamp(),       # a float, Unix seconds
)
```

| Argument | Description |
|---|---|
| `cost_meter_code` | Required. Cost Event Meter code. |
| `parent_transaction_id` | Feature Event `transaction_id` to link to. |
| `external_customer_id` | Customer ID. Pass this or `parent_transaction_id`. |
| `cost_event_id` | Stable event ID. Generated when omitted. |
| `request_id` | Optional provider request ID. |
| `operation_key` | Optional operation label. |
| `properties` | JSON-compatible properties, for example `{tokens, provider, model, type}`. |
| `timestamp` | Optional `float` of Unix seconds. An ISO string returns `400 invalid request body`. |

- Requires an `sk_` key.
- Without `parent_transaction_id` or `external_customer_id`, it raises `NozleValidationError` before any request.
- Returns `{"status": "accepted", "cost_event_id": ...}` after a `202`.
- The same `cost_event_id` sent twice returns `202` both times. Processing de-duplicates it.

<Warning>
An unknown `cost_meter_code` is accepted with `202` and never reported. Check the code against your Cost Event Meters; a typo loses the cost silently.
</Warning>
