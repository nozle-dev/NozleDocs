### Nozle Agent Kit 1.0.4

_October 18, 2026_

- [Agent Kit 1.0.4](https://github.com/nozle-dev/nozle-agent-kit/releases/tag/v1.0.4) follows the SDK releases of October 17. On Node, the agent captures LLM usage with `captureFetch()` for any client that accepts a custom `fetch`, including the Vercel AI SDK, LangChain and Gemini. On Python and Go, it captures through the provider's HTTP client. It serves billing screens through `createBillingHandler()` and the React billing hooks, verifies webhooks with the SDK helpers, and reads errors by `NozleApiError` status and code.
- It also follows the current API: plan families, `change_at` and pay-first plan changes, 422 for an event that matches no active subscription or several, and `null` limits from `can()`.
- The guards block a client file that imports `@nozle-js/node`, and treat capture helpers like the LLM wrappers when they check for double billing.
- To update, see [Install and update](/guides/agent-kit/install#update). Codex CLI users run the `hosts codex --write` command again in each app, because the hook path contains the version.

### Node.js SDK 0.13.0

_October 17, 2026_

- [`@nozle-js/node` 0.13.0](https://github.com/nozle-dev/nozle-js/releases/tag/node-v0.13.0): `new Nozle()` reads `NOZLE_SECRET_KEY` when you pass no `apiKey`. The `host` option (default `https://api.nozle.app`) fills in `baseUrl` and `eventsUrl`. Opt-in retries with `maxRetries` and `retryDelayMs` repeat only requests that are safe to repeat. See [Installation](/sdks/node/installation).
- Every call that gets a non-2xx response throws `NozleApiError`, which now carries `requestId` and `retryAfter`. The message keeps its `<operation> failed: <status> <statusText>` form and the class still extends `Error`. See [Errors and retries](/sdks/node/errors).
- `captureFetch()` returns a `fetch` that records the token usage of OpenAI-compatible, Anthropic and Gemini responses, for any client that accepts a custom `fetch`. `recordUsage()` records usage your code read itself. Capture reports `feature_not_found` once per event code through `onError` when no Feature has that code. See [LLM auto-capture](/sdks/node/llm-auto-capture).
- `getSubscriptions()`, `currentUsage()` and `pastUsage()` read Core subscriptions and usage. The `invoices` namespace lists invoices (with `paymentOverdue` and other filters), reads one and returns its PDF URL. The `alerts` namespace manages usage and wallet balance alerts. See [Billing](/sdks/node/billing#read-usage).
- `webhooks.verify()` and `createWebhookHandler()` check the `X-Nozle-Signature` of the webhooks Nozle sends. See [Receive Nozle webhooks](/api/receive-webhooks).
- `createBillingHandler()` serves the React billing hooks from your backend with your secret key; the customer always comes from your session. See [Provider and hooks](/sdks/react/hooks).
- Fixed: `wrapOpenAI` and `wrapAnthropic` keep the SDK's own `APIPromise` and `Stream`, so `withResponse()`, `asResponse()`, `chat.completions.parse()`, `messages.stream()` / `finalMessage()`, `stream.controller` and `toReadableStream()` work on a wrapped client. Usage is recorded once, when the response is read (not for `asResponse()`); a stream records when it is fully iterated. The optional peer dependency is `@anthropic-ai/sdk`. `checkAndDeduct()` is deprecated: use `usage.check()` and `usage.track()` with a credit system. See [LLM auto-capture](/sdks/node/llm-auto-capture#client-wrappers).
- Usage events recorded by `wrapOpenAI`, `wrapAnthropic` and `captureFetch` use the provider's response id as the transaction id, so the same response is never recorded twice.
- Fixed: `usage.track()` reuses the timestamp it filled in when the same idempotency key is sent again on the same client, so a retry no longer fails with `409 idempotency_key_reused`.
- **Breaking:** `CanResult.limit` and `CanResult.remaining` are typed `number | null`, `null` when the feature has no limit. Code that checked `=== undefined` should check `== null`. `PingResult.version` and `SubscriptionOptions.blocked_reason` are removed from the types; the API never sent them.
- Install with `npm install @nozle-js/node@0.13.0 @nozle-js/react@0.11.0 @tanstack/react-query`.

### Error statuses and checkout fixes

_October 17, 2026_

- **Breaking:** a request that the resource's current state refuses now returns `422` instead of `405`, with the same `code` (for example `not_voidable` or `plan_transition_policy_required`). A conflict with another operation in progress returns `409`. The SDKs branch on `code`, so their behavior is unchanged. See [Errors](/api/errors).
- Bad bodies and unreachable dependencies return JSON errors with a `code` instead of `500`: `400 bad_request`, `502 upstream_unavailable`.
- Checkout charges only through the connection assigned to the customer, for single and bulk Entity checkout, and returns `422 payment_provider_required` otherwise. Customer create keeps `payment_provider` and `payment_provider_code` without `sync_with_provider`.
- Checking out the same plan again reopens an abandoned new-subscription checkout; a different plan replaces it and returns the new checkout. `409 subscription_checkout_in_progress` (`entity_subscription_checkout_in_progress` for an Entity) remains only while the provider is still processing a payment for the old checkout.
- Stripe: a reused invoice checkout key returns `409 idempotency_key_reused`; a rejected webhook URL sends `payment_provider.error`; `payment_method.detached` clears the stored default. Razorpay credentials are checked when you connect.

### Usage, credits and checkout fixes

_October 17, 2026_

- The [LLM proxy](/api/llm-proxy#subscription) finds the subscription to bill before it calls the provider, and its usage event carries that `external_subscription_id`, so proxy usage is billed. A customer with several active subscriptions needs the new `X-Nozle-Subscription` header, which is not forwarded. A customer with no matching active subscription returns `422 active_subscription_not_found`, several without the header `422 active_subscription_ambiguous`; the provider is not called.
- `POST /events` and `/events/batch` accept `external_customer_id` without `external_subscription_id`: the event is billed to the customer's single active subscription. No or several active subscriptions return `422 active_subscription_not_found` or `422 active_subscription_ambiguous` (in a batch, under the event's position). An event with neither id returns `422 validation_errors` with `external_subscription_id: ["value_is_mandatory"]`. See [Events](/api/events).
- `can()` estimates revenue for the units of the call: 1 for a count Feature, the Feature's `field_name` value in `metadata` for a sum Feature. Other aggregations, or a sum call without that value, report economics `unavailable`, and the margin policy's `on_unavailable` decides. See [economics](/guides/entitlements/can-endpoint).
- The deprecated [Check & Deduct](/api/check-and-deduct) moves the wallet's money balance with the credits: `balance_cents`, the ongoing balance and the consumed amount change by credits × the wallet rate, and the wallet transaction amount is that money amount.
- Paid credit top-ups grant their credits when the top-up invoice is fully paid, by any route: a card or provider payment, a manual payment for the full amount, a payment request, or marking the invoice paid. A partial manual payment grants nothing until the invoice is fully paid. See [Paid Credit Top-ups](/guides/credits/top-ups).
- An unpaid plan or single Entity checkout expires after 23 hours, like an Entity checkout batch: the subscription is canceled with `cancelation_reason: timeout` (`subscription.canceled` webhook), the payment-gated invoice is closed, and the Stripe Checkout Session or Razorpay order expires. The coupons, credit-note credits and wallet credits the invoice used are returned when the checkout expires or its payment fails. See [Unpaid checkout expiry](/api/create-checkout#unpaid-checkout-expiry).
- Stripe invoice checkout and invoice payment URLs refuse an invoice that is paid, voided, draft, closed, failed or has nothing due with `invalid_invoice_status_or_payment_status`, as Razorpay already did.
- A paid upgrade checkout returns `409 subscription_change_pending` while the subscription has a scheduled cancellation or plan change. Cancelling at period end, scheduling a plan change or applying an immediate downgrade cancels an open upgrade checkout and expires its Stripe Checkout Session or Razorpay order.
