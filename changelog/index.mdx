## October 2026

### React themes

_Unreleased_

- `@nozle-js/react` `0.11.0` adds `appearance` on `BillingProvider` and every component, with predefined themes from `@nozle-js/react/themes`: `light`, `dark`, `system`, `shadcn`, `minimal` and `neobrutal`. See [Appearance](/sdks/react/styling).
- Components render without Tailwind. `PricingTable` marks contact-sales plans from `contactSalesPlans` instead of their names. Upgrade notes are on the Appearance page.

### Error statuses and checkout fixes

_Unreleased_

- **Breaking:** a request that the resource's current state refuses now returns `422` instead of `405`, with the same `code` (for example `not_voidable` or `plan_transition_policy_required`). A conflict with another operation in progress returns `409`. The SDKs branch on `code`, so their behavior is unchanged. See [Errors](/api/errors).
- Bad bodies and unreachable dependencies return JSON errors with a `code` instead of `500`: `400 bad_request`, `502 upstream_unavailable`.
- Checkout charges only through the connection assigned to the customer, for single and bulk Entity checkout, and returns `422 payment_provider_required` otherwise. Customer create keeps `payment_provider` and `payment_provider_code` without `sync_with_provider`.
- Checking out the same plan again reopens an abandoned new-subscription checkout; a different plan returns `409 subscription_checkout_in_progress`.
- Stripe: a reused invoice checkout key returns `409 idempotency_key_reused`; a rejected webhook URL sends `payment_provider.error`; `payment_method.detached` clears the stored default. Razorpay credentials are checked when you connect.

### Link existing Stripe customers from the SDKs

_October 14, 2026_

- Customer upsert accepts a billing configuration, so a customer can be created and linked to an existing Stripe customer (`cus_…`) in one call, without a separate REST request. Nozle stores the link and creates nothing in Stripe; repeating the upsert is safe.
- [`@nozle-js/node` 0.12.0](https://github.com/nozle-dev/nozle-js/releases/tag/node-v0.12.0): `customers.upsert({ billingConfiguration })`. [`nozle-sdk` 0.12.0](https://github.com/nozle-dev/nozle-python/releases/tag/v0.12.0): `customers.upsert(..., billing_configuration=...)`. [`github.com/nozle-dev/nozle-go` v0.11.0](https://github.com/nozle-dev/nozle-go/releases/tag/v0.11.0): `Customer.BillingConfiguration`.
- Upserts without it send the same request as before. See [Customers and Entities](/sdks/node/customers-entities#link-a-customer-that-already-exists-in-stripe) and [Assign the connection to customers](/integrations/stripe#assign-the-connection-to-customers).
- Install with `npm install @nozle-js/node@0.12.0`, `pip install nozle-sdk==0.12.0` or `go get github.com/nozle-dev/nozle-go@v0.11.0`.

### Nozle Agent Kit

_October 13, 2026_

- Released the [Nozle Agent Kit](/guides/agent-kit/overview), skills and guard hooks that let Claude Code, Codex CLI, and OpenCode integrate Nozle billing into your application. The agent reads your account through a read-only OAuth connection and edits only the files you approve.

- See [Install and update](/guides/agent-kit/install) and [Run an integration](/guides/agent-kit/workflow).

### Go event ingestion through Engine

_October 13, 2026_

- Node `0.11.0`, Python `0.11.0`, and Go `v0.10.0` send Feature Events to `https://api.nozle.app/engine/api/v1/events`. Go batches use `/engine/api/v1/events/batch`.
- Configure the Engine base URL for custom event ingestion. Core URL settings continue to control billing resources and subscription discovery. Event payloads, secret-key authentication, and transaction IDs are unchanged.
- Updated the [Events API](/api/events), SDK setup/tracking guides, and OpenAPI event creation operations to use Engine.

### Razorpay and Stripe guides, new SDK releases, API fixes

_October 13, 2026_

- Added a [Razorpay integration guide](/integrations/razorpay) and expanded the [Stripe integration guide](/integrations/stripe) to the same depth: connection setup, webhooks, checkout and retry behavior, refunds, errors and testing.
- Added the [public plan catalog reference](/api/list-plans).
- Released [`@nozle-js/node` 0.10.0](https://github.com/nozle-dev/nozle-js/releases/tag/node-v0.10.0) on npm and [`nozle-sdk` 0.10.0](https://github.com/nozle-dev/nozle-python/releases/tag/v0.10.0) on PyPI. Both add typed API errors (`NozleApiError` and `code` in Node, `NozleAPIError.code` and `has_code()` in Python), richer checkout result types, and Stripe and Razorpay README sections. `check-and-deduct` no longer needs `feature`.
- Released [`@nozle-js/react` 0.10.2](https://github.com/nozle-dev/nozle-js/releases/tag/react-v0.10.2) with the same checkout result types and a Stripe and Razorpay README section.
- Released [`github.com/nozle-dev/nozle-go` v0.9.1](https://github.com/nozle-dev/nozle-go/releases/tag/v0.9.1) with `APIError.Code()` and `HasCode()`, richer `CheckoutResult` fields, and a Stripe and Razorpay README section. `Consume` and `LLM` are removed, because their routes do not exist on the hosted service.
- Node.js 0.10.0 and Python 0.10.0 clear a customer's cached subscription after their own `subscribe`, `checkout`, cancel and plan-change calls, so `track()` no longer keeps using a stale subscription. `pending_subscription_id` is removed from the Node.js, Python and React scheduled checkout result types (the pending subscription is `subscription_id`). React 0.10.2 `PricingTable` shows `Plans could not be loaded: <reason>` when its catalog request fails. Go v0.9.1 removes `URL`, `PublishableKey`, `StripeAccount` and `PendingSubscriptionID` from `CheckoutResult` (checkout never returned them).
- **Breaking:** Node 0.10.0, Python 0.10.0 and Go v0.9.1 read `nozle_id` for credit systems. Ship them together with the server release that sends `nozle_id`; against an older server the credit system ID is empty or the call fails.
- `POST /subscribe` returns `404 customer_not_found` for an unknown customer instead of creating an empty one. See [Subscribe](/api/subscribe).
- Margin and analytics date ranges accept `YYYY-MM-DD` or RFC 3339, plus `from_date` and `to_date`. A plain-date `to` includes the whole day, and an invalid or reversed range returns `400 invalid_date_range`.
- Corrected the documentation for entitlement `reason` values, the required usage `timestamp`, credit balance decimals, the credit operations `limit` range, the margin simulate request, unknown cost meters and trend granularity.
- Install with `npm install @nozle-js/node@0.10.0 @nozle-js/react@0.10.2`, `pip install nozle-sdk==0.10.0` or `go get github.com/nozle-dev/nozle-go@v0.9.1`.

### Cost Intelligence foundation

- Added versioned Cost Sheets, Cost Event Meters, and historical Feature cost-composition modes.
- Added exact-decimal Feature Event and Detailed Cost Event rating with durable PostgreSQL ledger entries and rebuildable ClickHouse projections.
- Replaced legacy whole-cent `/can` margin fields with a side-effect-free `economics` estimate that identifies rule versions and unknown future costs.

- Added guarded replay tools for uncosted sources and failed ClickHouse projections, plus PostgreSQL-backed `/can` snapshots with disposable Redis caching.

## August 2026

_Updated through August 8, 2026._

### Tenant-safe customer provisioning

- Routed Node.js and Python `customers.upsert()` calls directly to Nozle Core using the merchant's secret key.
- Removed master-organization authentication from the Engine customer compatibility endpoint.
- Added local SDK validation and tenant-isolation regressions for customer provisioning.
- Verified Node.js and Python customer creation against the Pullse Testing production organization with disposable canaries.

### Mixed Entity checkout and billing anchors

- Added one-invoice, one-payment checkout for mixed Entity plan baskets of up to 100 Entities.
- Added a stable customer-level Entity billing anchor established only after the first successful paid checkout.
- Added anniversary-aligned proration for Entity plans purchased after the anchor is established.
- Added replay-safe checkout batches and fail-closed protection for concurrent first-paid checkouts.
- Clarified that paid top-ups enter the customer pool and are allocated explicitly to Entities.

### Entity-owned subscriptions and SDK 0.5.0

- Added independent subscriptions for customer Entities, including mixed monthly and annual plans under one paying customer.
- Added Entity-scoped checkout, plan changes, end-of-period cancellation, stable subscription identities, and payment-gated activation.
- Added suspended, deleted, and recreated Entity protection so stale identities cannot inherit billing state.
- Released the backend integration surface in `@nozle-js/node` 0.5.0 and `nozle-sdk` 0.5.0.
- Verified the Core API and published Python SDK against production with reversible Entity-subscription canaries.

### Subscription settlement controls

- Added preview and apply APIs for cancellation, downgrade, and uncancel transitions.
- Added merchant-controlled timing, billing-anchor, proration, credit, refund, offset, and final-invoice policies.
- Added idempotent transition application so uncertain requests can be retried safely.
- Released the settlement controls in `@nozle-js/node` 0.4.2 and `nozle-sdk` 0.4.2.

### Developer experience

- Completed the React, Node.js, and Python SDK references with current signatures and security guidance.
- Added rendered React component previews and a dedicated theming reference.
- Replaced customer-specific examples with neutral, reusable integration examples.
- Restored the complete Nozle Billing API reference with generated request, response, and schema documentation.

## July 2026

### Product credits

- Introduced exact-decimal credit systems, plan grants, paid top-ups, immutable balance sources, and operation history.
- Added advisory usage checks and atomic, idempotent credit consumption.
- Added durable usage-event publication and reconciliation so committed deductions survive downstream outages.
- Added customer and Entity balance APIs, per-Entity grants, shared-pool policies, and top-up allocation/deallocation.

### Payment-first billing

- Paid plan changes now preserve the current plan until payment succeeds.
- Added payment-aware checkout results for hosted Stripe, embedded Stripe, immediate completion, and scheduled changes.
- Added durable upgrade webhook processing and support for end-of-period cancellation.
- Added merchant-configurable billing anchors and transition-policy defaults.

### Security and tenancy

- Restricted publishable keys to the public plan catalog.
- Moved customer billing operations behind authenticated merchant backends and least-privilege secret keys.
- Hardened customer, organization, mutation, and internal service authorization.
- Removed automatic seat billing from Entity lifecycle changes; merchants now emit explicit, idempotent seat events.

### SDKs and dashboard

- Added product-credit and Entity APIs to the Node.js and Python SDKs.
- Refactored React checkout around merchant-owned callbacks and forwarded validated return URLs to Stripe.
- Added customer and Entity credit dashboards, paid top-up checkout, and refreshed analytics and settings interfaces.
