title: "Set up AI token billing"
description: "What to create in Nozle before LLM usage capture bills tokens, records their cost and shows margin."

Usage capture ([Node.js](/sdks/node/llm-auto-capture), [Python](/sdks/python/llm-auto-capture), [Go](/sdks/go/llm-usage), or the [LLM proxy](/api/llm-proxy)) only records events. Each LLM response becomes one usage event:

```json
{
  "code": "llm_tokens",
  "transaction_id": "llm-openai-chatcmpl-123",
  "external_customer_id": "workspace_123",
  "external_subscription_id": "sub_123",
  "properties": {
    "provider": "openai",
    "provider_host": "api.openai.com",
    "model": "gpt-4o-mini",
    "input_tokens": 1200,
    "output_tokens": 400,
    "latency_ms": 840
  }
}
```

What that event does depends on what you set up. Nozle accepts an event whose code matches no Feature and stores it, but it is never billed, costed or shown in margin. The dashboard event debugger shows it as "No meter matches the event code", and SDK capture reports it once per event code to your error callback as `feature_not_found`.

## 1. Bill tokens

1. **Create a metered Feature with the event code.** In **Usage → Meters → New**, set **Event code** to the code your capture sends: `llm_tokens` by default, or your `featureCode` / `X-Nozle-Feature-Code`.
   - **Method** Sum, **Value property** `total_tokens`, **Expression** `event.properties.input_tokens + event.properties.output_tokens`. The expression writes the sum into `total_tokens` before the event is stored.
   - To charge more for output tokens, weight them in the expression, for example `event.properties.input_tokens + event.properties.output_tokens * 4`, and price per weighted token. One event code maps to one Feature, so a weighted expression is how one event carries both prices.
   - To bill only one side, skip the expression and set **Value property** to `input_tokens` or `output_tokens`.
   - A Feature with an expression cannot be used with [product credits](/guides/credits/overview).
2. **Charge for it on the plan.** Add a usage charge for the Feature, for example package pricing per 1,000,000 tokens. Add an entitlement limit if you want [`can()`](/guides/entitlements/can-endpoint) to stop customers at a limit. See [plans](/guides/billing/plans).
3. **Give each customer one active subscription.** The usage event is billed to a subscription. Capture looks up the customer's single active subscription and records nothing for a customer with none or several. Pass a subscription id when a customer has several. The [LLM proxy](/api/llm-proxy#subscription) looks it up before it calls the provider and refuses the call with `422 active_subscription_not_found` or `422 active_subscription_ambiguous`; send `X-Nozle-Subscription` when a customer has several.

Usage counts towards the current period as soon as the event is processed. Revenue appears in margin reports when the invoice is finalized.

## 2. Record the cost of tokens and see margin

1. **Create a cost model from the AI tokens template** (**Usage → Cost models → New**, cost path **Detailed Cost Event**). It creates the Cost Event Meter `ai_tokens` (sum of `tokens`, filtered by `provider`, `model` and `type`). Enter your rate for each token type: input, output, and optionally cached input, cache write and reasoning.
2. **Link it to the usage Feature.** Set **Linked feature** to your token Feature (for example `llm_tokens`) and the composition to **Detailed events only**, then publish. With **Linked feature** set to none, each token cost event is still rated on its own meter and attributed to the customer, subscription and Feature of the usage event it points to, and counts in margin; the usage event itself stays uncosted with `missing_cost_composition`. A cost event for another customer than its parent is uncosted as `parent_customer_mismatch`, and one whose parent never resolved as `parent_attribution_failed`. Cost events recorded before this behavior are not rated again by themselves: replay the parent usage event, then its cost events. Linking a Feature is still the way to get a composition and the `can()` estimate.
3. **One cost model per provider and model you use.** The template's conditions must equal the `provider` and `model` values the capture sends (`provider` is the response format: `openai`, `anthropic` or `gemini`). A model without a matching rule is listed as uncosted with `no_matching_cost_rule`.
4. **Turn on cost events in capture.** Set `costMeterCode: "ai_tokens"` (Node.js), `cost_meter_code="ai_tokens"` (Python) or `CostMeterCode: "ai_tokens"` (Go). Each response then also sends one cost event per token type, linked to its usage event.
5. **Check for uncosted events** in the cost intelligence report or the Uncosted queue after the first calls. See [cost models](/guides/margin/cost-models).

For `can()` to return an estimated cost and margin before work starts, also add Feature Event cost components on the token Feature, set the composition to **Add both**, and use a standard charge. Without them `can()` reports economics as `not_configured`.

## 3. Credits instead of invoices

Usage capture does not spend [product credits](/guides/credits/overview). To deduct credits per call, make the Feature consumable (**Count**, or **Sum** on a property without an expression), give it a credit system rate, and call `usage.track()` with the token count after the LLM call instead of relying on capture. See [credit usage tracking](/guides/credits/usage-tracking).

## Token buckets

Every token is counted once, in one of these disjoint buckets. SDKs and the proxy split the provider response into them. The `type` of a cost event is the bucket name, and a cost rule prices one bucket.

| Bucket (`type`) | Meaning | OpenAI | Anthropic | Gemini |
|---|---|---|---|---|
| `input` | Text input not in another bucket | `prompt_tokens` minus cached, audio | `input_tokens` | `promptTokenCount` minus cached, audio, image |
| `cached_input` | Cache read | `prompt_tokens_details.cached_tokens` | `cache_read_input_tokens` | `cachedContentTokenCount` |
| `cache_write` | Cache write, default 5 minute TTL | `prompt_tokens_details.cache_write_tokens`, if present | `cache_creation_input_tokens` minus the 1 hour part | none |
| `cache_write_1h` | Cache write, 1 hour TTL | none | `cache_creation.ephemeral_1h_input_tokens` | none |
| `output` | Text output without reasoning and audio | `completion_tokens` minus reasoning, audio | `output_tokens` | `candidatesTokenCount` minus audio, image |
| `reasoning` | Thinking tokens | `completion_tokens_details.reasoning_tokens` | none reported; stays in `output` | `thoughtsTokenCount` |
| `audio_input`, `audio_output` | Audio | `*_details.audio_tokens` | none | `promptTokensDetails` and `candidatesTokensDetails`, modality `AUDIO` |
| `image_input`, `image_output` | Images | none today | none | same, modality `IMAGE` |
| `batch_input`, `batch_output` | Whole call billed at the batch tier | batch API calls | message batches | batch mode |

The input-side buckets add up to the call's total input, and the output-side buckets to its total output. A bucket larger than its total is clamped by Engine, so a client bug cannot make buckets exceed the totals. A batch-tier call moves its `input` and `output` into `batch_input` and `batch_output`; its other buckets keep their names. Server tool use such as web search is not tokens and is not counted.

### Usage event properties

The usage event carries the totals and the breakdowns. A breakdown is left out when it is 0.

| Property | Meaning |
|---|---|
| `input_tokens`, `output_tokens` | Total input and output, inclusive of every bucket |
| `cached_input_tokens`, `cache_write_tokens`, `cache_write_1h_tokens`, `reasoning_tokens` | Breakdowns of the totals |
| `audio_input_tokens`, `audio_output_tokens`, `image_input_tokens`, `image_output_tokens` | Modality breakdowns of the totals |
| `service_tier` | `batch` or `standard`. Left out means standard. |
| `usage_source` | `reported` (the provider sent the usage) or `estimated` |
| `stream_aborted` | `true`, only when the stream ended before the provider's final usage |

A per-model cost model (legacy) rates by bucket. Optional rates `cache_write_1h`, `reasoning`, `audio_input` and `audio_output` fall back when missing: `cache_write_1h` to `cache_write`, then input; `audio_input` to input; `reasoning` and `audio_output` to output. Image tokens use the input and output rates.

### Cost events per bucket

One cost event is sent for each non-zero bucket, with `cost_event_id` `<usage transaction_id>:<bucket>`, `operation_key` `<bucket>` and properties `{ tokens, provider, model, type }`. The SDKs send them when you set the cost meter code (see step 4 above). The [LLM proxy](/api/llm-proxy#cost-events) sends them when the request has the header `X-Nozle-Cost-Meter: <meter code>`, where the code belongs to a Detailed Cost Event meter such as `ai_tokens`. Without the header, the proxy sends only the usage event. SDK and proxy use the same ID shape, so a retry never rates a bucket twice. A `cache_write_1h` price entry needs Core 11.30.0.

## Aborted streams

A stream can end before the provider sends its final usage: the client disconnects, or the upstream stops. Nozle bills what was delivered instead of nothing.

- If the provider reported usage before the cut, that usage is used. Anthropic reports about 1 output token at the start of a stream, so its output is raised to the estimate of the delivered text when that is larger.
- If the provider reported nothing, as OpenAI does on a cut stream, Nozle estimates: `ceil(UTF-8 bytes / 4)`, of the request text for input and of the delivered text for output. A client wrapper that only sees the response estimates output only and reports input 0.
- The usage event has `usage_source` set to `reported` or `estimated`, and `stream_aborted: true`.
- A credit or budget hold on the call is finalized with that usage. Before, a cut stream released the hold, which made the call free.

The estimate is coarse by design. The `usage_source` property lets you tell estimated usage from reported usage.

<Warning>
The option to waive billing for aborted streams is not available yet. Aborted streams are always billed as described. Providers do not document how they bill a client abort, so the provider's own charge for the cut call can differ from the estimate.
</Warning>

## Uncosted models

When an LLM call is rated and no cost rule prices it, Nozle records the provider, model and token bucket. An LLM call is an event whose `properties.model` is a non-empty string. The call is still accepted and billed, and its cost counts as zero in margin until a price exists. Nozle records three cases:

| Source | When |
|---|---|
| `cost_event` | A Cost Event is uncosted with `no_matching_cost_rule`. The bucket is its `type`. |
| `feature_event` | A Feature Event is uncosted with `no_matching_cost_rule`. The bucket is empty. |
| `legacy_cost_model` | A per-model cost model has no rate for the model. The bucket is empty. |

Calls are counted per key, not stored one by one. A later priced call of the same key resolves it. Each organization keeps at most 500 open keys; more keys count in one `other` row.

**Setting.** `uncosted_model_action` is set per organization in GraphQL as `billingConfiguration.uncostedModelAction`:

| Value | Effect |
|---|---|
| `warn` (default) | Record, show in the dashboard, and notify. |
| `ignore` | Record and show in the dashboard. No notification. |
| `deny` | Refuse a call to a model that no cost rule of yours prices: `GET /can` with `model` answers `uncosted_model_denied`, and the [LLM proxy](/api/llm-proxy) answers `403 uncosted_model_denied` before the provider is called. See [refuse calls to unpriced models](#refuse-calls-to-unpriced-models). |

**Notification.** With `warn`, admins and members with `cost_intelligence:manage` get an in-app and an email notification, once per model per UTC day. At most 20 per organization per day are sent; the rest fold into one digest. No webhook is sent.

**API.** `GET /api/v1/cost-intelligence/uncosted-models` lists keys (`status` `open`, `resolved`, `dismissed` or `all`; `limit`; `cursor`) and needs `analytic:read`. `POST /api/v1/cost-intelligence/uncosted-models/dismiss` with `{provider, model, token_type, source}` dismisses one and needs `analytic:write`. Each row has `shared_price_available`, kept for compatibility and always `false`: Nozle does not price models for you. The [cost report](/api/cost-intelligence-report) has a new field `uncosted_models` with the top 50 open keys.

**Dashboard.** The list is under **Usage → Margin**, tab **Uncosted**.

To fix a key, add a price for the model in your [cost model](/guides/margin/cost-models). Then [reprocess](/guides/margin/reprocess) the events recorded before the price existed. Dismiss a key you do not want to price.

### Refuse calls to unpriced models

Set `uncosted_model_action` to `deny` to stop calls to a model that none of your cost rules prices.

- **`GET /can`.** Send the optional `model` and `provider` query parameters. A refused call answers `allowed: false`, `reason: "uncosted_model_denied"`, with `model` and `message`. Without `model` nothing is checked. See [Check an entitlement](/api/check-entitlement).
- **LLM proxy.** The model is read from the request body. A refused call answers `403` with code `uncosted_model_denied` and the provider is not called. See [LLM proxy errors](/api/llm-proxy#errors).
- **When the price cannot be looked up.** `/can` follows the `on_unavailable` of the margin policy that applies (the last one known for the call), and allows the call when none is known. The proxy allows the call and marks the response `X-Nozle-Budget-Unverified: true`. See [when the policy cannot be read](/guides/margin/alerts#when-the-policy-cannot-be-read).

## Checklist

| Goal | You need |
|---|---|
| Tokens appear as usage | A metered Feature whose event code equals the capture code; one active subscription per customer, or `X-Nozle-Subscription` on proxy calls |
| Tokens are billed | A usage charge for that Feature on the plan |
| Token cost and margin | An AI tokens cost model per provider and model, linked to the Feature with **Detailed events only**; `costMeterCode: "ai_tokens"` in capture |
| Cost estimate in `can()` | Feature Event cost components, composition **Add both**, a standard charge |
| Credits deducted per call | A consumable Feature with a credit rate, and `usage.track()` |
