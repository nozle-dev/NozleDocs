title: Sandbox
description: See whether your workspace has a sandbox, create it, and reset it.
---

Every workspace has one live organization and can have one [sandbox](/guides/getting-started/sandbox): a separate, linked organization for test data. It has its own customers, invoices, events, API keys and payment connections, and nothing in it reaches live.

Open **Settings** and choose **Sandbox** under **Organization**. The page opens from Live; earlier dashboard links to **Environments** land here.

## What the page shows

| Section | What it says |
| --- | --- |
| Status | **Active** once the sandbox exists, **Not created** before. An admin can create it here, or by switching to **Sandbox** in the workspace switcher. |
| Reset | Retires the sandbox and creates a fresh, empty one with new API keys. See [Reset the sandbox](/guides/getting-started/sandbox#reset-the-sandbox). |
| Copied from Live | The billing settings and policies copied once, when the sandbox is created. |
| What the sandbox has of its own | Customers, plans, invoices, events, API keys, webhook endpoints, payment connections and integrations. |
| What it shares with Live | Members, roles and sign-in methods, which you manage in Live, and your Nozle plan. The sandbox is free. |

## Who can change it

Every member can open the sandbox once it exists, with the same role they have in Live. Creating and resetting it needs the `developers:keys:manage` permission, which workspace admins have. Without it, the page shows **Ask an admin to create the sandbox**.
