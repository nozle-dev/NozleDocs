The `can()` endpoint is the core of Nozle's entitlement system.

## Request

```
GET /api/v1/can?customer_id=cust_123&feature=api_calls
Authorization: Bearer sk_nozle_...
```

Call this endpoint from a trusted backend with a restricted secret key. Derive `cust_123` from the authenticated application user; publishable keys are rejected.

## Response

```json
{
  "allowed": true,
  "used": 1500,
  "limit": 10000,
  "remaining": 8500,
  "economics": {
    "status": "estimated",
    "reporting_currency": "USD",
    "estimated_cost": "0.05",
    "estimated_revenue": "0.10",
    "estimated_margin": "0.05",
    "estimated_margin_percent": "50",
    "cost_rule_version_ids": ["4d946b17-aafe-4c6d-9863-4b69049fe6ef"],
    "exclusions": ["future_detailed_cost_events"],
    "policy_version_id": "b0251ae2-86cd-48f5-a34a-4c423f6d7821",
    "policy_decision": "allow",
    "policy_reason": "within_policy",
    "calculated_at": "2026-09-02T12:00:00Z"
  }

```

## Field reference

| Field | Type | Description |
|-------|------|-------------|
| `allowed` | `boolean` | Whether the customer can use this feature |
| `reason` | `string?` | Why access was denied (if `!allowed`) |
| `used` | `number` | Current usage count this billing period |
| `limit` | `number` | Usage cap for this feature |
| `remaining` | `number` | `limit - used` |
| `economics.status` | `string` | `estimated`, `not_configured`, `unavailable`, or `stale` |
| `economics.reporting_currency` | `string?` | The organization's reporting currency |
| `economics.estimated_cost` | `string?` | Exact decimal incremental cost for the proposed Feature Event |
| `economics.estimated_revenue` | `string?` | Exact decimal directly attributable usage revenue |
| `economics.estimated_margin` | `string?` | Estimated revenue minus estimated cost |
| `economics.estimated_margin_percent` | `string?` | Margin percentage when estimated revenue is greater than zero |
| `economics.cost_rule_version_ids` | `string[]?` | Immutable Cost Rule versions used by the estimate |
| `economics.exclusions` | `string[]?` | Costs unavailable before execution, such as future Detailed Cost Events |
| `economics.policy_version_id` | `string?` | Historical margin-policy version used for the decision |
| `economics.policy_decision` | `string?` | `allow`, `warn`, or `deny` |
| `economics.policy_reason` | `string?` | The threshold or unavailable-data rule that produced the policy decision |
| `economics.calculated_at` | `string` | Time at which the estimate was calculated |

## Runtime behavior

The service may cache entitlement and usage state. Always treat the returned decision as point-in-time and enforce it immediately before protected work.

The optional `economics` object is also point-in-time, but it is not a financial ledger entry. Calling `/can` never consumes usage, changes a pricing period, or records cost. If a Feature uses `detailed_events_only`, the estimate is `unavailable` because the actual Cost Events do not exist yet. If it uses `add_both`, the known Feature Event Cost is returned and `future_detailed_cost_events` appears in `exclusions`.

## Denial reasons

- No active subscription
- Feature not included in plan
- Usage limit exceeded
- Subscription expired/cancelled

## SDK wrappers

**Node:**

```ts
nozle.can('cust_123', 'api_calls')
```

**Python:**

```python
nozle.can('cust_123', 'api_calls')
```

**React:** fetch the result through your authenticated backend and pass it to `FeatureGate`, `UsageGate`, or your own UI.
