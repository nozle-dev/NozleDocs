---
title: "API URLs"
description: "Choose the correct service prefix and configure SDK overrides."
---

Nozle's public services share `api.nozle.app`. Each service keeps its own authentication
and API paths behind a service prefix.

| Service | Base URL | Examples |
| --- | --- | --- |
| Core billing | `https://api.nozle.app/core` | `/graphql`, `/api/v1/customers`, `/api/v1/subscriptions` |
| Engine | `https://api.nozle.app/engine` | `/api/v1/events`, `/api/v1/events/batch`, `/api/v1/can`, `/api/v1/checkout` |
| Onboarding AI | `https://api.nozle.app/ai` | `/v1/conversations` |

Append an operation's path once. For example, an Engine catalog request is
`https://api.nozle.app/engine/api/v1/plans`.

Node 0.11.0, Python 0.11.0, and Go v0.10.0 server SDKs default to Engine for
event ingestion and extension calls, and Core for billing resources and subscription
discovery. Set one `host` (Node `host`, Python `host`, Go `WithHost`) and the SDK adds `/engine` and `/core` itself. `baseUrl` and `eventsUrl` (Python `base_url` and `events_url`, Go `WithBaseURL` and `WithEventsURL`) still set one service on its own and win over `host`. Configure the Engine base URL for custom event ingestion. React defaults
public catalog requests to Engine.

```ts
const nozle = new Nozle({
  apiKey: process.env.NOZLE_SECRET_KEY!,
  host: 'http://localhost:8888',
})
```

Go uses the same local reverse proxy paths:

```go
client := nozle.New(os.Getenv("NOZLE_SECRET_KEY"),
  nozle.WithHost("http://localhost:8888"),
)
```

For self-hosted reverse proxies, both overrides can also include path prefixes.
Keep server credentials on the server. React uses a publishable catalog key and
your authenticated merchant backend for checkout. Core dashboard sessions and scoped
AI tokens are separate credentials, even though their services share a hostname.

Core payment callbacks use
`https://api.nozle.app/core/webhooks/stripe/{organization_id}?code={stripe_provider_code}` for Stripe and
`https://api.nozle.app/core/webhooks/razorpay/{payment_provider_id}` for Razorpay.
An existing provider registration must be updated separately from application URL settings.

The two socket transports serve different purposes:

- Core subscriptions: `wss://api.nozle.app/core/cable`.
- Centrifugo browser transport: `wss://api.nozle.app/ws/connection/websocket`.

Keep their existing authentication and reconnect behavior. The public Centrifugo route
does not expose its administrative or server API. `lite.nozle.app` remains the model gateway.
